# Как обновлять гайды

Этот документ — обязательная карта зависимостей для изменений в Habr, Career,
Courses и Landings. Он не заменяет пакетные `AGENTS.md`: сначала определите
тип изменения здесь, затем выполните проверки конкретного пакета.

## Источники истины

| Слой | Редактируется | Производные файлы |
|---|---|---|
| Токены | `machine/*tokens*.json` либо пакетный генератор, указанный в `package.json` | CSS токенов и отчёты исключений |
| Компонент/блок | адресная Markdown/machine-спецификация и runtime CSS/JS | viewer-каталог, поиск, visual/maturity-контракты |
| Страница | pattern/page-спецификация и standalone-пример | machine-запись, viewer-страница, браузерные проверки |
| Ассет | исходный локальный файл и manifest/asset-index пакета | превью и проверки существования |
| Маршрутизация | корневые `README.md`, `AGENTS.md` и пакетный `AGENTS.md` | проверка входных ссылок |
| Версия | `VERSIONING.md` и каноническое поле machine index | README, package version, CHANGELOG и тег |

Если пакет генерирует machine-файл или отчёт, не исправляйте производный файл
вручную. Используйте команду `build:*` из его `package.json`, затем проверяйте
дифф: генератор не должен затронуть соседние сущности без причины.

## Матрица изменений

| Изменилось | Обязательно проверить или обновить |
|---|---|
| Цвет, размер, шрифт, радиус, тень | machine-токен → CSS-токен → все состояния компонента → обе темы, если они есть → отчёт исключений |
| Компонент | спецификация → runtime CSS/JS → один канонический пример → machine-запись → каталог/search → accessibility → visual contract |
| Состояние/вариант | список состояний → пример с реальным состоянием → state coverage → интерактивное управление в viewer → проверка |
| Организм или блок | дочерние компоненты вместо копий разметки → адаптивность → ограничения ширины → пример → machine-зависимости |
| Страница | общая оболочка/header/footer → layout-компоненты → повторяемые блоки → 320/480/768/1024/Auto → pattern-запись |
| Ассет | локальный файл → понятное имя → manifest/index → все ссылки → декодирование в браузерной проверке |
| Навигация или путь | сохранить старый путь/алиас → обновить README/AGENTS/catalog/search → проверить внутренние ссылки |
| Правило композиции | human-документ → machine-контракт → минимум один правильный и один запрещённый случай в проверке |
| Граница покрытия | README/AGENTS → maturity/unknowns → roadmap; не повышать уверенность без нового evidence |

## Повторяющаяся разметка

Перед добавлением HTML найдите существующую сущность в machine-каталоге.
Повторяющийся визуальный объект должен иметь один CSS-корень и каноническую
разметку. Страница ссылается на этот компонент; локальная копия допустима
только как явно описанная композиционная обёртка. Если внешний вид неизвестен,
сначала используйте authority выбранного пакета: production → Storybook →
Figma → документированное допущение. Не восстанавливайте DOM по одному CSS.

## Быстрый цикл изменения

1. Проверьте `git status --short` и отделите чужие незавершённые изменения.
2. Прочитайте корневой и пакетный `AGENTS.md`.
3. Измените источник истины, runtime и один канонический пример.
4. Пересоберите только относящиеся к изменению производные файлы.
5. Запустите пакетный `npm run validate`.
6. Для визуального изменения запустите viewer-проверку и осмотрите контрольные ширины.
7. Запустите `node tools/validate-guides.mjs` из корня.
8. Обновите roadmap: выполненное убрать из активной очереди, оставшийся риск сформулировать проверяемо.

## Повышение версии

1. Выберите SemVer по [`VERSIONING.md`](VERSIONING.md); версия гайда независима от версии сервиса.
2. Обновите каноническое поле версии в machine index пакета.
3. Синхронизируйте пакетный `package.json`, `README.md`, `AGENTS.md`, корневые `README.md` и `VERSIONING.md`.
4. Перенесите `Unreleased` в датированный раздел `CHANGELOG.md`; опишите совместимость и migration notes.
5. Для переименованных публичных путей добавьте алиас минимум на один релизный цикл.
6. Прогоните пакетные проверки, корневую проверку маршрутов и визуальные тесты.
7. После ревью создайте отдельный release-коммит и аннотированный тег `<package>-vX.Y.Z`.

## Перед коммитом

- Нет несвязанных файлов в staged diff.
- Нет литералов размеров/цветов вместо токенов без записанного исключения.
- Повторяющиеся элементы используют компонент, а не копию.
- Ссылки и ассеты существуют; примеры открываются без горизонтального overflow.
- Статусы `complete/partial/figma-only/research` соответствуют evidence.
- Локальные review-материалы из `.review-quiz/` не отслеживаются Gitом.
