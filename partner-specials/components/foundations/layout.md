## Когда использовать

Используйте Layout для горизонтальных полей секции и сетки спецпроекта. Он задаёт расположение, а цвет, шрифт и изображения приходят из клиентской темы. Назначайте содержимому подходящие HTML-элементы отдельно: контейнер не подменяет section, main или article.

## Как работает

По умолчанию контейнер выбирает число колонок и поля по ширине окна. `ps-layout__grid` растягивает одинаковые колонки внутри контейнера. `ps-layout__full` занимает всю строку. Длинное неразрывное содержимое получает возможность переноса; фиксированная ширина изображений и вложенных виджетов остаётся ответственностью их компонентов.

Это новый браузерный API. `data-ps-layout-source="drawn"` выбирает альтернативные поля нарисованного примера. Отсутствие атрибута или значение `native` использует native layoutGrid. `data-ps-layout="1440"` явно закрепляет профиль конкретного артборда независимо от окна; допустимы семь ширин таблицы. Атрибут не устанавливает ширину контейнера и не предназначен для автоматической адаптации небольших вложенных блоков.

## Размер и расположение

Значения сняты в [layout-details.json](../../evidence/source/figma/layout-details.json) и [layout-drawn-sample.json](../../evidence/source/figma/layout-drawn-sample.json).

| Ширина артборда | Колонки | Промежуток | Поля native | Поля drawn |
|---|---:|---:|---:|---:|
| 1920 | 12 | 8 px | 56 px | 100 px |
| 1440 | 12 | 8 px | 56 px | 100 px |
| 1280 | 12 | 8 px | 56 px | 56 px |
| 1024 | 8 | 8 px | 48 px | 48 px |
| 768 | 8 | 8 px | 40 px | 36 px |
| 390 | 4 | 4 px | 20 px | 20 px |
| 320 | 4 | 4 px | 20 px | 20 px |

Ширина колонки вычисляется как `(ширина контейнера − 2 × поле − (колонки − 1) × промежуток) / колонки`. На 390 это 84,5 px; нарисованные прямоугольники источника чередуют 84 и 85 px. CSS использует равные доли и субпиксельное округление браузера. Высота иллюстраций не задаёт высоту страницы.

## Внешний вид

Layout не рисует фон, рамку или подсветку колонок. Синие, красные и зелёные области Figma объясняют сетку; цветные полосы витрины также служат пояснением. Смена темы не изменяет геометрические токены.

## Токены

Имена `--ps-layout-*` — новый контракт пакета. Значения native подтверждены настройками фреймов и цепочками aliases в [layout-variables.json](../../evidence/source/figma/layout-variables.json); имена CSS не выдаются за имена Figma variables.

| Суффикс после `--ps-layout-` | Значение | Роль |
|---|---|---|
| `margin-mobile` | 20px | Поля 320/390 |
| `margin-tablet` | 40px | Поля native 768 |
| `margin-compact` | 48px | Поля 1024 |
| `margin-desktop` | 56px | Поля native 1280/1440/1920 |
| `margin-drawn-wide` | 100px | Альтернативные поля 1440/1920 |
| `margin-drawn-tablet` | 36px | Альтернативные поля 768 |
| `columns-mobile` / `columns-tablet` / `columns-desktop` | 4 / 8 / 12 | Число колонок |
| `gap-mobile` / `gap-desktop` | 4px / 8px | Промежутки |
| `margin` / `columns` / `gap` | Вычисляются профилем | Текущие значения контейнера |

Базовые переменные живут в [layout-tokens.css](../../ui/layout-tokens.css). Не меняйте их ради перекрашивания под клиента: меняйте палитру темы. Геометрию меняйте только как отдельное проектное отклонение. Живой каталог показывает все 14 значений, включая 3 вычисляемые роли.

## Responsive

Новый runtime использует следующие интервалы ширины окна: до 768 — mobile; от 768 — tablet; от 1024 — compact; от 1280 — desktop; от 1440 — wide (отличается только drawn). Колонки растягиваются непрерывно внутри каждого интервала. Верхнего ограничения ширины нет. Явный профиль через `data-ps-layout` отключает эту адаптацию для контейнера.

Пороговые значения выбраны по нижней опорной ширине каждой группы. Это решение реализации, а не извлечённые медиазапросы или доказанная модель поведения между артбордами.

## Доступность

У Layout нет интерактивных состояний, фокуса или добавленных ARIA-ролей. DOM-порядок содержимого сохраняется. Поясняющие пустые колонки витрины скрыты от вспомогательных технологий.

## Разметка

Скопируйте `ui/` целиком. Подключите один CSS; витрина не требуется.

```html
<link rel="stylesheet" href="./ui/partner-specials.css">
<div class="ps-layout">
  <div class="ps-layout__grid">
    <div class="ps-layout__full">Содержимое секции</div>
  </div>
</div>
```

Альтернативный рисунок выбирается явно: `<div class="ps-layout" data-ps-layout-source="drawn">`. Для воспроизведения 1440-профиля добавьте `data-ps-layout="1440"`; фактическую ширину задаёт родитель.

## Ограничения

- GAP-L1: native layoutGrid расходится с видимыми прямоугольниками на 1920, 1440 и 768. Default native выбран потому, что это числовая сетка фрейма с variable bindings. Это обоснованный контракт реализации, но не подтверждение авторского замысла. Drawn сохраняется отдельно; разрешить конфликт может автор макета.
- GAP-L2: production DOM/CSS, реальные пороги и ширина максимального контейнера не сняты. Весь browser runtime новый.
- GAP-L3: показаны семь опорных ширин, а не семь производственных брейкпоинтов. Между ними поведение задаёт описанная реализация.
- GAP-L4: drawn-профиль воспроизводит поля, число колонок и промежутки, но не намеренное чередование целочисленной ширины колонок 390. CSS округляет равные доли самостоятельно.
- Состав секций, высоты, span-раскладка контентных блоков и утверждённая тема клиента этим примитивом не определяются. Полная библиотека остаётся в разработке.
