## 1. Типы правил

Каждый существенный вывод во всех девяти документах имеет статус. Статус важнее формулировки.

| Статус | Что означает | Как применять |
|---|---|---|
| **OBSERVED** | Факт, замеренный на production-страницах | Не инструкция. Свидетельство, а не требование |
| **INVARIANT** | С высокой вероятностью часть идентичности продукта; нарушение делает интерфейс чужим | Сохранять при создании нового интерфейса этого продукта |
| **DEFAULT** | Рекомендуемое решение, если нет причины поступить иначе | Брать по умолчанию, отклоняться осознанно |
| **FREEDOM** | Область свободного выбора | Существующие значения — не ограничение |
| **AVOID** | Обычно даёт результат, плохо соответствующий направлению | Не запрет |
| **NEVER** | Абсолютный запрет | Редко и только при явном обосновании |

### Главная проблема, которую v0.2 исправляет

В v0.1 наблюдение слишком быстро превращалось в закон:

```text
v0.1:  «В исследованных проектах нет мягких теней»  →  «Хабр никогда не использует мягкие тени»
v0.2:  OBSERVED — на 11 проектах мягких теней не встретилось.
       Это вывод из отсутствия. Возможно, приём просто не понадобился,
       или он есть в макетах, которых мы не видели.  →  AVOID, не NEVER.
```

```text
v0.1:  «Большинство спецпроектов использует Inter»  →  «Новый спецпроект обязан использовать Inter»
v0.2:  OBSERVED — Inter присутствует во всех 11 проектах.
       Все 11 собраны в Webflow, где Inter — дефолтный шрифт.
       Совпадение может быть производственным, а не брендовым.  →  TO VALIDATE WITH FIGMA.
```

### Design DNA и Implementation conventions

Во всех документах разделены два уровня:

* **Design DNA** — типографический характер, плотность, композиция, whitespace, поведение цвета, геометрия, характер карточек, иерархия, art direction. Может стать инвариантом.
* **Implementation conventions** — фреймворк, стратегия rem, набор медиазапросов, именование классов, структура CSS. **Не бренд**, а следствие технологии. Вынесено в §18 каждого документа.

Пример: брейкпоинты `479 / 767 / 991 / 1280 / 1440 / 1920` в лендингах и спецпроектах — это **дефолт Webflow**, а не респонсив-стратегия Хабра.

## 3. Метод исследования

Исследование проводилось **не по скриншотам**, а инструментально.

**Инструментарий:**

* Headless Chrome (152.x) через Chrome DevTools Protocol: `Target.createTarget` → `Page.navigate` → `Runtime.evaluate`.
* Принудительно задавалась светлая тема через `Emulation.setEmulatedMedia` с `prefers-color-scheme: light`. Это важно: при дефолтных настройках headless Chrome страницы Хабра отдавали **тёмную** тему, и первые замеры (header `#0d0d0d`, фон `#171717`) были ошибочными.
* Замеры через `getComputedStyle()` на реальном отрендеренном DOM, а не по исходному CSS.
* Продуктовые страницы — **пять** viewport: 1440 / 1280 / 1024 / 768 / 375. Лендинги и спецпроекты — три: 1440 / 768 / 375.
* Дополнительно: `@media`-условия из `document.styleSheets`, CSS custom properties с `:root`, гистограммы `border-radius` / `box-shadow` / `padding` / `gap` / `font-size` / `color` / `background-color` по всем видимым элементам, структурное дерево DOM с размерами боксов, спецификации кнопок / инпутов / карточек / иконок.
* Технологический фингерпринтинг: HTTP-заголовки, cookie, содержимое JS-бандлов, разметка.
* Файлы темы Хабра скачаны и распарсены напрямую.

**Ограничения (зафиксированы явно):**

* `qna.habr.com/my/feed` и все формы Q&A кроме поиска требуют авторизации — не исследованы.
* Часть CSS лежит на `assets.habr.com` кросс-доменно, поэтому `cssRules` недоступны из страницы. Для Career это означает, что **брейкпоинты выведены по поведению боксов, а не прочитаны**.
* `habr.com/ru/feed/` в гостевом режиме — лента «Все потоки», не персональная.
* Рекламные вставки третьих сторон (AdFox, Jivosite) из выводов исключены.
* Ни одна страница не исследована в динамике: hover, focus, состояния загрузки и ошибок, открытые модалки и дропдауны замерены только косвенно.

### 5.3. Ключевое наблюдение о зрелости

**Зрелость токен-слоя ложится ровно на карту поколений интерфейса.** Два продукта без нормальных токенов — Career и Q&A — это ровно те два, где палитру пришлось восстанавливать замерами. И это же объясняет, почему **тёмная тема есть только у habr.com**: у остальных нет слоя, через который её можно переключить.

Следствие для планирования: **Career — продукт с наибольшим риском расхождения production ↔ Figma**, потому что между дизайном и кодом там нет сверяемого слоя.

## 8. Сравнения

### 8.1. Habr vs Q&A

**Общее:** тёмная верхняя полоса, серый фон страницы, белые контентные поверхности, отсутствие теней, малые радиусы, высокая плотность, метаданные серым 13px.

**Различия:**

* Habr — **центрированный фиксированный** container 1096. Q&A — **fluid** с левым фикс-навбаром: layout, характерный для 2013–2015 годов.
* Habr — контент в белых плитках с зазором 12px. Q&A — единый белый лист, элементы разделены вертикальным ритмом 28px и тонкими разделителями.
* Habr использует Fira Sans на заголовках. Q&A — единый `toster-text` с weight 700.
* Q&A — единственный продукт с зелёной primary-кнопкой и радиусом 5px.

**Q&A — самое старое поколение.** Для развития существующего Q&A нужно воспроизводить именно этот язык. Но как основа нового сервиса он не годится — см. §11.

### 8.2. Career vs Courses

Живут на одном домене, **но это разные дизайн-системы на разных стеках**.

| | Career | Courses |
|---|---|---|
| Стек | Rails + Webpacker + Vue-острова | Nuxt + Vue SFC + Tailwind |
| Токены | нет (0 переменных) | 52 переменные |
| Container | 1100 / padding 12 | 1124 / padding 24 |
| Header | 48 (TM) + 64 (белый), **static** | 64, **синий `#346ef4`**, sticky |
| Текст | `#1b272c` (hue 198°, S 24%) | `#2c2e34` (hue 225°, S 8%) |
| Вторичный | `#55798b` холодный сине-серый | `#909194` нейтральный серый |
| Акцент | `#8164f7` фиолетовый | `#ff7e47` оранжевый |
| Ссылка | `#0464d2` | `#346ef4` |
| Primary btn | фиолетовая, r12 | **чёрная `#2c2e34`**, r12 |
| Чипы | r8, заливка `rgba(166,189,201,.2)` | **r9999 pill**, заливка `#f1f1f1` |
| Тени | нет | `0 4px 6px -1px rgba(0,0,0,.05)` |
| Sidebar | есть (300) | нет |
| Межсекционный интервал | 24 | 48 |
| Footer | белый | `#f1f1f1`, grid 4×257 |

**Наследуется от Career в Courses только TM-панель.** Правила Career на Courses не распространять. **INVARIANT.**

### 8.3. Продуктовый UI vs маркетинговый лендинг

| | Продукт | Лендинг |
|---|---|---|
| H1 | 20–32px | 46–122px |
| Letter-spacing H1 | `normal` | −0.5 … −6px |
| Высота кнопки | 30–40px | 52–88px |
| Радиус кнопки | 3–12px | 20–100px, часто pill |
| Между блоками / секциями | 12–24px | 100–200px |
| Фон | светлый нейтральный | часто тёмный насыщенный |
| Иллюстрации | почти нет | основа композиции |

**Но:** лендинг сохраняет продуктовый container (`1100` на `career.habr.com/info/*` и `track.habr.com`) и продуктовую шапку. Это и есть мост между регистрами.

### 8.4. Имиджевые спецпроекты vs партнёрские

| | Имиджевые (Хабр) | Партнёрские |
|---|---|---|
| Домен | `*.habr.com`, `*.webflow.io` | `*.habr.io` |
| Технология | Webflow | Vite + PHP Laminas |
| Шрифт | **Inter** (+ иногда дисплейный) | **шрифт партнёра** (17 из 18) |
| Палитра | своя авторская | брендбук партнёра |
| Токены | `--_size---*`, `--_font---*` (Webflow) | `--primary`, `--bg`, `--sidegap`, `--easing` |
| Масштабирование | брейкпоинты Webflow | **fluid-rem**, два макета |
| Логотип Хабра | сам по себе или «Хабр + название» | в паре «Партнёр × Хабр» |
| Чья визуальная идентичность | Хабра | **партнёра** |

Это **два разных производственных конвейера** с разными правилами.

## 10. Preliminary Habr Design DNA — TO VALIDATE WITH FIGMA

> **Здесь только гипотезы.** Общий визуальный язык дизайн-команды по production-сайтам определить нельзя: мы видим результат, но не видим намерения, отвергнутых вариантов и правил. Ниже — то, что стоит проверить в первую очередь, когда появятся Figma-материалы.

### H1 — Сдержанность акцента

```text
Hypothesis:
  Хабр систематически ограничивает акцентный цвет текстом, иконкой, тонкой обводкой
  и одной кнопкой; крупные площади остаются нейтральными.

Evidence:
  Habr:    #548eab — 290 текстовых и 98 border-вхождений против 17 фоновых
  Career:  #8164f7 — 82 фоновых вхождения на 11 страниц = ровно кнопки
  Courses: #ff7e47 — 125 фоновых вхождений = ровно pill-бейджи высотой 20px
  Q&A:     #65c178 — 10 фоновых вхождений на 6 страниц = ровно кнопки
  Выдержано в четырёх независимых системах на разных стеках.

Confidence: ВЫСОКАЯ — самая устойчивая закономерность экосистемы.
  Единственная альтернативная гипотеза: это общая практика продуктового дизайна,
  а не специфика Хабра.

What to inspect in Figma:
  — Есть ли явное правило об использовании акцента в дизайн-системе?
  — Существуют ли макеты с крупными акцентными площадями (герои, промо-блоки,
    баннеры), которые не попали в production?
  — Как акцент ведёт себя в обложках и баннерах, где ограничений продукта нет?
```

### H2 — Подтонированная нейтраль вместо чистого белого и чёрного

```text
Hypothesis:
  В маркетинговых материалах текст никогда не бывает чисто белым или чисто чёрным —
  он подтонирован в сторону палитры проекта.

Evidence:
  company.habr.com:  #ecf5e7 (630 вхождений) против #ffffff (22)
  technotext:        #e2e4cd / #ecedde
  habr-museum:       #fcfff5
  startup-crunch:    #ebffe0
  karernyy-fest:     #fcfcc5
  sanatoriy:         #f2f0eb / #302e38
  vibe:              #43494b
  vibe-chek-1:       #ecf9ec
  9 из 11 имиджевых проектов + вся B2B-площадка.
  Исключение: medicinskaya-konferenciya — чистый белый на чистом чёрном.

Confidence: СРЕДНЯЯ-ВЫСОКАЯ — приём воспроизводится независимо от палитры,
  что говорит скорее о навыке команды, чем о случайности.

What to inspect in Figma:
  — Зафиксирован ли этот приём где-либо в виде рекомендации?
  — Как ведёт себя текст в обложках, баннерах, промографике?
  — Есть ли материалы, где используется чистый #ffffff, и чем они отличаются?
```

### H3 — Вторичность через альфу, а не через отдельный цвет

```text
Hypothesis:
  Второй уровень текста задаётся прозрачностью основного, а не отдельным hex.

Evidence:
  company.habr.com:  rgba(219,233,240,.62)
  karernyy-fest:     rgba(252,252,197,.7)
  medconf:           rgba(255,255,255,.8) и rgba(255,255,255,.6)
  sanatoriy:         rgba(48,46,56,.6)
  vibe-chek-2:       rgba(71,85,89,.6)
  Устойчиво в маркетинговых материалах.
  ⚠ В продуктовых интерфейсах — наоборот: там отдельные hex
    (Habr #8f8f8f / #6f7476; Career #55798b / #7996a5).

Confidence: СРЕДНЯЯ — приём чёткий, но разделение «маркетинг — альфа,
  продукт — hex» может быть следствием технологии (Webflow удобнее для альфы),
  а не решением.

What to inspect in Figma:
  — Как заданы вторичные уровни текста в переменных?
  — Есть ли opacity-токены?
  — Совпадает ли подход в продуктовых и маркетинговых файлах?
```

### H4 — Inter как шрифт по умолчанию для маркетинга

```text
Hypothesis:
  Inter — осознанный выбор дизайн-команды для маркетинговых материалов,
  а не платформенный дефолт.

Evidence:
  ЗА:     присутствует во всех 11 имиджевых проектах и на всей B2B-площадке,
          в том числе там, где заголовки набраны Unbounded.
  ПРОТИВ: все эти проекты собраны в Webflow, где Inter — один из дефолтных шрифтов.
  ПРОТИВ: ни один из 18 партнёрских проектов на habr.io Inter не использует —
          там шрифт партнёра (17/18).
  ПРОТИВ: продуктовые интерфейсы используют Inter только в Career и Courses;
          Habr использует Fira Sans + системный стек, Q&A — toster-text.

Confidence: НИЗКАЯ — доказательства против сильнее доказательств за.
  Это главный кандидат на переклассификацию после Figma.

What to inspect in Figma:
  — Какой шрифт указан в дизайн-системе как основной?
  — Есть ли Figma-файлы спецпроектов, и какие шрифты в них?
  — Существует ли фирменный шрифт Хабра, не попавший в production?
  — Почему Habr использует Fira Sans, а Career и Courses — Inter?
    Это переход, сосуществование или разные решения разных команд?
```

### H5 — Сжатая крупная типографика в промо

```text
Hypothesis:
  Дизайн-команда предпочитает заголовки с line-height ≤ font-size
  и отрицательным трекингом на крупных кеглях.

Evidence:
  company.habr.com:  88/88 ls −2px; 72/72 ls −2px  (задано токенами)
  habr-museum:       93.6/93.6 ls −3px
  technotext:        122.4/110.16 ls −6px
  sanatoriy:         144/100
  karernyy-fest:     60/57 ls −2px
  career-employee2:  100/90
  vibe-chek-2:       88/88
  track.habr.com:    104/104 ls −4px
  ibs-race:          120/108 ls −2.4px
  Устойчиво во всех маркетинговых направлениях, включая партнёрские
  (где шрифт партнёрский — то есть приём переживает смену гарнитуры).

Confidence: ВЫСОКАЯ для маркетинга — это одно из немногих свойств,

What to inspect in Figma:
  — Есть ли типографическая шкала для промо-материалов?
  — Как набираются обложки и баннеры — тем же приёмом?
  — Есть ли правило о трекинге на крупных кеглях?
```

### H6 — Отказ от мягкой тени как приёма

```text
Hypothesis:
  Дизайн-команда сознательно не использует мягкую рассеянную тень;
  глубина строится фоном, границей, жёстким смещением или inset-подсветкой.

Evidence:
  Продукты:   Habr 1 тень (focus-ring), Q&A 0, Career 0–1, Courses только rgba(0,0,0,.05)
  Имиджевые:  0 мягких теней на 11 проектов; встречаются 10px 10px 0 0 (Музей),
              4px 4px 0 0 (Startup Crunch), inset-подсветки (Медконференция)
  Партнёрские: 0 мягких теней на 18 проектов
  Исключение: продуктовые лендинги — rgba(51,51,51,.12) 0 8px 16px (55 вхождений)

Confidence: СРЕДНЯЯ. Наблюдение сильное по объёму, но это ВЫВОД ИЗ ОТСУТСТВИЯ.
  Плюс найденное исключение показывает, что мягкая тень допустима
  как минимум в одном регистре.

What to inspect in Figma:
  — Есть ли токены/стили теней в дизайн-системе?
  — Если есть, но не используются — это осознанный отказ.
  — Если нет — возможно, вопрос просто не поднимался.
  — Почему тень появляется именно в продуктовых лендингах?
```

### H7 — Плотность как позиция

```text
Hypothesis:
  Высокая информационная плотность — осознанная позиция Хабра,
  соответствующая аудитории, а не следствие возраста интерфейсов.

Evidence:
  ЗА:     плотность высокая и в старом Q&A, и в новых Курсах
          (самый частый размер текста в Курсах — 12/16, 254 вхождения)
  ЗА:     контролы 30–40px против рыночных 44–48px во всех четырёх продуктах
  ПРОТИВ: самый новый продукт (Courses) при этом увеличил межсекционный
          интервал вдвое относительно Career (48 против 24) —
          возможен дрейф в сторону большего воздуха

Confidence: СРЕДНЯЯ.

What to inspect in Figma:
  — Есть ли в дизайн-системе явные density-правила?
  — Отличается ли плотность в новых макетах от production?
  — Есть ли сетка/спейсинг-шкала, зафиксированная как система?
```

### Что по production определить нельзя вообще

Эти области требуют Figma и не имеют даже гипотез:

* **Art direction спецпроектов** — принципы выбора визуального направления.
* **Иллюстративный язык** — в выборке стили несопоставимы: ретро-коллаж, пиксель-арт, фотоколлаж, плоский вектор, 3D-рендер. Есть ли общий язык — неизвестно.
* **Работа с фотографией** — в production почти отсутствует.
* **Брендовый юмор и тон** — названия проектов («Санаторий маркетолога», «Вайб-чек», «ИТ-качалка») намекают на выраженный регистр, но визуально он не восстанавливается.
* **Экспериментальная графика** — генеративная, 3D, коллажная.
* **Обложки, баннеры, промоматериалы** — вне production полностью.
* **Motion-язык** — статический анализ не читает Webflow Interactions и JS-анимации.
* **Иконографика** — icon set по инлайновым SVG не опознаётся.

## 11. Legacy

### 11.1. Q&A — подтверждённый legacy

Признаки совпадают на всех уровнях сразу:

| Уровень | Признак |
|---|---|
| Шрифт | `toster-text` — наследие Toster, продукта до ребрендинга |
| Стек | jQuery + jQuery UI как основной фреймворк |
| Layout | fluid с левым фикс-навбаром — схема 2013–2015 годов |
| Токены | именование по оттенку (`--mine-shaft`, `--seashell`, `--romance`, `--silver`) вместо ролей |
| Палитра | пять близких серых подряд без системы: `#a5acb3`, `#9099a3`, `#898d92`, `#b2bac2`, `#a8b1ba` |
| Отступы | шаг 5 с вкраплением 28 — не сводится ни к 4, ни к 8 |
| Тема | тёмная невозможна без переименования переменных |

**Статус: LEGACY.**

Документ `02-habr-qna.md` пригоден для **поддержки и развития существующего Q&A**. Он **не должен использоваться как визуальная основа нового сервиса Хабра**.

### 11.2. Другие возможные legacy-паттерны

Помечены как требующие проверки, но не подтверждены:

| Паттерн | Где | Почему подозрителен |
|---|---|---|
| Header **static**, не sticky | Career | Нестандартно для 2020-х; может быть как решением, так и незакрытым долгом |
| Плитка с `border-radius: 0` | Habr | Все соседние системы используют скругления; возможно, наследие старой вёрстки |

| Пять близких серых | Q&A | Классический признак накопившейся энтропии |
| jQuery в бандле Career | Career | Остаток предыдущего поколения |
| Радиус 3px | Habr | Значение может быть унаследовано, а не выбрано |

| Брейкпоинты Career | MEDIUM | Медиазапросы недоступны (кросс-домен), вывод по поведению боксов |
| Секции лендингов «100–200px» | HIGH для Webflow, MEDIUM для `habr.io` | На `habr.io` вертикаль в rem и «плывёт» вместе с шириной |
| `company.habr.com/ru/agency/` | Осознанное исключение | Другая палитра (`#46f20d`), радиусы 30/90, inset-подсветки. Один проект — не правило |

| Состояния (hover, focus, loading, error) | LOW | Замерены косвенно, по статическому рендеру. Динамика не исследована |

## 14. Ключевая находка по спецпроектам `habr.io`

13 из 18 проектов объявляют **один и тот же набор имён переменных**:

```css
--cl-white  --cl-black  --cl-gray-100  --cl-gray-200  --cl-gray-300
--bg  --bg-gray  --bg-dark  --text  --inverted
--primary  --primary-hover  --primary-active
--secondary  --secondary-hover  --secondary-active
--bg-disabled  --text-disabled  --disabled  --error  --placeholder  --border-color
--easing: cubic-bezier(0.4, 0, 0, 1)
--sidegap  --sidegap-n  --header-height  --section-py  --gridgap
```

Плюс `html { font-size: 10px }` и весь макет в rem: проект **масштабируется пропорционально**, а не переверстывается.

Замеренный `html { font-size }` по ширинам:

| Проект | @1440 | @768 | @375 |
|---|---:|---:|---:|
| фиксированные (9 проектов) | 10px | 10px | 10px |
| `ibs-race` | 10px | 5.34px | 6.38px |
| `lenta-tech-swipe` | 7.50px | 13.02px | 6.36px |
| `lavivion` | 7.51px | 21.34px | 10.42px |

**Почему это ценно.** Единственное место в экосистеме, где контракт одновременно:

* **семантический** (`--primary`, а не `--orange`) — в отличие от Q&A и имиджевых спецпроектов;
* **переиспользуемый между проектами** — в отличие от Webflow-переменных одного сайта;
* **отделяет тему от реализации** — заполнил палитру партнёра, получил рабочий проект.

Это **самый готовый кандидат на starter template** и, возможно, модель именования для остальных направлений.

**Важно:** контракт технический. Визуальная идентичность проектов принадлежит партнёрам и не является стилем Хабра.
