# CSS Career

Всё, что нужно, чтобы вёрстка выглядела как Хабр Карьера. Подключается одной строкой:

```html
<link rel="stylesheet" href="../ui/career.css">
```

Всё, кроме шрифта, лежит внутри папки: к `assets.habr.com` и к Storybook слой
не обращается. Единственная внешняя загрузка — Inter из Google Fonts.

---

## Порядок слоёв

Он повторяет каскад самого Career, и его нельзя менять произвольно.

| # | Файл | Что внутри | Происхождение |
|---|---|---|---|
| 1 | `fonts.css` | подключение переменного Inter | Google Fonts; в продукте — `assets.habr.com` |
| 2 | `tokens.css` | 121 переменная `:root` | из сборки, значения 1:1 |
| 3 | `foundations.css` | база документа, значения `--tw-*`, шкала кеглей | из сборки + три добавленных правила, помечены |
| 4 | `utilities.css` | 549 правил Tailwind | подмножество сборки: то, что есть в разметке Career |
| 5 | `components/*.css` | 64 секции настоящего CSS компонентов из 63 файлов сборки | из сборки, снят только Vue-скоуп `data-v-*` |
| 6 | `components.css` | то, чего в сборке нет | старая реализация, Figma, замеры production — каждое помечено источником |
| 7 | `state-contract.css` | недостающие interaction states и ARIA aliases | нормативный UI kit contract; не production snapshot |
| 8 | `layout.css` | оболочка страницы, колонки, перестроение | замеры production |

### `focus-modality.js` — необязательный спутник слоя

Единственный JS в `ui/`. Ставит на `<html>` атрибут `data-focus-modality`
(`keyboard` после Tab, `pointer` после нажатия указателем), а
`state-contract.css` гасит по нему внешнее кольцо фокуса у текстовых полей.

Нужен потому, что у input и textarea `:focus-visible` по спецификации
срабатывает всегда, включая фокус указателем: поле принимает клавиатурный ввод
независимо от того, как в него попали. Для кнопок, вкладок и чипов такой
проблемы нет, и на них правила гашения не распространяются.

Подключать не обязательно. Без скрипта атрибута нет, правила не срабатывают
и кольцо показывается при клике тоже — доступность при этом не теряется.

`state-contract.css` намеренно расположен после обоих component-слоёв. Он не
переписывает извлечённые файлы и позволяет явно отличить наблюдавшееся в продукте
от решений, добавленных при нормализации библиотеки компонентов.

## Что слой требует от страницы

Четыре условия. Три из них выполняются сами, если подключить `career.css` целиком;
четвёртое нужно знать заранее, потому что оно про разметку.

**1. Порядок импортов менять нельзя.** Сброс рамок из `foundations.css` и правило
`:where(.base-section){border-width:1px}` из `components/cards.css` имеют одинаковую
нулевую специфичность — какое из них победит, решает только порядок. `career.css`
расставляет их правильно; если вы подключаете файлы вручную, `foundations.css`
должен идти раньше `components/`.

**2. Ничего, кроме `career.css`, подключать не требуется.** Единственная внешняя
загрузка — Inter из Google Fonts в `fonts.css`. Если в проекте уже есть preflight
Tailwind, три добавленных правила просто продублируют его — конфликта не будет.

**3. Утилиты обязательны.** Разметка Career смешивает BEM-классы и утилиты в одном
атрибуте. Подключить `components/*.css` без `utilities.css` нельзя: половина
геометрии живёт в утилитах, включая произвольные значения вида
`grid-cols-[40px_minmax(0,1fr)_24px]`.

**4. `layout.css` требует обёртку и работает на `@container`, а не на `@media`.**
Это единственное место, где пакет намеренно отличается от продукта.

```html
<div class="career-shell">   <!-- container-type: inline-size -->
  …вся страница…
</div>
```

Без этой обёртки перестроение оболочки не сработает вообще: правила написаны как
`@container (max-width: 1023px)` и `@container (max-width: 479px)`. Сделано это
затем, чтобы `showcase/pages.html` мог показывать один и тот же паттерн на нескольких
ширинах одновременно — рамка задаёт ширину, и оболочка перестраивается внутри неё.

Значения при этом те же, что в продукте, и единицы сопоставимы: медиазапросы
браузера сравниваются с шириной **окна**, включая полосу прокрутки, и ширина
рамки означает ровно то же самое. Поэтому пресет 768 показывает мобильную
оболочку — как и окно 768 в продукте.

**Если переносите слой в приложение**, замените `@container` на `@media` с теми же
числами и снимите `container-type` с `.career-shell`. Таких мест ровно пять:
`layout.css` — три раза `max-width: 1023px` и один раз `max-width: 479px`,
`components.css` — один раз `max-width: 1023px` (мобильная перестройка карточки
вакансии). Больше ничего менять не нужно: остальные брейкпоинты пакета —
в `utilities.css` и в `components/*.css` — уже написаны обычными `@media`
и совпадают с продуктом один в один.

Обёртку `.career-shell` использует `showcase/pages.html`. В `showcase/components.html` её нет
и не нужно: витрина показывает отдельные компоненты, а не оболочку страницы.

## Что означает «из сборки»

Career собран на Nuxt + Tailwind. Его Storybook отдаёт скомпилированный CSS по одному
файлу на компонент. Эти файлы перенесены сюда как есть: значения, порядок правил
и медиазапросы не тронуты.

Единственное изменение — снят Vue-скоуп: селектор
`.base-button[data-v-5293367b]` стал `.base-button`. Иначе правила не применились бы
к разметке за пределами приложения.

В шапке каждой секции указано, из какого файла сборки она пришла и сколько байт
занимала:

```css
/* ---------------------------------------------------------------------
   base-button
   источник: _sources/career/source/css/base-button.CeGTylXy.css (10926 B)
   --------------------------------------------------------------------- */
```

## Три добавленных правила

Их ровно три, все в `foundations.css`, идут в этом порядке и каждое помечено
в коде комментарием «ПЕРВОЕ / ВТОРОЕ / ТРЕТЬЕ добавленное правило». Без них
компоненты Career ломаются, потому что опираются на базовый CSS приложения,
которого в сборке Storybook нет.

```css
*,*::before,*::after { box-sizing: inherit }
```
Career объявляет `box-sizing: border-box` на `body,html` — это правило из сборки,
оно на месте. Но потомкам оно не наследуется само, а вся геометрия Career посчитана
в `border-box`: без распространения `min-height: 40px` + `padding: 8px 12px`
у кнопки дают 56 пикселей вместо 40.

```css
*,*::before,*::after { border-width: 0; border-style: solid; border-color: currentColor }
```
Без сброса браузер рисует кнопкам и полям свою рамку `2px outset`, и она видна
у каждого варианта, который не объявляет `border-style` сам: `appearance-main-border`,
`appearance-passive`, `base-chip`, `icon-button`. Career написан в расчёте на этот
сброс: правило, которому нужна рамка, задаёт `border-width` явно
(`.notification`, `.checkbox-button`, `.base-section`), а состояния меняют только
`border-color`.

```css
button,input,optgroup,select,textarea { font-family: inherit; … }
```
Браузер не наследует шрифт в элементах формы. Без этого правила кнопки и поля
рисуются системным Arial вместо Inter. Текст — штатный preflight Tailwind,
который в настоящем Career приходит из базового CSS приложения.

Проверено по снимкам настоящего Storybook в
`../evidence/source/archive/storybook/`: там у этих компонентов чёрной обводки нет.

Больше ничего не дописано. Если правило не помечено как добавленное — оно из продукта.

## Почему утилиты Tailwind лежат отдельным файлом

Career верстает BEM-классами и утилитами одновременно, в одном атрибуте:

```html
<button class="base-button inline-flex appearance-main-border size-l has-before is-sizeable">
```

Убрать утилиты нельзя — без них разметка Career не воспроизводится. Перенести все
1 695 правил сборки тоже неправильно: 1 146 из них ни один компонент не использует.

Поэтому в `utilities.css` — ровно те правила, чьи классы физически встречаются
в разметке Career, плюс полная именованная шкала теней. Разбор — в
[`../evidence/coverage.md`](../evidence/coverage.md).

Брейкпоинты Career вынесены в шапку файла: шкала max-width-first,
`tablet:hidden` означает «скрыт при ширине ≤ 1023px».

## Две системы имён

`components/*.css` — новая реализация (Nuxt): `base-button`, `checkbox-label`,
`notification`, `text-input__input`.

`components.css` — старая (Rails, production): `basic-section`, `checkbox__wrapper`,
`checkbox__box`, а также решения, известные только по Figma и замерам.

Оба набора действующие: Career переезжает на новый стек по частям. Где имена
расходятся, спецификация компонента говорит об этом прямо.

Обратите внимание: **имя компонента в Storybook и имя класса в разметке
не всегда совпадают.** `BaseNotification` рендерит `.notification`,
`BaseIconButton` — `.icon-button`, `BasePaginationButton` — `.pagination-button`.

## Что сюда не входит

CSS документации. `showcase/components.css` и `showcase/pages.css` живут рядом с витринами,
используют префикс `--doc-*` и на внешний вид компонентов не влияют. При переносе
в UI Kit берётся только эта папка.
