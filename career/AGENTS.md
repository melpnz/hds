# Контракт Career machine-first

Размеры интерфейса берутся из `machine/dimension-tokens.json`; CSS-переменные подключаются через `ui/career.css`. Масштабируемая база — `0.25rem` при эталонном root `16px`; границы и толщина focus ring остаются в `px`, line-height использует безразмерные токены. Новые размеры не записывай литералами. Остальные значения сверяй с `machine/reports/dimension-exceptions.md` и не округляй без дизайнерского решения.

Это актуальный гайд Career v1.2. Начинай с
[`machine/index.json`](machine/index.json), затем следуй его `readOrder`.

## Как читать

1. Для задачи уровня нового продукта, страницы или общего визуального языка сначала открой `machine/style-profile.json`. Для одного компонента пропусти этот шаг.
2. Открой короткий `machine/catalog.json`.
3. Выбери один раздел и один адресный каталог из `file` или
   `groups[].file`.
4. Открой только `item.file` выбранной сущности.
5. `ruleFiles`, цветовые `groups`, examples и длинные guide sections
   загружай только по необходимости.
6. Не загружай все каталоги, компоненты, правила или assets для одной задачи. `machine/provenance/index.json` открывай только для аудита миграции, не как источник обычной реализации.

## Как реализовывать

- Подключай `ui/career.css`.
- Если есть `markup.html`, используй его copy-safe разметку без
  переименования классов.
- `implementation.markup: null` означает, что DOM не снят: не сочиняй его.
- Разделяй `stateGroups.ui`, feature states и domain states.
- Учитывай `knowledge`, evidence, maturity и unknowns.
- Для непокрытого сценария используй ближайший паттерн и явно назови
  допущение. Не выдавай его за подтверждённое поведение Career.

Пакет покрывает опубликованный Career v1.2 в пределах гостевого публичного
среза. Авторизованные сценарии, живые ошибки форм и модальные потоки остаются
неподтверждёнными.
