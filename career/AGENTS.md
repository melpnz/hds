# Контракт для модели

Инструкция потребителю-модели. Человеку — [`README.md`](README.md).

## Порядок чтения

1. [`machine/index.json`](machine/index.json) — точка входа: версия, пути, команды
   проверок, граница знаний.
2. Дальше только файлы, перечисленные в его `files`. Markdown читать не нужно:
   он для человека и содержит то же самое прозой.

Исключение — если задача попала за `coverage.boundary`. Тогда открывать
[`docs/guide/decisions.md`](docs/guide/decisions.md): там 16 Decision Guides
с оценкой уверенности и указанием, где заканчивается evidence.

## Как собирать экран

```
семейство страницы → области → модули → компоненты → тексты
```

1. **Семейство.** LISTING · DETAIL · PROFILE · RATING · DASHBOARD · SERVICE.
   Ни одно не подошло — задача за границей покрытия, см. ниже.
2. **Каркас.** Контейнер 1100 / `0 12px`, сетка 752 + 24 + 300. Сжимается
   главная колонка, сайдбар фиксирован. Обёртка `.career-shell` нужна только
   для `layout.css`: он написан на `@container`, а не на `@media`.
3. **Компоненты.** Брать из `machine/components.json` по `id`.
4. **Разметку** — из поля `markup.html`, **дословно**. Ничего не переименовывать:
   классы связаны с CSS, который вы не видите. Если у компонента `markup: null`,
   разметка не снята — не сочиняйте её, возьмите другой компонент или отметьте
   пробел.
5. **Значения** — только из `machine/tokens.json`. Литеральных цветов, отступов
   и радиусов не вводить: у Career холодная сине-серая шкала, и любой «обычный
   серый» сразу читается как чужой продукт.

## Чем проверять

- `rules` из `machine/rules.json` — 57 правил композиции. У большинства
  `predicate.type: "manual"`: проверяются глазами по `statement`.
- `node tools/validate-classes.mjs <файл.html>` — ловит классы, которых нет
  в CSS пакета. `ui/utilities.css` — подмножество Tailwind: валидная утилита
  вроде `gap-5` или `md:flex` в нём отсутствует и не сработает молча.
- Полный список — [чеклист готовности](docs/development/checklist.md).

## Граница

`coverage.boundary` в `index.json` говорит, где знание заканчивается. Пакет снят
**гостем, по публичной части продукта**. Не покрыты: личный кабинет, формы ввода,
модальные потоки, загрузка, ошибки форм, сценарии успеха.

Если задача там — пакет даёт **верный визуальный язык и компоненты** и **не даёт
верную структуру экрана**. В этом случае:

- взять ближайший подтверждённый паттерн как отправную точку;
- назвать допущение вслух — в ответе, в handoff, в комментарии к макету;
- **не** писать «в Career так принято», если за этим не стоит правило с покрытием.

Отсутствие раздела в пакете — это «не знаем», а не «не существует». Пустые места
оставлены пустыми намеренно: догадка, выданная за факт, портит не один экран,
а следующий, который на неё сошлётся.

## Состояния экрана

`machine/components.json` описывает состояния элемента. Что показывать, пока
данные грузятся, и чем «ничего не найдено» отличается от «ещё не искали» —
в [`docs/guide/feature-states.md`](docs/guide/feature-states.md). Это
**нормативный контракт**: почти все эти состояния живут за авторизацией и в
продукте не снимались.

## Чего в машинном слое пока нет

`areas` внутри паттерна — последовательность блоков. Извлекать не из чего:
композиции в витрине собраны не из каркасных модулей R4. Пока порядок блоков
берётся из [`docs/guide/page-families.md`](docs/guide/page-families.md).

`code.importPath` и `code.props` — требуют доступа к репозиторию `career-web`.
Имя Vue-компонента (`code.component`) выведено из Storybook и доступно.

Исполнимый предикат есть у 4 правил из 57; остальные `manual` и проверяются
глазами по `statement`.
