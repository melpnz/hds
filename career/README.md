# Habr Career — Design System Knowledge

Пакет знаний о визуальном языке **Хабр Карьеры**. Собран обратной разработкой:
инструментальные замеры production, Figma-библиотеки, Storybook новой реализации.

Дата последнего обновления: **3 сентября 2026**.
Статус: **v1.2 — MVP Product Design System**. Это не утверждённая дизайн-система
компании и не UI Kit; это карта того, что можно достоверно утверждать о Career
сегодня — но карта, которую можно брать в работу как есть.

**Что такое v1.2.** Пакет стал пригоден не только для воспроизведения Career,
но и для проектирования нового в его языке. Появился слой решений:
[`RULES.md`](RULES.md) §13 — 16 Decision Guides, §14 — наблюдения о продуктовых
текстах. Каждый Decision Guide разделён на **OBSERVED** (что наблюдалось),
**DECISION GUIDE** (как этим пользоваться в похожем контексте) и **GAP**
(где evidence кончается), и несёт собственную оценку уверенности. Новых правил
при этом не изобреталось: всё собрано из уже подтверждённого. Ниже —
раздел **Coverage / Known limits**, фиксирующий границу пакета.

**Что такое v1.1.** Та же v1.0 по содержанию — перестроена только файловая
структура, разбор в [CHANGELOG.md](CHANGELOG.md).

**Что такое v1.0.** Компоненты описаны настоящим CSS Career, извлечённым из сборки
`career-web`: 63 файла компонентов, 121 переменная, 146 символов иконок,
41 иллюстрация. Слой машиночитаемых спецификаций [`components/`](components/) —
77 файлов: 75 исходных спецификаций плюс Badge и Tabs, поднятые из существующего
CSS/showcase в ходе развития UI kit. Пакет не зависит от Storybook, а разметку из любой
спецификации можно скопировать на пустую страницу с одним
[`ui/career.css`](ui/career.css) — и она выглядит правильно, вместе
с иконками. Изменения относительно v0.5 — в [CHANGELOG.md](CHANGELOG.md).

## Coverage / Known limits

Исследование велось **гостем**, по публичной части продукта. Это определяет
границу пакета, и знать её нужно до того, как браться за задачу.

**Хорошо покрыто** — есть замеры, живая реализация и правила с покрытием:

* продуктовая оболочка: шапка, контейнер, сетка, подвал;
* листинг сущностей — самое частое семейство, 6 страниц;
* страница сущности (detail);
* профиль человека и организации;
* адаптив публичных страниц на четырёх вьюпортах;
* переиспользуемые компоненты — 77 спецификаций с настоящим CSS и разметкой;
* пустой результат поиска и служебный экран 404.

**Покрыто частично** — правила есть, но покрытие низкое:

* дашборд и рейтинг — по одной странице каждый, правила `DB-*` помечены
  как ненадёжные;
* сложные состояния: наблюдались пустой результат и 404, остальные нет.

**Не покрыто, evidence недостаточно:**

* личный кабинет и всё, что видит авторизованный пользователь;
* полноценные формы ввода данных — правила `F-*` выведены из фильтров листинга,
  а не из форм;
* модальные потоки: компонент есть, сценарии не наблюдались;
* загрузка и скелетоны;
* ошибки формы в живом продукте;
* сценарии успеха и подтверждения;
* тексты ошибок, подтверждений и сообщений об успехе.

### Главное правило

**Если задача попадает в непокрытую зону, пакет гарантирует визуальный язык
и компоненты — и не гарантирует правильную структуру экрана.**

Практически это значит: компоненты, токены, сетка, цвета и типографика
останутся верными, а состав экрана, порядок блоков и расположение действий
окажутся догадкой.

**Догадку нельзя молча выдавать за паттерн Career.** Если решение принято
без evidence, оно помечается как решение — в handoff, в комментарии к макету,
в ответе. Формулировка «в Career так принято» допустима только тогда, когда
за ней стоит правило с покрытием.

Что делать, когда правила не хватает: взять ближайший подтверждённый паттерн
как отправную точку, назвать сделанное допущение вслух и **спросить**,
а не достроить. Пакет спроектирован так, чтобы пробел был виден: пустые места
в нём оставлены пустыми намеренно.

Полный разбор границ — [`RULES.md`](RULES.md) §15 и раздел «Чего здесь нет
и почему» в [`showcase/pages.html`](showcase/pages.html).

## When to use

* Новый экран или функция внутри **Хабр Карьеры**.
* Прототип, который должен выглядеть как Career, а не как «аккуратный современный SaaS».
* Проверка готового макета на соответствие продукту.
* Подготовка будущего Career UI Kit.

## Current system status

**Career существует в двух реализациях одновременно.**

```
career.habr.com — большая часть          career.habr.com — /resumes, /salaries,
├── Ruby on Rails + Webpacker            │   часть профилей компаний
├── Vue 3 островами                      ├── Nuxt + Vue 3 SFC
├── 0 CSS-переменных на :root            ├── Tailwind CSS
└── SCSS → литералы                      ├── 121 CSS custom property 
                                          └── тот же стек, что у Хабр Курсов
```

Продукт переезжает на новый стек по частям. **Композиция при переезде не меняется:**
контейнер 1100/12, сетка 752 + 24 + 300, шаг карточек 12 и padding карточки 24
одинаковы в обеих реализациях. Меняется способ записи значений, а не сами значения.

Практический вывод: **берите значения из новой реализации** (`ui/tokens.css`),
но композиционные правила справедливы для обеих.

## Source authority

Иерархия, применённая в пакете. Она **не механическая** — у каждого источника
своя зона компетенции.

```
1. Figma  new-career-lib / new-career-modules   ← НАМЕРЕНИЕ
      сильнее всего: токены, размерные шкалы, матрицы вариантов и статусов
      слабее: композиция страниц (её там нет вообще)

2. career-web  (Storybook + новая реализация)   ← РЕАЛИЗАЦИЯ
      сильнее всего: значения переменных, анатомия компонентов
      слабее: что из 99 компонентов актуально, а что переходное

3. career.habr.com  production                  ← ФАКТ
      сильнее всего: КОМПОЗИЦИЯ СТРАНИЦ — единственный источник
      слабее: значения (устаревающая часть не имеет токенов)

4. Устаревающая реализация                      ← LEGACY
      применяется, только когда других источников нет
```

### Как разрешались спорные случаи

Правило: **выбор опирается на источник, а не на то, что «выглядит логичнее».**

| Случай | Решение | Основание |
|---|---|---|
| Padding секции 16 ↔ 24 | **24** | Замер production **новой** реализации. Значение 16 относилось к обёртке story |
| Граница карточки: есть ↔ нет | **есть, 1px `rgba(24,46,57,.1)`** | Замер 12 страниц в обеих реализациях + Storybook. Прежний вывод был ошибкой замера |
| Высота чипа 28 ↔ 32 | **32** | Новая реализация. Аргумент «32 лучше выравнивается с кнопкой M» сам по себе доказательством не является — решает то, что это текущая реализация |
| Активный сегмент табов: белый ↔ фиолетовый | **фиолетовый** _(закрыто в v0.5)_ | Снята разметка: активная вкладка получает `text-ui-white`, а под текстом лежит слой `bg-ui-primary`. Белого варианта в реализации нет |
| Цвет фокуса `#fdb814` | **устаревшее значение** _(закрыто в v0.5)_ | Единого цвета фокуса нет: `outline: 2px solid` цветом самого варианта при 60%, только на `:focus-visible` |
| Системный красный `#e21212` ↔ `#f8651b` | **`#f8651b`** _(закрыто в v0.5)_ | У кнопки есть `appearance-danger` и `danger-border`; `#e21212` в новой реализации не встречается |

## Visual DNA

Пять признаков, по которым Career узнаётся. Если новый экран нарушает их,
он перестаёт быть Career — даже при правильных компонентах.

### 1. Белый фон и границы вместо теней

Фон страницы — чистый `#ffffff`. Поверхности разделяются **границей 1px
`rgba(24,46,57,.1)`** и полупрозрачным сине-серым тинтом, а не серым фоном
и не тенью. Во всём продукте существует ровно одна тень — у выпадающих меню.
Карточка при наведении не поднимается, не получает тень и не меняет фон.

### 2. Холодная сине-серая нейтральная шкала

Семь ступеней с hue около 200°: `#1b272c → #55798b → #7996a5 → #a6bdc9 →
#d4dee2 → #eaf2f5 → #f8fbfc`. Это не нейтральный серый. Рядом с белым
разница в характере заметна сразу — нейтральный серый читается как Курсы.

### 3. Фиолетовый — действие, синий — ссылка

`#8164f7` — только действие: кнопка, активный контрол, иконка-действие.
`#0464d2` — только ссылка. Роли не смешиваются. **Фиолетовый не заливает
площади:** фиолетовой секции, баннера или hero в Career нет.
Единственное исключение — заливка активной строки разреза на дашборде
(`primary @ 10%`).

### 4. Микро-метка 12/16 как способ группировки

Метаданные группируются меткой **12/16·400 `#7996a5`** — не подписью поля
и не заголовком, а ярлыком группы, под которым идёт строка чипов.
Приём встречается на страницах обеих реализаций и является одним из самых
узнаваемых в продукте.

### 5. Плотность

Отступ 4 встречается на порядок чаще остальных. Между карточками — 12,
внутри карточки — 24. Career — плотный интерфейс: он показывает много,
но не производит впечатления тесноты за счёт светлого фона и мягких радиусов.

> **Чего в Career нет:** теней у плоскостей — карточка отделяется рамкой, а не
> тенью; тени есть у всплывающих слоёв (шесть именованных классов перечислены
> в Foundations) и ещё в двух местах зарплатной шкалы, где тень работает как
> графический акцент на диаграмме, а не как отрыв поверхности:
> `.salary-bar__median-divider` и `.salary-bar__sub-bar`.
> Дальше: градиентов (кроме промо-слоя «Бустер» и AI),
> тёмных секций (кроме верхней панели Хабра 48px), uppercase, отрицательного
> трекинга, липких панелей действий, масштабирования типографики на мобильном.

Живая витрина — [`showcase/#s-foundations`](showcase/components.html#s-foundations).
Токены — [`ui/tokens.css`](ui/tokens.css).

| | |
|---|---|
| **Шрифт** | Inter, переменный, `font-weight: 100 900`. В интерфейсе используются 400 и 600. Подключается из Google Fonts — [`ui/fonts.css`](ui/fonts.css). В продукте раздаётся с `assets.habr.com` |
| **Шкала текста** | Именованная, из сборки: `text-display-xl` 28/32 · `-l` 24/28 · `-m` 20/24 · `-s` 18/24 · `text-body-l` 16/24 · `-m` 14/20 · `-s` 12/16 · `-xs` 11/16. Прочие значения встречаются в устаревающей реализации |
| **Цвет** | 121 переменная, полный разбор — [`evidence/tokens.md`](evidence/tokens.md). Альфа-производные выводятся из базовых через `color-mix()` |
| **Отступы** | Переменных нет: отступы задаются утилитами (`gap-2`, `p-6`). Шаг 4. Рабочие значения — 4 · 8 · 12 · 16 · 24, на них приходится подавляющее большинство. Реже, но штатно: 2 · 32 · 48. Значения 6 · 10 · 20 · 44 единичны и привязаны к одному месту — за общее правило их принимать не надо |
| **Радиусы** | Переменных нет: утилиты `rounded-*`. 8 (кнопка M/SM, чип) · 12 (кнопка L/XL, поле) · 24 (`rounded-3xl` — карточка) · full (круглые контролы, бейдж, аватар человека) |
| **Границы** | Границы плоскостей — всегда 1px: `rgba(24,46,57,.1)` карточки · `#d4dee2` контролы · `#ededed` плотная сетка. 2px встречается только как обводка поверх фона, а не как граница поверхности: кольцо счётчика непрочитанных (`border-2 border-ui-white`) и кольцо фокуса сегментированных вкладок |
| **Тени** | Шесть именованных классов, не переменные: `shadow-border` · `shadow-gray-shadow` · `shadow-dropdown` · `shadow-float-element` · `shadow-float-notice` · `shadow-context-menu-dropdown`. Значения — в [`evidence/tokens.md`](evidence/tokens.md) |
| **Иконки** | 146 символов в 5 спрайтах, все локально: [`ui/assets/icons/`](ui/assets/README.md). Плюс 127 отдельных файлов в `single/` и объединённый пак из 21 иконки в `pack/`. Базовый размер 24×24, цвет наследуется от текста |
| **Высоты контролов** | 28 · 32 · 40 · 48 (`size-sm` / `m` / `l` / `xl`) |
| **Контейнер** | `max-width: 1100px`, `padding: 0 12px`, полезная ширина 1076 |
| **Брейкпоинты** | Три: **480 · 768 · 1024**. Имена вариантов: `small-phone` ≤479 · `phablet-only` 480–767 · `phone` ≤767 · `tablet` ≤1023 · `desktop` ≥1024. Шкала max-width-first. Полный разбор и контрольные ширины — [`RULES.md`](RULES.md) §11 |
| **Что брейкпоинтом не является** | **1100** — это `max-width` контейнера (`SH-5`), медиазапроса на него нет ни одного. **320** и **1440** — контрольные ширины, запросов на них тоже нет. Вариант `tablet-only` 768–1023 объявлен в теме, но правил с ним в сборке нет. Единственный запрос вне шкалы — `max-width: 360px` из стороннего Toastify и `-webkit-min-device-pixel-ratio: 1.5` для ретина-фона одной карточки |

## Accessibility

Раздел описывает **только то, что физически есть в извлечённой разметке и CSS**.
Career не публиковал требований к доступности, и пакет их не выдумывает: если
атрибута в снимке нет, здесь об этом сказано прямо, а не заполнено «как принято».

**Что есть в коде и работает.**

| Приём | Где | Сколько в пакете |
|---|---|---|
| `aria-label` | иконочные кнопки, пагинация, навигация, поля без видимой метки | 68 |
| `aria-pressed` | кнопки-переключатели, чипы-фильтры | 40 |
| `aria-hidden` | декоративные значки внутри кнопок с текстом | 12 |
| `aria-current` | активный пункт навигации и текущая страница пагинации | 9 |
| `aria-labelledby` | секции, озаглавленные видимым заголовком | 3 |
| `aria-disabled` | ссылка в роли выключенной кнопки (`is-link-disabled`) | 2 |
| `aria-expanded` | кнопка, раскрывающая список | 1 |
| `role="combobox"` · `role="region"` | кастомный селект · озаглавленная область | по 1 |
| `sr-only` · `visually-hidden` | подпись только для скринридера; настоящий `input` под кастомным контролом | 26 · 7 |

**Фокус.** У кнопок, чипов и вкладок кольцо фокуса объявлено и показывается строго
на `:focus-visible` — при клавиатурной навигации, но не по щелчку мыши. Всегда
`outline: 2px solid` цветом варианта на 60 % прозрачности, `outline-offset: 2px`
(11 объявлений). У брендированных кнопок кольцо сделано двойной тенью
`0 0 0 1px #fff, 0 0 0 3px var(--color-font-black)` — чтобы читаться на цвете компании.
У сегментированных вкладок вместо `outline` используется псевдоэлемент `after:`
с рамкой 2px, а сам `outline` снят — замена на месте.

**А у полей ввода кольца фокуса нет.** Это не пробел извлечения, а поведение самой
сборки: `.text-input:focus-within` и `.text-input:hover` меняют только `border-color`,
тогда как рамка у поля нарисована тенью `inset 0 0 0 1px`, а `border-width` равен нулю.
Замерено в живом рендере: при фокусе меняется только вычисленный `border-top-color`
с `#1b272c` на `#55798b`, видимого изменения нет. Ещё три места объявляют
`outline: none`: `.base-select__input:focus` и `.button-range__button:focus-visible`
дают замену (цвет границы, тень-кольцо), а `.suggestion-item__button:focus` — нет.
Кольцо для полей пакет добавляет сам — в нормативном слое `ui/state-contract.css`,
отдельно от извлечённого CSS. Показывается оно только при переходе Tab: у input
и textarea `:focus-visible` по спецификации срабатывает и при фокусе указателем,
поэтому одним CSS клик от Tab не отличить. Режим отмечает необязательный
`ui/focus-modality.js` атрибутом `data-focus-modality` на `<html>`; без скрипта
кольцо показывается всегда, то есть клавиатура без видимого фокуса не остаётся.

**Скрытый настоящий контрол.** Чекбокс, радио, переключатель и звёздный рейтинг
рисуются `span`-ами, но под ними лежит настоящий `input`, спрятанный классом
`visually-hidden` / `sr-only`. Клавиатура и скринридер работают с ним; заменять
эту конструкцию на `div` с обработчиком нельзя.

**Чего в снятой разметке нет.** В 58 спецификациях из 75 раздел «Доступность»
говорит «в снятой разметке нет ARIA-атрибутов и role, не достраиваем». Это не
означает, что их не должно быть — только то, что источник о них молчит.
Практически это значит: **модальные окна, выпадающие списки, тултипы и тосты
приходят без `role`, без ловушки фокуса и без связей `aria-describedby`.**
Если вы делаете новый экран, эту часть придётся спроектировать самостоятельно —
опереться в пакете не на что.

**Контраст.** Посчитан по формуле WCAG для нейтральной шкалы на белом фоне:

| Переменная | Значение | Контраст | AA для основного текста (4.5) |
|---|---|---|---|
| `--color-ui-gray-1` | `#1b272c` | 15.29 | да |
| `--color-ui-gray-2` | `#55798b` | 4.67 | да |
| `--color-ui-gray-3` | `#7996a5` | 3.13 | нет — только для крупного текста |
| `--color-ui-gray-4` | `#a6bdc9` | 1.95 | нет |
| `--color-ui-primary` | `#8164f7` | 4.12 | нет, на грани |

Практический вывод: `gray-3` — предел для третьестепенных подписей, `gray-4`
годится только для границ и выключенных состояний. Фиолетовый как цвет текста
на белом AA не проходит; в продукте он и используется почти только как фон кнопки,
где текст белый.

## Current conflicts

Нерешённые расхождения между источниками. **Не входят в reusable-набор.**
Разбор — `research/system-audit.md` §13, показ — раздел «Отложено»
в [`showcase/`](showcase/components.html#s-deferred).

| Конфликт | Состояние |
|---|---|
| Какая из трёх Figma-библиотек Career — источник истины | открыт |
| Промо-состояние карточки вакансии | открыт, уверенность средняя |
| Расхождение имён между двумя реализациями (`checkbox__box` ↔ `checkbox-button`) | не конфликт: оба набора действующие, продукт переезжает по частям |

Закрыты в v0.4: **padding секции** (24), **граница карточки** (есть),
**значения брейкпоинтов** (1024 у legacy; 480/768/1024 у новой реализации).

Закрыты в v0.5 — извлечением настоящего CSS, а не выбором из вариантов:

| Что было открыто | Чем закрылось |
|---|---|
| Активный сегмент табов: белый ↔ фиолетовый | **фиолетовый.** Разметка снята: активная вкладка получает `text-ui-white`, а под текстом лежит отдельный слой `span.absolute.inset-0.bg-ui-primary`. Белого варианта в реализации нет |
| Цвет кольца фокуса `#fdb814` | **устаревшее значение.** В новой реализации фокус — `outline: 2px solid` цветом самого варианта при 60% непрозрачности, `outline-offset: 2px`, и только на `:focus-visible`. Единого «цвета фокуса» у Career нет |
| Системный красный для кнопки danger | **`--color-ui-red` `#f8651b`.** У кнопки есть варианты `appearance-danger` и `danger-border`; `#e21212` в новой реализации не встречается |
| Padding секции 16 ↔ 24 | **оба верны и это не конфликт.** `:where(.base-section)` задаёт 24, `--padding-medium` — 16. Это два варианта одного компонента, а не расхождение источников |
| Высота чипа 28 ↔ 32 | **32**, `min-height: 2rem` в CSS компонента |
| Размерная шкала кнопки | `sm` **28** (а не 24), `m` 32, `l` 40, `xl` 48 |
| Значения `tablet:` и `phone:` в утилитах | 1023 и 767, извлечено из медиазапросов сборки |

## Чего этот пакет не делает

Он **не** является утверждённой дизайн-системой, UI Kit, npm-пакетом,
Tailwind-пресетом или компонентной библиотекой. Он не нормализует
противоречия и не достраивает неизвестное.

Если решение не подтверждено источником, его здесь нет — и это осознанно.
Надёжный пакет с пробелами полезнее полного пакета с догадками.

**И он не содержит проектируемых фич.** Career — source of truth: то, что о продукте
известно сегодня. Новые экраны и предложения живут в [`../design/`](../design/README.md),
в папке своей задачи, и берут отсюда `ui/`, `RULES.md` и спецификации — но ничего
сюда не возвращают, пока решение не станет частью продукта.
