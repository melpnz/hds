# Career — роадмап

Актуальный пакет опубликован по стабильному пути `career/`. Старый пакет сохранён
локально в `archive/career/v1/` и не входит в GitHub. Полная карта текущего гайда —
в [`machine/index.json`](machine/index.json), границы покрытия — в
[`machine/guides/coverage.json`](machine/guides/coverage.json).

## Следующие задачи

### Четыре модуля без достоверного preview

Не восстанавливать DOM по одному CSS и не показывать preview другого компонента
как будто это нужный модуль.

| Модуль | Что уже есть | Что нужно для закрытия |
|---|---|---|
| `JournalBlockSidebar` | назначение, Storybook-имя и наблюдаемые тексты | production или рабочий Storybook snapshot бокового блока: `outerHTML`, скриншот, размеры и состояния |
| `PromotionCard` | CSS и варианты `header` / `resumes` | DOM обоих вариантов, используемые изображения и иконки, скриншоты на характерных ширинах |
| `ResumeCard` | назначение и небольшой фрагмент CSS | DOM и скриншоты трёх заявленных Storybook-вариантов; предпочтительно snapshot `/resumes` |
| `TestResultModals` | CSS содержимого и готовый базовый `Modal` | открытый DOM и скриншоты `ScreeningsListModal`, `SkillsTestResultModal`, `SpecsTestResultModal`, включая loading/error/success, если доступны |

Предпочтительный источник — репозиторий `career-web`; затем рабочий Storybook,
production `outerHTML` + скриншот, затем Figma. Для каждого модуля нужно
зафиксировать props/варианты, основные состояния, ассеты и доступность.

Критерий готовности: подтверждённый DOM, хотя бы один визуальный эталон,
адресный standalone preview и provenance в машинной спецификации. После этого
убрать `copy-safe-markup-not-captured`.

`TransitionFade` сюда не входит: это CSS-переход без собственного DOM и
самостоятельного визуального вида. Отсутствие preview для него корректно.

### Остальные неподтверждённые сценарии

- Авторизованные страницы и личный кабинет.
- Живые ошибки форм и модальные потоки.
- Раскрытые состояния `CustomSelect`, `MultiSelect` и `ContextMenu`.
- DOM тоста `notify()`.
- Соответствие имён иконок Figma и спрайта реализации.

## Правила ведения

- Не додумывать DOM и поведение без источника.
- Новое знание добавлять в адресную машинную сущность, а не в общий монолит.
- Повторную проверку проводить инкрементально по изменённым сущностям; полный
  `npm run validate` оставлять финальным gate.
- Локальную сверку с архивом запускать при наличии `archive/career/v1/`;
  опубликованный пакет обязан проходить проверку и без архива.
