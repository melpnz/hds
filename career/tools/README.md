# Проверки Career components

## Базовая проверка

```bash
node career/tools/validate-components.mjs
```

Проверяет структуру `components/manifest.json`, уникальность имён, допустимый
словарь состояний, существование спецификаций и showcase anchors. Пробелы в
state evidence выводятся как warnings, чтобы текущий baseline можно было
улучшать постепенно.

## Строгий режим

```bash
node career/tools/validate-components.mjs --strict
```

Завершается с ненулевым кодом и при errors, и при warnings. Текущий baseline
проходит strict-режим; команда предназначена для CI вместе с `npm test`.

Warnings нельзя устранять добавлением слов в спецификацию. Они закрываются
одним из трёх способов:

1. состояние реализовано и показано живым примером;
2. существующее поведение найдено в runtime и корректно задокументировано;
3. состояние помечено `unsupported` с обоснованием и удалено из requiredStates.

## Иконки витрины

```bash
node career/tools/sync-showcase-icons.mjs          # обновить
node career/tools/sync-showcase-icons.mjs --check  # только проверить
```

`inline-showcase-icons.mjs` переносит иконку в разметку один раз, после чего
её содержимое живёт в HTML копией: правка файла в `ui/assets/` до витрины
не доходит. `sync-showcase-icons.mjs` перечитывает каждый
`<svg data-icon-src="…">` и обновляет внутренность, `viewBox` и `fill`.
Режим `--check` ничего не пишет и падает, если копии разошлись, — его место
в CI рядом с `validate-showcase-icons.mjs`.

## Классы без определения

```bash
node career/tools/validate-classes.mjs                   # витрины пакета
node career/tools/validate-classes.mjs путь/к/фиче.html   # своя разметка
```

`ui/utilities.css` — не весь Tailwind, а только правила, встретившиеся
в разметке Career. Валидная утилита вроде `gap-5` или `md:flex` в нём
отсутствует и поэтому не применяется — молча, без ошибки в консоли. Проверка
сравнивает классы разметки с тем, что реально объявлено в CSS, и падает,
если найден класс без правила.

Своя разметка сверяется только с `ui/`: если класса там нет, на странице
с одним `career.css` он не сработает.

Базовая линия известных пробелов — `tools/known-missing-classes.json`,
у каждой записи указана причина. Они выводятся предупреждением и не роняют
проверку, чтобы не мешать поймать новые.

## Счётчики в документации

```bash
node career/tools/validate-counts.mjs
```

Числа — компонентов, спецификаций, переменных, утилит, иконок — записаны
в прозе в десятке мест и правятся руками. После правки пакета они расходятся
молча, и по устаревшему числу судят о покрытии. Проверка считает реальные
значения и сверяет их с заявленными; при расхождении печатает, где и на сколько.

## Машинный слой

```bash
node career/tools/build-machine.mjs      # собрать machine/*.json из источников
node career/tools/validate-machine.mjs   # сверить его с текстом и с CSS
```

`machine/` собирается **из источников**, а не пишется руками: правка
`machine/*.json` бессмысленна, следующая сборка её сотрёт. То, чего скрипт снять
не может, живёт в `machine/*.overrides.json`.

Валидатор падает, если `id` разошлись между JSON и `manifest.json`, значение
токена не совпало с CSS, правило не найдено в markdown, в разметке компонента
есть класс без правила или счётчики в `index.json` разъехались с содержимым.

## Возраст evidence

```bash
node career/tools/check-evidence-age.mjs --max-age=90
```

Снимки продакшена стареют молча: даты снятия внутри файлов нет. Скрипт печатает
возраст каждого снимка и его URL. Старше порога — не ошибка, а повод пересверить;
порядок пересъёмки описан в `docs/guide/coverage.md`.
