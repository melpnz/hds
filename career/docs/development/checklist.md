# Чеклист готовности экрана

Что проверить, прежде чем считать новый экран или фичу сделанной. Список
рассчитан на того, кто собрал интерфейс по этому пакету, — не на ревью самого
пакета: для него есть отдельный чеклист в конвейере сборки.

Половина пунктов проверяется командой, а не глазами. Начните с них: они дешевле
и ловят то, что глаз пропускает.

---

## 1. Машинные проверки

```bash
node career/tools/validate-classes.mjs путь/к/фиче.html
```

Ищет классы, которые есть в разметке, но не определены ни в одном CSS пакета.
`ui/utilities.css` — не весь Tailwind, а только правила, встретившиеся
в разметке Career: валидная утилита вроде `gap-5` или `md:flex` в нём
отсутствует и не сработает — молча, без ошибки в консоли.

Если экран живёт внутри пакета, добавьте к нему и остальные:

```bash
node career/tools/validate-counts.mjs        # числа в документации не разошлись
node career/tools/sync-showcase-icons.mjs --check
node career/tools/validate-components.mjs --strict
npx playwright test
```

## 2. Каркас

- [ ] Экран отнесён к одному из семейств: LISTING · DETAIL · PROFILE · RATING ·
      DASHBOARD · SERVICE. Ни одно не подошло — задача в непокрытой зоне,
      см. [границы](../guide/coverage.md).
- [ ] Контейнер **1100** с полями `0 12px`; сетка **752 + 24 + 300**.
      Сжимается главная колонка, сайдбар фиксирован.
- [ ] Заголовок экрана лежит **внутри** первой карточки — вместе с поиском,
      сортировкой и счётчиком, если они есть.
- [ ] Шаг между карточками **12**; padding карточки **24**, радиус **24**,
      граница 1px. Ни тени, ни подъёма при наведении.
- [ ] Основное действие — **в шапке сущности**, не в конце страницы
      и не в липкой панели.

## 3. Визуальный язык

- [ ] Фон страницы белый; поверхности разделяются границей, а не серым фоном
      и не тенью. Тень есть только у всплывающих слоёв.
- [ ] Нейтральные — холодная сине-серая шкала Career, а не нейтральный серый.
- [ ] Фиолетовый только для действия, синий только для ссылки. Фиолетовый
      не заливает площади: фиолетовой секции или hero в Career нет.
- [ ] Метаданные сгруппированы микро-меткой 12/16 · 400 `gray-3`.
- [ ] Ни одного литерального цвета или размера там, где есть токен.

## 4. Состояния

- [ ] У каждого интерактивного элемента есть `default`, `hover`,
      `focus-visible`, `pressed`, `disabled` — имена только из
      [словаря](../../components/STATES.md).
- [ ] Состояния работают в браузере, а не только описаны.
- [ ] Загрузка, пустой результат и ошибка предусмотрены — или явно отложены
      с указанием причины. Молчаливое отсутствие — не решение.
- [ ] Данных нет из-за пустого ответа, а не из-за ошибки, — это разные экраны.

## 5. Адаптив

- [ ] Проверено на **375 · 768 · 1024 · 1440**.
- [ ] Оболочка перестраивается на **1023**, а не на 767: медиазапрос
      сравнивается с шириной окна вместе с полосой прокрутки.
- [ ] Типографика **не** масштабируется: H1 остаётся 28/32 и на 375.
- [ ] Нет горизонтальной прокрутки документа ни на одной ширине.
- [ ] Длинный текст, пустое значение и отсутствие иконки не ломают раскладку.

## 6. Доступность

- [ ] Иконочные кнопки имеют `aria-label`; декоративные значки — `aria-hidden`.
- [ ] Кольцо фокуса видно при обходе Tab и не теряется; порядок табуляции
      осмысленный.
- [ ] Переключатели используют `aria-pressed`, текущий пункт — `aria-current`.
- [ ] Под кастомным чекбоксом, радио и переключателем лежит настоящий `input`,
      а не `div` с обработчиком.
- [ ] Модальное окно возвращает фокус триггеру и закрывается по Escape.
- [ ] Цвет не единственный носитель смысла: статус продублирован текстом.

## 7. Допущения

- [ ] Всё, чего не было в пакете и что пришлось решить самому, названо вслух —
      в handoff, в комментарии к макету или в ответе.
- [ ] Формулировка «в Career так принято» использована только там, где за ней
      стоит правило с покрытием.
- [ ] Если решение опиралось на [Decision Guide](../guide/decisions.md),
      указано, на какой именно и какая у него уверенность.
