# Состояния фичи

Словарь [`components/STATES.md`](../../components/STATES.md) описывает состояния
**элемента**: hover, focus-visible, disabled. Он не отвечает на вопрос, что
показать, пока данные грузятся, и чем «ничего не найдено» отличается от «ещё
не искали». Эта страница — про второе.

> **Это нормативный контракт, а не наблюдение.** В продукте эти состояния снять
> не удалось: почти все они живут за авторизацией. Здесь записано, как их
> собирать из уже подтверждённых компонентов и правил, чтобы не изобретать
> каждый раз заново. Где нужно решение — оно помечено как решение.
> Границы покрытия — [`coverage.md`](coverage.md).

---

## Цепочка

Экран с данными проходит по одной из веток. Пропускать звенья нельзя: каждое
отвечает на свой вопрос пользователя.

```
                    ┌─ empty-before-search  «ещё не искали»
idle ─→ loading ─→ ─┼─ no-results           «искали, ничего нет»
                    ├─ success              «вот данные»
                    ├─ error ─→ retry       «не смогли, попробуйте ещё»
                    └─ forbidden            «нельзя»
```

| Состояние | Когда | Чем собирается |
|---|---|---|
| `idle` | форма не отправлена, фильтр не тронут | обычный экран |
| `loading` | запрос в пути | `Skeleton` в форме будущего содержимого; `aria-busy="true"` на секции |
| `empty-before-search` | поиск ещё не выполнялся | `EmptySection` с приглашающим текстом и основным действием |
| `no-results` | запрос выполнен, данных нет | `EmptySection` с текстом про сброс фильтров; **подтверждено**: наблюдался пустой результат поиска |
| `success` | данные пришли | обычный экран |
| `validation` | форма не прошла проверку | `aria-invalid` на поле, текст ошибки связан через `aria-describedby` |
| `error` | сеть или сервер | `Notification` варианта `danger`, содержимое не подменяется |
| `retry` | после `error` | действие в самом `Notification`, не отдельным экраном |
| `forbidden` | нет прав | служебный экран семейства SERVICE |

---

## Правила

**`loading` не подменяет каркас.** Скелетон повторяет форму того, что придёт:
столько же карточек, та же высота. Экран не должен прыгать, когда данные
приедут. Спиннер вместо всей страницы — не вариант Career: у продукта есть
`Skeleton`, и он используется по месту.

**`empty-before-search` и `no-results` — разные экраны.** Первый приглашает
к действию, второй объясняет, почему пусто, и предлагает сбросить фильтр.
Одинаковый текст в обоих — самая частая ошибка.

**`error` не стирает то, что уже показано.** Если список загружен, а обновление
не прошло, список остаётся; ошибка приходит `Notification`. Подменять содержимое
экрана ошибкой можно только когда показывать нечего.

**`retry` живёт внутри сообщения об ошибке.** Отдельная кнопка «Повторить»
где-то на странице оставляет пользователя гадать, что именно повторится.

**Необратимое действие подтверждается модальным окном**, и кнопка подтверждения
получает `appearance-danger`. Отмена — `appearance-passive`, не ссылка.

**`forbidden` — это SERVICE-экран**, а не пустое состояние внутри листинга:
у семейства SERVICE сетка отменяется, и это верный сигнал, что пользователь
не там.

## Доступность

- Секция в загрузке получает `aria-busy="true"`; спиннеру не назначается
  `role="status"` в каждом месте — это создаёт повторяющиеся объявления.
- Появление ошибки объявляется live-регионом. Обычное пустое состояние
  `role="alert"` **не** получает: оно не событие.
- Ошибка поля связана с полем через `aria-describedby`, а не только цветом
  рамки.
- При `prefers-reduced-motion: reduce` скелетон не мигает, а остаётся
  статичным.

## Что здесь решение, а не факт

Подтверждены наблюдением только `no-results` и служебный экран 404. Всё
остальное — сборка из подтверждённых компонентов по общей логике. Если для
вашей задачи это важно, снимите живой сценарий и замените решение фактом:
строка про это есть в [`ROADMAP.md`](../../ROADMAP.md).
