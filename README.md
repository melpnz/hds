# HDS — гайды Хабра

Гайды для создания интерфейсов сервисов и лендингов. Здесь собраны правила визуального языка, примеры, компоненты и границы применимости. Это частично готовые пакеты знаний, а не единая завершённая дизайн-система.

**Начни с этого файла.** Его можно дать коллеге или ИИ вместе с описанием задачи:

> Прочитай README в репозитории https://github.com/melpnz/hds, выбери подходящий маршрут и используй его при разработке. Моя задача: …

## Что собираемся создать

Если ты ИИ и тип задачи ещё не указан, спроси: **«Что создаём: интерфейс сервиса или лендинг?»** После ответа предложи соответствующий выбор:

| Интерфейс сервиса | Лендинг |
|---|---|
| Хабр | О компании |
| Карьера | Продуктовый |
| Курсы | Брендинговый, акционный |
| Q&A | Партнёрский спецпроект |

Если пользователь уже назвал продукт и тип задачи, не спрашивай повторно. «Страница Хабра» неоднозначна — уточни интерфейс или промо. Для лендинга выясни продукт/бренд и цель страницы, если их нет в запросе. Затем открой файлы своего маршрута ниже; одной ссылки на них пользователю недостаточно.

## Маршруты для лендингов

Сначала открой введение и «Типы правил» **одного** выбранного документа, затем разделы по задаче:

| Тип лендинга | Основной маршрут |
|---|---|
| **О компании** | [Компания и B2B-направление](05-company-landings.md) |
| **Продуктовый** | [Промо продуктов](06-product-landings.md) |
| **Брендинговый, акционный** | [Имиджевые и брендовые спецпроекты](07-brand-specials.md) |
| **Партнёрский спецпроект** | [Совместные проекты с компаниями](08-partner-specials.md) |

Эти документы описывают исследованные страницы, а не универсальные шаблоны. Акционный проект без близкого примера требует собственного решения; не объявляй его готовым паттерном. В партнёрском проекте учитывай бренд партнёра, в продуктовом — какой продукт продвигается. B2B-страницы рекламных продуктов company.habr.com относятся к первому маршруту; при такой неоднозначности уточни контекст.

**Новый пакет [landings/](landings/README.md) активно разрабатывается.** Для применения новых блоков или нового брендового стиля проверь [роадмап](landings/ROADMAP.md) и прочитай только относящиеся к задаче принятые материалы. Наличие CSS-файла или папки не означает готовность. Не считай весь пакет готовым и не считай его автоматически заменившим все четыре документа выше. В покрытой области учитывай новые принятые решения и явно отличай их от старых наблюдений; при неразрешённом конфликте обозначь его, а не смешивай правила молча.

## Как применять гайд и не читать лишнее

1. Выбери один маршрут. Кратко сообщи пользователю, какой гайд используешь и есть ли существенный пробел для его задачи.
2. Прочитай входную инструкцию, границы и только нужные разделы. В длинном файле сначала просмотри заголовки, затем извлеки выбранные разделы. Не загружай все продукты, исследования и изображения сразу.
3. Применяй правила с учётом их статуса. Наблюдение о существующей странице не превращается в обязательное требование. Не выдавай своё решение за подтверждённый паттерн.
4. Для внешнего вида используй доступные токены, CSS и спецификации выбранного пакета. Учитывай стек проекта; пример HTML/CSS сам по себе не является готовой библиотекой React/Vue-компонентов. Для Карьеры соблюдай отдельный контракт разметки.
5. Открывай витрину или отдельный скриншот, когда нужно понять композицию, неоднозначную деталь или проверить сходство. Скриншоты не обязательны для первоначального выбора маршрута и не загружаются пакетом.
6. Перед завершением проверь результат по относящимся к задаче правилам и доступным проверкам пакета. Назови допущения там, где гайд не покрывает сценарий.

Если файлы недоступны, попроси доступ или локальную копию; не утверждай, что прочитал их. Ссылка сама по себе не гарантирует, что ИИ может открыть приватный репозиторий. При чтении через GitHub переходи к содержимому файлов; при наличии клона используй локальные пути. Не обходи ограничения вложенных инструкций.

## Примеры и устройство репозитория

Состав публикации: [что отправляем в GitHub и что оставляем локально](PUBLICATION.md).

- Карьера: [компоненты](career/showcase/components.html), [страницы](career/showcase/pages.html).
- Хабр: [компоненты](habr/showcase/components.html), [страницы](habr/showcase/pages.html).

Это HTML-файлы: в интерфейсе репозитория GitHub они показываются как код. Для живого просмотра используй локальный сервер по инструкции пакета; опубликованного сайта эта навигация не предполагает.

Папки продуктов содержат рабочие гайды. Корневые документы 00–08 — исследовательский корпус; для направлений с отдельным пакетом начинай с пакета. Для проверки конкретных правил доступны evidence внутри продуктов.

Авторские папки `.audits/`, `.claude/` и `_sources/` не публикуются. Упоминания и ссылки на них в исследовательских материалах пакетов относятся к внутренним источникам автора. Для создания фичи не нужно искать эти папки или запускать конвейер сборки гайдов. Если необходимое правило не изложено в опубликованных материалах, обозначь пробел, а не предполагай содержимое внутреннего источника.
