# Обновления опубликованного навыка

Постоянный адрес актуальной версии: https://github.com/melpnz/hds/tree/main/skills/habr-design-review
Версия зафиксированного выпуска определяется `release.json`; он содержит SHA-256 публикуемых файлов.

## В начале работы

До ревью выполнить `node "$SKILL_DIR/scripts/check-updates.mjs"`. Нужен Node.js 20+; проверка не требует npm-зависимостей, авторизации GitHub или доступа к истории разговоров. Она делает не более одной попытки в местный календарный день на установленную копию. Общий сетевой таймаут — 6 секунд. `--force` применять только по явной просьбе проверить снова. Состояние хранится вне навыка: `HDS_SKILL_STATE_HOME`, в авторской Windows-среде `D:/.agent/apps/skill-updates`, иначе `$XDG_STATE_HOME/hds/skill-updates` или `~/.local/state/hds/skill-updates`.

- `current`, `unavailable`, `checking`, `cached:true`, отсутствие Node или невозможность запустить команду: продолжить ревью. Не требовать восстановления GitHub/установки инструментов ради проверки обновлений. Не объявлять версию актуальной при `unavailable`.
- `update-available` и `shouldNotify:true`: сообщить установленную и новую версии, кратко перечислить изменения **всех** выпусков между ними из `changes.entries`, дать `changelogUrl` и предложить обновиться. `changes.complete:false` означает, что исходная версия не найдена в истории: обозначить неполноту. При `changes:null` прямо сказать, что список изменений получить не удалось; не выдумывать его.
- До ответа продолжать независимую подготовку. Без согласия на обновление выполнять ревью текущей версией; при отказе продолжить её использование. Решение об установке принимает пользователь конкретной установленной копии, не GitHub и не скрипт проверки.

## После согласия на установку

Это установка официального выпуска, не право изменять авторский код. Скачать целиком `skills/habr-design-review` из коммита `commit`, который вернула проверка; не смешивать файлы `main` из разных моментов времени. Сверить версию, имя и все SHA-256 из `release.json` до изменения установленной копии. Не исполнять скачанные скрипты до проверки.

Сохранить резервную копию установки вне её каталога. Если есть локальные изменения относительно прежнего `release.json`, сообщить о них и не затирать без отдельного решения. Авторскую рабочую копию без `release.json` не подменять: её обновляет Stepan Voevodin как исходник. Заменить только файлы опубликованного пакета; не удалять пользовательские прогоны, секреты, профили браузера, знания, локальные bench и посторонние файлы. При изменении зависимостей выполнить `npm ci` в установленной копии; пользовательские конфиги восстановить отдельно после сверки. Проверить версию, заново прочитать обновлённый SKILL.md и продолжить работу. При ошибке вернуть сохранённую копию.

Новые версии публикует Stepan Voevodin. Потребители присылают ему отчёты и предложения; автоматическая проверка не даёт права редактировать или публиковать навык.
