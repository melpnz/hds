# Детали, геометрия и русский язык

Прочитать при дополнении и чистке автоматических находок. Цель — не терять небольшое подтверждаемое отличие и не выдавать предположение о его причине за факт.

## Геометрия и мелкие детали

`capture` и оба пути выгрузки Figma сохраняют `rawBox` в CSS px рядом с прежним целочисленным `box`. Целые координаты нужны для кропов, дробные — для замера. Снимки без новых полей продолжают работать, но точность нельзя восстановить из округлённых данных.

`match-figma` дополнительно вызывает `detail-audit.mjs`: сравнивает диапазоны стилей текста, односимвольные детали в контексте, внешнюю/внутреннюю ширину сопоставленных блоков и дробную толщину обводки. Эти находки имеют `requiresVisualCheck`; просмотреть увеличенный кадр перед выдачей. В `meta.geometryWarnings` — ограничения сопоставления, старые данные без диапазонов и generated content для ручного просмотра. Не считать предупреждения проверенными автоматически.

Для ширины различать внешний border box, доступную область внутри padding/обводки и рамку текста. У контролов проверить одинаковое содержимое и состояние: hug-кнопка с «22%» и «24%» может иметь разную ширину закономерно. Не назначать fill/max-content по одному размеру. Проверять полные подписи, стрелку, gap, padding, рамку/shadow/outline и ограничения ширины.

Устойчивое отличие 1–2 px на границах контрола или внутреннего блока не выбрасывать только из-за общего допуска ±2 px. Проверить сопоставимые границы и видимые пиксели; контур текста Range и слой Figma не всегда одинаковы. Дробную рамку не округлять до 1 px: записать фактическое значение, DPR, масштаб viewport, CSS zoom/transform; причина может оставаться неизвестной. Не считать одиночную субпиксельную разницу доказанным дефектом без визуальной проверки.

В находке разделять:
- `observation`: что измерено/видно;
- `cause`: `status:"confirmed"` с доказательством либо `status:"unverified"` с гипотезой;
- `fix`: подтверждённое исправление либо то, что нужно уточнить. Не придумывать CSS для заполнения поля.

Неверная гипотеза о причине не отменяет реальное отличие. Если одна обводка объясняет несколько сдвигов дочерних элементов, после проверки объединить их, не плодить находки.

Отдельно просмотреть точки-разделители, линии, рамки, иконки и текст с несколькими стилями. Экспорт сохраняет `textRuns` с диапазонами UTF-16: один серый символ среди чёрных букв — самостоятельное оформление. На сайте смотреть вложенные span и `generated` (::before/::after). Сопоставлять символ по строке/родителю/соседям, не глобально со всеми «•». Цвет символа оценивать по его внутренним пикселям и стилю, не по сглаженному краю. Для старых выгрузок без диапазонов проверить PNG или получить новую выгрузку; совпадение одного общего style.color не доказывает совпадение всей строки.

## Языковой проход

После съёмки и сопоставления выполнить:

```text
node scripts/language-review.mjs <run> init
```

В `<run>/language-review.json` собраны уникальные тексты каждого источника с контекстами разных ширин/состояний. Проверить их самому как агенту: скрипт ведёт учёт, он не является проверкой орфографии. При новых снимках повторить init — прежние решения по неизменённому тексту сохраняются, новые тексты остаются pending.

Проверять русский язык независимо в макете и на сайте: написание слов, согласование, формы после числительных, пропуски/повторы и пунктуацию по контексту. Совпадение ошибочного текста двух источников не делает его правильным. Число и существительное могут быть разными узлами — проверить полную фразу и соседей на кадре/в DOM; дополнить запись контекстом при необходимости. Для длинного, обрезанного или не попавшего в инвентарь текста проверить исходник отдельно и добавить запись с местом. Не переносить орфографию ошибочного макета в правильный сайт.

Статусы:
- `checked` — проверено, замечаний нет; длинное объяснение не требуется;
- `issue` — явная ошибка; заполнить `category` (spelling/agreement/punctuation), `suggestion`, `reason`;
- `question` — спорная формулировка; те же поля, предложение требует решения дизайнера/редактора;
- `not-applicable` — нерусский текст, имя/бренд или другой обоснованный случай; обязательна `reason`.

Не переименовывать бренды и курсы по словарной догадке, не требовать точку у короткой подписи, не считать любое е/ё ошибкой. Редакторский вкус и стилистическая замена не равны нарушению нормы. Не отмечать все записи checked массовой командой без чтения. Проверять один и тот же текст один раз с учётом разных контекстов; не хранить абзац «всё правильно» для каждого повторения.

```text
node scripts/language-review.mjs <run> verify
node scripts/language-review.mjs <run> apply
```

`verify` завершается ошибкой при неразобранных записях; `apply` переносит вопросы/ошибки в findings.json и не трогает findings.auto.json и решения. Ошибка только Figma → «Правки в макет», сайта → основной разбор, обоих → одна связанная запись с `alsoMockup`. Для одинаковой проблемы в разных формулировках задать одинаковый `issueKey`; это не склеивает все разные ошибки в одну. Идентификаторы стабильны. Места и селекторы сохранены в `languageContexts`, без выдуманного парного скриншота. Если приложен языковой ledger, builder показывает покрытие в «Дополнительно»; pending не считается завершённой проверкой. Отсутствие ledger у старого отчёта не означает, что язык был проверен.

## Перед выдачей

У каждой новой находки убедиться в правильной паре, одинаковом состоянии, читаемом доказательстве и корректном адресате. Маленький размер отличия не причина скрывать его; недостаток доказательств — причина пометить вопрос или ограничение. Самопроверка отчёта не должна выставлять решения за дизайнера.
