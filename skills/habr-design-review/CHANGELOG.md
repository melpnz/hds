# История изменений habr-design-review

## 1.7.0 — 2026-11-09

- Добавлена проверка небольших деталей: сохраняются диапазоны стилей внутри текста (включая одиночные символы), цвета/начертания сравниваются по диапазонам. Старые снимки без диапазонов дают ограничение для визуальной проверки, а не ложное подтверждение совпадения. Оба пути выгрузки Figma поддерживают новые данные; capture сохраняет вложенные текстовые фрагменты и generated content.
- Дробные rawBox сохраняются рядом с координатами кропов. Дополнительный проход проверяет внешнюю и внутреннюю ширину сопоставленных контейнеров, числовые подписи контролов и дробную обводку. Для hug учитывается полная подпись; небольшое отличие требует просмотра кадра. Наблюдение и непроверенная причина разделены, предположения не превращаются в CSS-предписания.
- Введён обязательный языковой проход: language-review.mjs собирает уникальные тексты сайта и макета с контекстами, отслеживает неразобранные записи и переносит результаты в отчёт. Орфографию, согласование и пунктуацию проверяет агент; скрипт не подменяет проверку словарной эвристикой. Ошибка только макета попадает в его правки, сайта — в основной разбор, общая ошибка связана одной записью. Подтверждение дизайнером не выставляется автоматически.
- Исправлен просмотр страницы целиком для состояний без макета; недостающий источник показан явно. Selftest больше не ждёт удалённый индикатор прогресса, проверяет переключение всех состояний и не нажимает решения за дизайнера.
- Добавлена справка detail-review.md и регрессии для серого символа внутри строки, числового селекта, внутренней ширины, дробной рамки, маршрутизации языковых ошибок и отчёта без макета.

## 1.6.0 — 2026-11-02

- В начале ревью агент спрашивает, для кого готовится отчёт: «Разработчик», «Дизайнер» или «Иное». Выбор сохраняется в review-config.json и метаданных audience; старые отчёты без настройки работают как прежде.
- Для дизайнера и «иного» прежний сценарий сохранён. Разработчику сразу открывается вкладка «Отчёт» со всеми найденными замечаниями, без ожидания дизайнерских вердиктов. Исправленные пункты, улучшения, механика и правки макета остаются различимыми.
- В отчёте разработчика и его экспорте есть предупреждение о возможной ошибке ИИ и рекомендация обратиться к дизайнеру при сомнениях. Сам показ замечания не ставит «Баг»/«Берём» и не меняет метрики подтверждений.
- Роль передаётся в перепроверку и feedback; явная настройка нового прогона может её переопределить. Неподтверждённые улучшения обозначаются как предположения, для правок макета не создаются выдуманные кадры сайта.

Проверки: браузерные сценарии всех трёх ролей, приоритет настройки, полный список/стартовая вкладка/предупреждение и экспорт, неизменность данных и метрик, наследование роли в перепроверке и регрессии текущего отчёта.

## 1.5.0 — 2026-11-02

- Обновлён визуал отчёта по согласованному превью: компактная шапка «Нейро-Степан: …», короткие ссылки, дата проверки и время сохранения, настройки стороны и темы справа. Название, ссылки и время берутся из данных конкретного ревью.
- «Отчёт» вынесен первым отдельным пунктом, стартовая вкладка остаётся «Не исправлено»/«Расхождения». В отчёт входят подтверждённые баги и принятые улучшения; пустой отчёт предлагает сначала разобрать находки и перейти к ним.
- «Правки в макет» стали отдельной вкладкой. Статистика, качество, «Что проверено», методика и раскрытый по умолчанию «Расход токенов» собраны в «Дополнительно». Пустая вкладка «Совпадает» не показывается.
- Убраны верхний прогресс, дублирующие кнопки формирования отчёта/правок макета, ручного сохранения и выгрузки обучения. Решения записываются в текущий HTML автоматически через локальный сервер; вкладка «Отчёт» сохраняет feedback JSON рядом. Время сохранения подтверждается после успешной записи.
- Фильтры критичности, типа и разрешений — dropdown с множественным выбором и сбросом на «Все…», в одной строке после решений через разделитель. Стрелки выровнены по центру; на узких экранах фильтры переносятся.
- Метаданные карточек — обычный текст через «·», без похожих на кнопки плашек; ширины сгруппированы. Увеличен отступ перед переключателем кадров, убраны легенда «элемент», блок «В Jira» у каждой карточки и лишний вводный текст перепроверки.
- Записи сервера упорядочены, при временной блокировке файла Windows выполняются ограниченные повторы атомарного переименования; одинаковые решения не переписывают HTML. Windows launcher запускает сервер скрыто. Автономный HTML остаётся доступен для просмотра, файловое сохранение требует сервера.

Проверки: основной набор, перепроверка, workspace, обновления, браузерные регрессии и новый report-ui-test. Проверены универсальная шапка и несколько страниц, фильтры, пустой отчёт, вкладки, запись решений в HTML/JSON, восстановление после перезагрузки и формирование feedback.

## 1.4.0 — 2026-10-30

- Первый публичный пакет в `melpnz/hds`, постоянный путь `skills/habr-design-review`, метаданные источника и manifest файлов с SHA-256. Локальные эталоны, история ревью, секреты и установленные зависимости в публикацию не входят.
- Перед первым ревью за местный календарный день выполняется короткая проверка GitHub без npm-зависимостей. При недоступности сети или отсутствии обновления работа продолжается; при новой версии агент показывает изменения всех пропущенных выпусков по changelog и предлагает установку.
- Обновление устанавливается только с согласия пользователя копии, из одного зафиксированного коммита с проверкой файлов и резервной копией. Право изменять официальный исходник остаётся у Stepan Voevodin; авторская рабочая копия не подменяется.
- Каталог и инструменты публикации допускают соседние независимые скиллы. Добавлены проверки ежедневного кэша, смены дня и версии, недоступности/таймаута сети и диапазона changelog.
- Перед первой публикацией Playwright обновлён до исправленной версии 1.55.1; lock-файл зависимостей синхронизирован, npm audit не сообщает известных уязвимостей.

## 1.3.0 — 2026-10-30

- Улучшения с решением «Берём» включаются в основной отчёт и экспорт с конкретным комментарием дизайнера. Отсутствие макета явно сохраняется; экспорт использует один настоящий кадр сайта, метрики багов не меняются.
- Принятое улучшение переносится в следующую перепроверку вместе с авторством и согласованным заданием. Требуемое состояние не заменяется стартовым снимком.
- Перепроверки по умолчанию создаются внутри одной задачи в `rechecks/NN`. Указатель переключается только после сборки готового отчёта; корневой запуск открывает последнюю версию, исходное ревью доступно отдельно. Порт локального отчёта сохраняется при переносе.

Проверки: основной набор тестов, перепроверка локальной страницы, браузерные проверки принятого улучшения и экспорта, вложенные версии и перенос согласованного задания.

## 1.2.0 — 2026-10-30

- Снятые состояния без макета (ошибки, пустые экраны и другие) включаются в план и требуют самостоятельной визуальной проверки, а не пропускаются из-за отсутствия Figma-фрейма.
- Для предположений добавлены признаки `basis: visual-heuristic` и `referenceStatus: missing`: предложения находятся в «Улучшениях», явно обозначают отсутствие макета и не выдаются за подтверждённое расхождение.
- В карточке без макета показывается один кадр сайта с пояснением; режимы наложения и сравнения не предлагаются.
- В feedback и разметке для обучения сохраняются основание предположения и его авторство. Дизайнерское предложение по улучшению не превращается автоматически в пропущенный подтверждённый баг.
- В ревью AI-поиска добавлена IMP-01 по замечанию Stepan Voevodin: тесная компоновка текста ошибки и кнопки «Повторить» на 320 px. Это предложение для обсуждения; существующие решения дизайнера сохранены.

Проверки: существующие тесты и расширенные регрессии прошли; проверены односторонняя карточка, отсутствие ложного увеличения числа пропущенных багов и сохранение гипотез в feedback/labels. Карточка IMP-01 просмотрена в браузере, ошибок JS нет; метрики подтверждённых багов и решения дизайнера сохранились.

## 1.1.0 — 2026-10-30

- Добавлен план всех состояний `state-plan.json`: отсутствующие и недостигнутые состояния требуют уточнения у пользователя, сохраняются в покрытии отчёта и не заменяются стартовым экраном. Настоящие фрагменты связываются с подходящим снимком явно. План сохраняется при приёме feedback и регрессионной проверке.
- Для изображений capture сохраняет исходные размеры и `object-fit/object-position`. Добавлен журнал визуальной проверки `image-audit.json`: масштаб и кадрирование внутри маски проверяются отдельно от контейнера; совпадение изображения не объявляется автоматически по размерам файла.
- Сопоставитель больше не предлагает отрицательный padding. В инструкциях закреплена проверка переносов и правил адаптива до предложения CSS, с явной областью применения исправления.
- Для измерения зазора добавлен `evidence.measurement`: обе границы попадают в кроп, промежуток выделяется и подписывается. Padding родителя не рисуется от рамки другого элемента.
- Добавлен журнал `token-usage.json` по этапам с контрольными точками Codex/Claude или фактическими показателями из указанного источника. В HTML и feedback показываются вход, выход, кэш, источник и неполнота учёта; недоступные и незарегистрированные этапы не считаются нулём. В разметку для обучения сохраняются этапы и измеренная сумма, для многостраничного прогона расход не дублируется в истории каждой страницы.
- В отчёт и feedback добавлен номер выпуска навыка вместе с прежним хешем кода.

Проверки: существующий набор тестов, новые проверки счётчиков/состояний/изображений/разметки/feedback и локальная браузерная съёмка прошли. На 11 эталонах все подтверждённые находки сохранены, полнота 100%. На сохранённом AI-поиске 13 → 8 черновых карточек за счёт пяти подтверждённых ложных сравнений; исходные решения и отчёт прогона не переписывались. HTML просмотрен, ошибок JS нет. Старым этапам расход задним числом не приписывается.
