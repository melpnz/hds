# Роадмап Courses UI

Актуализировано: 23 сентября 2026 года.

Цель — последовательно довести библиотеку до состояния, в котором составные элементы переиспользуют общие примитивы, а визуальные параметры управляются семантическими токенами. Работа ведётся по одному пункту: отдельная правка, проверка на витрине, автоматические проверки, затем отдельный коммит.

## Правила работы

- Не объединять компоненты только из-за внешнего сходства, если у них различаются семантика или ARIA-поведение.
- Не переопределять внутреннее устройство дочернего компонента через селекторы по тегам и `:deep()`, если задачу можно решить вариантом или параметром компонента.
- Для цветов, типографики, размеров и скруглений использовать токены соответствующей категории.
- Не считать пункт завершённым до визуальной проверки на 320, 480, 768 и 1024 px и прохождения применимых автоматических проверок.

## Этап 3. Защитные проверки

- [x] Расширить `check:tokens`: проверять CSS компонентов, базовые стили `courses.css` вне `:root`, inline styles и Tailwind arbitrary values. Для динамических inline-значений добавлен узкий документированный allowlist с проверкой устаревших исключений.
- [x] Запрещать прямые `px/rem` там, где это не документированное исключение; viewport-границы остаются зоной ответственности отдельного `check:breakpoints`.
- [x] Выявлять `calc(var(--crs-unit) * N)`, если для значения уже существует именованный токен.
- [x] Выявлять использование токена неправильной категории: `space` для радиуса или типографики.
- [x] Расширить `check:composition` за пределы ручного списка: автоматически анализировать все компонентные зависимости, неизвестные теги, циклы и повторную реализацию базовых контролов через нативные `button/input/textarea/select/a/svg`. Ключевые архитектурные связи дополнительно защищены строгими контрактами, а допустимые владельцы нативной семантики документированы и проверяются на устаревание.
- [x] Полностью устранить переопределения дочерних компонентов: в библиотеке осталось `0 :deep()` и `0` селекторов внутренних интерактивных тегов. `check:composition` запрещает повторное появление таких связей, а примитивы могут стилизовать только собственные нативные контролы.
- [x] Добавить визуальные регрессионные снимки ключевых вариантов на 320, 480, 768 и 1024 px: 24 эталона для `Button`, `CourseCard`, `SiteHeader`, `CatalogMenu`, `Modal` и `FilterModal`, отдельные команды проверки и осознанного обновления снимков.

## Текущий статус аудита

- Цвета в стилях Vue-компонентов централизованы; прямых `hex/rgb/rgba` не найдено.
- Использование spacing-токенов для радиусов и типографики устранено и защищено автоматической проверкой.
- Viewport-границы сведены к 480, 768 и 1024 px и защищены проверкой `check:breakpoints`; раскладки проверены в браузере на 320, 480, 768 и 1024 px без ошибок и горизонтального переполнения.
- Проверка композиции автоматически охватывает все 74 компонента и 115 внутренних зависимостей; 29 ключевых составных компонентов дополнительно защищены обязательными архитектурными контрактами.
- Границы компонентов жёстко защищены: `check:composition` не содержит allowlist для `:deep()` и селекторов внутренних интерактивных тегов и останавливает проверку при первом новом нарушении.
- Проверка токенов контролирует CSS компонентов и базовые стили вне `:root`: цвета, прямые `px/rem`, семейство шрифта, категории радиусов/типографики/размеров, длительности loader, высокие `z-index` и заменяемые вычисления через `--crs-unit`. Inline styles и Tailwind arbitrary values также защищены, а допустимые динамические значения явно документированы.
- Визуальная регрессия фиксирует шесть ключевых поверхностей на четырёх контрольных ширинах; все 24 эталона повторно проходят сравнение без обновления снимков.
