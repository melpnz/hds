# Roadmap — Хабр Курсы v1.1

Актуализировано: 5 октября 2026 года.
Сводная очередь — [Courses общего roadmap](../ROADMAP.md#courses).

## Текущий статус

Используем UI Kit владельца — Courses Nuxt Kit; переход на другую frontend-
библиотеку не планируется. Опубликованная версия — **1.3.1**, гайд — **v1.1**.
Релиз опубликован 05.10.2026 после успешного CI точного тега.
HeaderDropdown, визуальные тесты и исправления SortSheet, FilterChip, OptionList
и API фильтров SiteHeader входят в 1.2.0; guide/provider API синхронизирован.

72 прямых соответствия, 72 provider-primary, 0 hybrid и 0 отсутствующих состояний.
Все 147 provider-токенов сопоставлены без конфликтов значений.

## Решения владельца · 01.10.2026

- Рабочая палитра берётся из используемых цветов UI Kit. Генерируемый
  `machine/reports/provider-color-usage.json` различает используемые и резервные
  CSS-токены; Figma-группы больше не требуют отдельного решения перед разработкой.
  Исторические токены сохранены для совместимости.
- Visual regression расширена: 20 поверхностей/состояний × 4 ширины =
  80 сценариев и 160 эталонов (цвет + геометрия). Старые 48 эталонов сохранены.
- По следующему решению владельца выполнен production-анализ двенадцати страниц:
  семь ширин, отдельные граничные замеры, локальные reference и правила композиции.
  Figma-сверка и точные component-сборки через kit не входят в этот срез.
- Следующий этап согласован как план: сначала доработать UI Kit по выявленным
  расхождениям, затем собрать 12 страниц из его настоящих Vue/Nuxt-компонентов.
  Старые рецепты использовать как основу структуры, новые замеры — как источник
  актуальной геометрии. Само включение в план не разрешает новые exports и варианты.
- Другая frontend-библиотека не ожидается: продолжаем развивать этот UI Kit.
- Выпуск согласован и автоматизирован через ручной GitHub Actions workflow:
  проверки точного коммита тега → ZIP слоя и каталога + SHA-256 → черновик.
  Публикация остаётся ручной; инструкция — `../tools/README-courses-release.md`.

### Точка продолжения · 02.10.2026

Все 12 исследованных production-страниц собраны вне layer как живые Vue/Nuxt-композиции
из публичных компонентов Courses UI Kit. В основном гайде они стали первичными превью;
локальные production-reference сохранены второй вкладкой для сравнения. Каталог страниц
поддерживает 320 / 480 / 768 / 1024 / Auto, а статическая сборка явно prerender-ит все
двенадцать маршрутов.

Закрыто и проверено:

1. Guide/provider-контракты, токены, manifest и machine-данные синхронизированы:
   72 прямых соответствия, 147 сопоставленных токенов, 0 конфликтов.
2. Все 12 страниц проходят браузерную проверку на 320 / 480 / 768 / 1024 / 1440
   без горизонтального переполнения; интегрированный viewer проверяет обе вкладки
   и загрузку живой композиции.
3. Найденные сборкой страниц ошибки фиксированной ширины `PromoCard` и `PersonCard`
   исправлены в ките. Карусель больше не использует устаревший экземпляр Swiper при
   пересоздании; тест явно ждёт завершения смены loop-режима и стабилен в 10 повторах.
4. `typecheck`, kit checks, guide validation, consumer build, component-page tests,
   visual regression и статическая генерация прошли. Все 12 HTML-маршрутов присутствуют
   в `.output/public`.
5. Все 12 live/reference пар вручную сопоставлены на 320 / 480 / 768 / 1024 / 1440.
   Исправлены составные формы и подписи рейтинга, отзывов и промокодов, выбранная
   организация и мобильная сводка промокодов, а также композиции экспертов и редакции.
   Найденный при этом конфликт CSS у двух полей `SearchForm` исправлен в самом UI Kit
   и закрыт регрессионным browser-тестом.

## Новые сервисы · очередь решений после аудита 05.10.2026

Основание — аудит внешнего прототипа «Хабр Репититор» на localhost:3000:
15 экранов, исходники и сохранённые desktop/mobile-снимки. Это не новая ручная
приёмка в живом браузере и не production evidence. Приложение не изменялось.
Принятые 12 страниц Курсов остаются принятыми; очередь ниже относится к
расширению гайда для новых сценариев, а не повторному открытию их приёмки.

Без новых дизайнерских решений выполнено: актуализированы границы покрытия,
уточнено разрешение проектировать явно заказанные новые сценарии вне layer;
добавлены карта переиспользования, минимальный контракт композиции, матрица
состояний и правила проверки открытых overlay, клавиатуры и восстановления.
Процедура связана с AGENTS, машинным индексом и consumer-workflow.
Полная проверка `npm run validate` и `git diff --check` проходят; provider,
его релизные архивы, production-замеры и приложение прототипа не изменены.

Разбирать с владельцем последовательно. Правила NS-01 согласованы ниже;
NS-02: правило фильтрации и вариант редакции согласованы, прочие примеры открыты;
NS-03: порядок согласования композиции и сохранение mobile-контента приняты;
NS-04: готовые состояния Kit и согласование непокрытой композиции приняты;
Вопросы по правилам NS-01–04 закрыты; детали новых экранов согласуются внутри
их продуктовых задач, не требуют отдельной универсальной спецификации сейчас.
NS-05 проверяется при повторном запуске исходной задачи по решению владельца:
отдельную тестовую страницу не создавать. Реализация и визуальная проверка
новых вариантов не считаются завершёнными только по записи решения.

1. **NS-01 — оболочка нового сервиса внутри Курсов: правила согласованы 05.10.2026.**
   Общие шапка и футер сохраняются; примыкающий синий hero имеет единый градиент
   с шапкой. На обычных страницах используется простая шапка сайта, H1 — на
   общем белом фоне; hero возможен по ситуации, не автоматическая светлая панель.
   Новую навигацию агент предлагает вариантами и ждёт выбора пользователя,
   а не добавляет второй уровень самостоятельно. Для «Репетитора» предпочтение
   владельца — аватарка в общей шапке и dropdown разделов, не универсальный канон.
   Записано в `docs/decisions/unknowns.md` и consumer-workflow. Для конкретной
   реализации ещё нужны состав меню, гостевой/mobile-вариант, проверка API и
   desktop/mobile-пример; недостающий API дорабатывается отдельной задачей Kit.
2. **NS-02 — вкладки и фильтрация: правило принято 05.10.2026.**
   Для фильтрации используются чипсы, не табы, независимо от ширины. На `/editor`
   принят dropdown выбора статуса с чипсом-триггером на всех разрешениях;
   отдельный desktop-ряд не нужен. Сначала различать переход, переключение
   содержимого, выбор в форме и фильтрацию. Проверить публичный API
   FilterChip/dropdown и доступность, подпись и выбор/сброс брать из контракта;
   неподдержанные варианты уточнять отдельно. Реализация не выполнена этим
   обсуждением. Страница состояний и 10px-навигация остаются
   отдельными примерами, не согласованными автоматически. Результат: принятые
   правила и проверка 320/375/480/767/768 с длинными текстами.
3. **NS-03 — согласование композиции: правило принято 05.10.2026.**
   Вместо обязательных универсальных шаблонов: для аналогов использовать
   существующие композиции; для новых сценариев сначала предлагать блоки,
   порядок и расположение. Существенно разные варианты показывать пользователю
   с рекомендацией и ждать выбора до реализации, затем собирать из Kit без
   дублирования покрытых элементов. Предложение включает desktop/mobile:
   содержательные блоки не удаляются молча. «15 минут для себя» на `/training`
   должно сохраняться на mobile; перенос или изменение оформления допустимы.
   Скрытие требует подтверждённого адресного контракта или отдельного согласования.
   Записано в инструкции и consumer-workflow; проверочный прототип не менять.
   Проверку действия этих правил выполнить в NS-05; новые recipes/exports
   автоматически не создаются и не считаются принятыми.
4. **NS-04 — композиция состояний: правило принято 05.10.2026.**
   Загрузка, пустой результат, ошибка и успех используют готовые компоненты
   и состояния Kit без нового визуального стиля. Подтверждённый случай следует
   существующему контракту; непокрытые размещение/поведение нового сценария
   сначала предлагаются пользователю и согласуются. Записано в инструкции
   и consumer-workflow. Это не новая приёмка визуальных примеров или backend:
   проверить выбранные композиции в контрольной сборке NS-05.
5. **NS-05 — повторный запуск исходной задачи пользователем.** Владелец заново
   поручит агенту задачу с актуальным гайдом; отдельная тестовая страница не нужна.
   Этот агент не изменяет исходный проверочный прототип. В повторном запуске
   проверить, что исполнитель читает обновлённые AGENTS/consumer-workflow,
   согласует новую композицию до сборки, использует Kit и сохраняет mobile-контент.
   Затем проверить результат в браузере на desktop/mobile и основные состояния.
   Отчёт разделяет нарушение правила, пробел гайда и новый продуктовый вопрос.
   Пока повторный запуск не выполнен, не объявлять эффективность новых правил
   подтверждённой практикой; обновление инструкций не блокируется этим этапом.

Отдельный backlog самого прототипа, не задачи изменения гайда: неправильный
active на несвязанных маршрутах, гостевой «Выход», fallback неизвестного URL,
разные реализации проверки ответа, самодельные Link/Toast и неполный снимок
модалки. Исправлять приложение только по отдельной задаче его владельца.

## Границы ответственности

Machine-гайд хранит назначение, поведение, доступность и композицию;
UI Kit — публичный API, разметку, токены, ассеты и визуал.
Production и Figma — evidence, не параллельная реализация.
Копии layers/courses в продуктах остаются read-only и не обновляются автоматически.
