# Состояния компонентов · Курсы

Закрытый словарь состояний, правило, по которому определяется, какие состояния
обязательны у записи реестра, и разметка всех 55 записей
[`manifest.json`](manifest.json) → `requiredStates`. Метод — `.claude/guide/METHOD.md`
§5; реестр и его поля — [`INDEX.md`](INDEX.md); форма спецификации —
[`SPEC-TEMPLATE.md`](SPEC-TEMPLATE.md). Шаг роадмапа — R1-01.

Этот документ не «состояния, которые сняты» (это R1-02 и дальше, шаг за шагом
на вёрстке каждого элемента) — а «состояния, которые применимы к элементу
по его природе», то есть по тому, что о нём уже известно из принятого реестра
и снятой разметки десяти страниц. Применимость и снятость — разные вопросы;
путать их значит не отличать «у кнопки нет loading» от «мы не проверяли,
грузится ли кнопка».

## 1. Закрытый словарь (METHOD §5, дословно)

Ровно двадцать имён. Ни одно не добавляется и не переименовывается —
список сверяется `tools/validate-components.mjs` с `manifest.json` →
`allowedStates`, а тот — с самим METHOD.md.

`default` · `hover` · `focus-visible` · `pressed` · `selected` · `current` ·
`checked` · `indeterminate` · `expanded` · `collapsed` · `open` · `closed` ·
`disabled` · `readOnly` · `loading` · `invalid` · `error` · `success` ·
`empty` · `dragActive`

### Запрещённые слова

`active`, `focus`, `select`, `inactive` — запрещены как неоднозначные
(METHOD §5). Ни одно из них не встречается ни в этом документе, ни
в `requiredStates` манифеста; это exit criteria волны R1 и проверяется
механически (`grep` по названиям состояний в `manifest.json` и в разделах
«Состояния» спецификаций, `tools/validate-components.mjs`). Замены:

| Запрещено | В проде звучит как | Каноническое имя |
|---|---|---|
| `active` | `router-link-active`, `swiper-slide-active`, «активная вкладка» | `current` (маршрут/слайд) или `selected` (выбор из набора), по контексту — см. §4 |
| `focus` | «в фокусе» без уточнения модальности | `focus-visible` — единственная форма фокуса, которую фиксирует пакет |
| `select` | «выбрать», `is-selected` | `selected` |
| `inactive` | «неактивна» | `disabled`, если элемент недоступен для взаимодействия; `default`, если это просто не текущий/не выбранный вариант |

### Что означает каждое слово здесь

Определения — общее значение термина (не «как реализовано в Курсах»); частные
случаи и evidence — в §4.

| Состояние | Когда используется | Типичный DOM/API |
|---|---|---|
| `default` | обычный вид вне прочих состояний. Требуется у каждой записи реестра без исключения — это её базовое появление, зафиксированное хотя бы одним evidence (прод, Storybook или Figma) | отсутствие прочих state-классов/атрибутов |
| `hover` | указатель над целью | `:hover`, утилита `hover:*` |
| `focus-visible` | видимый фокус с клавиатуры | `:focus-visible`, утилита `focus-visible:*` |
| `pressed` | цель нажата прямо сейчас | `:active` в смысле «зажато», `aria-pressed` для toggle-кнопки |
| `selected` | выбран один вариант из набора (фильтр, вкладка, плитка) | `aria-selected`, модификатор `is-selected`/собственный класс |
| `current` | указывает на текущий маршрут, страницу или активный элемент карусели/списка | `aria-current`, `router-link-active`, `swiper-slide-active` |
| `checked` | отмечен чекбокс, radio или switch | `checked`, `aria-checked` |
| `indeterminate` | чекбокс частично отмечен (не весь список выбран) | DOM `indeterminate`, `aria-checked="mixed"` |
| `expanded` | раскрыт подраздел содержимого **в потоке страницы**, без выхода в отдельный слой | `aria-expanded="true"` |
| `collapsed` | тот же подраздел свёрнут | `aria-expanded="false"`, `max-h` с `overflow-hidden` |
| `open` | открыт оверлей — модалка, дропдаун, поповер, — вынесенный из потока | `open`, `aria-expanded` на триггере, отсутствие класса `hidden` на панели |
| `closed` | тот же оверлей закрыт | класс `hidden`, отсутствие узла в DOM |
| `disabled` | элемент недоступен для взаимодействия | нативный `disabled`, `disabled:*`-утилиты |
| `readOnly` | значение доступно для чтения и фокуса, но не для изменения | `readonly` |
| `loading` | выполняется операция | `aria-busy`, класс `is-loading` |
| `invalid` | значение не прошло валидацию | `aria-invalid`, `:invalid` |
| `error` | операция или запрос завершились ошибкой | доменное состояние + обратная связь |
| `success` | операция завершена успешно | доменное состояние + обратная связь |
| `empty` | коллекция, результат или единичное значение не содержит данных | доменное состояние; для единичного значения — плейсхолдер вместо реального изображения/текста |
| `dragActive` | перетаскиваемый объект находится над целью | drag-события |

`expanded`/`collapsed` и `open`/`closed` — разные пары нарочно: первая про
содержимое, оставшееся в потоке страницы (раскрывающийся список ссылок),
вторая — про слой, вынесенный поверх страницы (модалка, дропдаун). Реестр
Курсов даёт для этого прямое разграничение: `LinkGrid` раскрывается на месте
(`overflow-hidden`/`max-h-[94px]`, без absolute-позиционирования) → пара
`expanded`/`collapsed`; `HeaderDropdown`, `FilterModal`, `CatalogMenu`,
`Select`, `MultiSelect` — панель вынесена (`absolute`/модалка) → пара
`open`/`closed`.

## 2. Как определяется требуемость

`kind` (METHOD §5: `primitive` · `component` · `module` · `adapter`) сам по
себе не разделяет интерактивные и статичные записи: в реестре Курсов
`kind: primitive` покрывает и `Link` (867 вхождений, `<a>`), и `SpriteIcon`
(611 вхождений, декоративный `<svg>` без своего поведения); `kind: component`
покрывает и `Button`, и `Prose` (текстовый блок без единого состояния). Матрица
«только по `kind`» в §3 поэтому даёт не список обязательных состояний,
а **потолок и пол**: что структурно исключено для вида целиком и что для него
в принципе возможно. Кто из возможного обязателен — решает природа конкретной
записи, проверяемая по восьми сигналам ниже. Это и есть развёртка требования
задания «по природе, не по кинду»: `kind` держит форму документа (одна
таблица на объявленный словарь видов METHOD), сигналы — источник каждого
факта.

Каждый сигнал — проверяемый факт, взятый из `productionEvidence[].selector`,
поля `notes` записи `manifest.json` (обе колонки приняты фактом на этом шаге —
BRIEF/METHOD этого требуют для manifest.json, в отличие от `inventory.json`)
или из прямого запроса по `evidence/source/production/pages/*/dom.html`
(команды и числа — §4, начало каждой группы). Отрицательный сигнал — тоже
факт, а не умолчание: «нет своего узла-ссылки» так же проверяем, как «есть».

| № | Сигнал | Вопрос | Что открывает |
|---|---|---|---|
| N1 | интерактивность | Корневой узел записи (или неотделимый от неё оверлейный узел без своей записи в реестре) — `<a href>`, `<button>`, `<input>` или иначе фокусируемый по нативной семантике? | `hover`, `focus-visible` |
| N2 | собственный «корпус» | У интерактивной поверхности есть свой фон/рамка/паддинг — плоскость, которую нажатие может визуально осадить? Голая строка текста таким корпусом не считается | `pressed` (только вместе с N1) |
| N3 | отключаемость | Есть нативный способ его отключить (атрибут `disabled`) или структурная граница (первый/последний элемент списка, которую платформа блокирует)? | `disabled` |
| N4 | членство в выборе | Запись — один из взаимоисключающих или независимо переключаемых вариантов набора? | `selected` / `current` / `checked` / `indeterminate`, конкретное слово — по механике выбора (см. §4) |
| N5 | раскрытие содержимого своего узла | Корневой узел записи сам показывает/прячет свою же подструктуру? | `expanded`/`collapsed` (в потоке) или `open`/`closed` (слой поверх) — какая пара, см. правило в §1 |
| N6 | значение и его проверка | Запись — поле формы, чьё значение может не пройти валидацию, быть заблокировано для правки или быть в процессе отправки? | `invalid`, `readOnly`, `loading`, `success` |
| N7 | коллекция с нулевым случаем | Запись рендерит список переменной длины, зависящий от пользовательской фильтрации, то есть способный дойти до нуля? | `empty` (как «результат пуст») |
| N8 | подстановка вместо данных | Запись подставляет плейсхолдер, когда настоящего изображения/текста нет? | `empty` (как «значения нет», отдельное основание от N7 — таблица §4 их не путает) |

`default` не выведен ни из одного сигнала — он обязателен у всех 55 записей
без исключения (METHOD-конвенция и §1 выше): это не состояние-триггер,
а утверждение «у записи вообще есть базовый вид», подтверждённое тем, что
у каждой записи реестра есть хотя бы один evidence (`productionEvidence`,
`storybookEvidence` или `figmaEvidence` — все три пустыми одновременно быть
не могут, это проверяет `validate-components.mjs`).

Правило про модули — отдельно, потому что модуль **составной**: он не
получает состояния своих зависимостей повторно. `CourseCard` не наследует
`disabled` от вложенного `Button` — это состояние Button, документированное
в его собственной записи; `CourseCard` получает состояние только там, где
меняется его **собственный корневой узел** (весь ли он превращён в ссылку,
раскрывается ли он сам, зависит ли его собственный счётчик отображаемых
элементов от фильтра). Без этого правила составной реестр из 28 модулей
задвоил бы десятки состояний вложенных Button, Link и Chip — противоречие
инварианту METHOD §6.6 «две проекции не расходятся» здесь же, внутри одной
проекции.

## 3. Матрица по видам (METHOD §5: `primitive` · `component` · `module` · `adapter`)

Обозначения: **R** — обязательно у каждой записи вида (не зависит от природы);
**C** — обязательно только при выполнении сигнала из §2, сигнал назван;
**—** — структурно исключено для вида целиком, ни у одной записи такого вида
это состояние не бывает обязательным.

Как читать прочерки (структурные, не «на глаз»):

- **`primitive` не бывает `selected`/`current`/`checked`/`indeterminate`/
  `expanded`/`collapsed`/`open`/`closed`/`disabled`/`readOnly`/`loading`/
  `invalid`/`error`/`success`/`dragActive`.** Ни у одной из 11 примитивов
  реестра нет собственной подструктуры, которую можно раскрыть или закрыть
  (примитив — лист дерева, не контейнер), и ни один не является полем формы
  или элементом набора с выбором — эти роли в реестре Курсов начинаются
  с `kind: component` (`FilterChip`, `Checkbox`, `Select`…). Если в будущем
  волну продукта пополнит примитив-переключатель — это меняет матрицу,
  а не разметку конкретной записи в обход неё.
- **`component` не бывает `expanded`/`collapsed`.** Ни один из 16
  зарегистрированных компонентов не раскрывает контент в потоке страницы —
  раскрытие в реестре Курсов устроено только через оверлей (`open`/`closed`:
  `Select`, `MultiSelect`) либо принадлежит модулю (`LinkGrid`). Компонент
  может быть носителем самого выбора (`selected`/`checked`), но не
  раскрывающимся контейнером.
- **`module` не бывает `selected`/`checked`/`indeterminate`/`disabled`/
  `readOnly`/`invalid`.** Эти четыре состояния принадлежат отдельному
  переключаемому элементу или полю формы — ролям, которые в реестре Курсов
  живут на уровне `component` (сам `FilterChip`, сам `Checkbox`). Модуль их
  агрегирует (панель фильтров держит несколько `FilterChip`), но выбор
  остаётся состоянием чипа, а не панели — иначе, отмечая `FilterBar`
  состоянием `selected`, пришлось бы каждый раз называть, какой из
  вложенных чипов выбран, то есть дублировать состояние чипа его
  контейнером.
- **`adapter` — 0 из 55 записей реестра.** Ни одна текущая запись не имеет
  `kind: adapter` (проверено: `manifest.components.filter(c => c.kind ===
  "adapter").length === 0`), хотя вид объявлен в METHOD §5 и в
  `manifest.json` → `allowedKinds`. Строка матрицы — не наблюдение (наблюдать
  не над чем), а контракт на будущее: адаптер — обёртка над сторонним
  виджетом, включённая в визуальный язык продукта без того, чтобы продукт
  сам её стилизовал (ближайшие кандидаты по устройству — `Carousel`,
  обёртывающий Swiper, и рекламный контур `AdSlot`/`AdCard` поверх AdFox, —
  оба сегодня заведены как `module`; менять их `kind` не входит в объём этого
  шага, значит и подтвердить строку `adapter` фактом реестра сейчас нечем).
  Столбец построен так же, как для `component`, с одним отличием: `error`
  обязателен там, где сторонний виджет может не загрузиться (в отличие от
  наших компонентов, отказ здесь — не наша логика, а сеть/скрипт третьей
  стороны), поэтому именно `adapter`, а не `component`, — единственный вид
  матрицы со столбцом `error`.

## 4. Разметка 55 записей реестра

По одной строке на запись; порядок — как в `manifest.json`. `requiredStates`
проставлен туда же, здесь — то же самое плюс обоснование. Слово в скобках
после состояния — какой сигнал (§2) его открыл; для `default` сигнал не
называется (см. правило выше).

### 4.1 Числа корпуса, на которые опирается разметка ниже

Посчитано по `evidence/source/production/pages/*/dom.html` (10 файлов,
снято на 1440 — сноска `countingRule` в `manifest.json`):

Ноль по `aria-expanded`/`aria-selected`/`aria-checked`/`readonly`/`aria-invalid`
— не «не проверяли»: команда выполнена, число посчитано, оно и есть факт.
Означает это не «состояний нет по природе» (не путать с §2), а что раскрытие,
выбор чекбоксом, чтение-без-правки и невалидность нигде в десяти снятых
страницах не помечены ARIA/атрибутом — сама возможность состояния (когда она
есть) выводится из вида элемента и конвенции платформы (METHOD §3 п. 1,
которым фронтенд-паттерн стоит выше продакшен-поведения), а его фактическая
съёмка — предмет R1-02 и спецификаций.

### 4.2 Примитивы (`kind: primitive`, 11 записей)

| id | `requiredStates` | Обоснование |
|---|---|---|
| `sprite-icon` | `default` | `<svg class="svg-icon">`, всегда вложен в другой узел (611 вхождений — во всех ролях, от рейтинга до кнопки); сам не является ни `<a>`, ни `<button>` → N1 не выполнен, дальше по цепочке ничего не открывается |
| `social-icon` | `default`, `hover` (N1), `focus-visible` (N1) | сам является узлом `footer a.block.rounded-full` — интерактивен без обёртки; своего фона/рамки, годного под «нажатие», нет (24×24 иконка без чипа) → N2 не выполнен, `pressed` не открыт |

## 5. Слова словаря, не встретившиеся ни у одной из 55 записей

`success`, `error`, `loading`, `dragActive` не входят в `requiredStates` ни
одной записи реестра Курсов. Это не пробел разметки, а честный итог: в
реестре нет ни одного компонента обратной связи об операции (тост,
уведомление, индикатор отправки формы) и ни одного drag-and-drop элемента —
проверено по корпусу (`loading`/`spinner`/`skeleton`/`aria-busy` — 0
вхождений, §4.1) и по составу самого реестра (55 записей, ни одна не
относится к категории `feedback`, кроме `EmptyState`, у которого своя
причина не иметь `empty` — см. 4.4). Слова остаются в словаре METHOD §5 —
они общий контракт конвейера, не настройка конкретного пакета, и будущая
запись (например, если продукт заведёт форму обратной связи) получит их
тем же механизмом §2, без изменения словаря.
