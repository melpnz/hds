# Контракт для модели · Хабр Курсы

Этот пакет описывает публичную часть Курсов так, чтобы по нему можно было
собрать новый экран, не открывая продукт. Человек читает `docs/guide/*.md`,
модель — `machine/*.json`. Это одна и та же правда в двух проекциях;
расходятся они только по ошибке, и такую ошибку ловит
`node tools/validate-machine.mjs`.

## Порядок чтения

1. `machine/index.json` — что за продукт, где что лежит, чем проверяется,
   где кончается покрытие.
2. `machine/patterns.json` — паттерн страницы: каркас, состав колонки по
   блокам, поведение на 1024, 768 и 375.
3. `machine/components.json` — записи: разметка, состояния, зависимости,
   адрес в продакшене и в Figma.
4. `machine/tokens.json` — значения.
5. `machine/rules.json` — правила уровня страницы (`kind: "rule"`) и решения
   (`kind: "decision-guide"`).
6. `machine/content.json` — форматы чисел и подписи кнопок.

Файлы вне этого списка модели не нужны; markdown из `humanDocs` читается
только тогда, когда нужно понять, откуда взялось число.

## Как собирать экран

1. Выберите паттерн по семейству страницы: листинг, таблица, сущность,
   промо-раздел, профиль. Нет подходящего — скажите об этом прямо, а не
   придумывайте шестое семейство.
2. Возьмите каркас паттерна: контейнер 1124 с полями 24, одна колонка, шаг
   между блоками из `frame.columnGap`, отступ сверху из `frame.columnPadTop`.
3. Разложите блоки в порядке `sequence`: у каждого блока названы модули,
   которые в нём стоят, и сколько их было в снятом продукте.
4. Каждый модуль и компонент вставляйте разметкой из `markup.html`. Классы не
   переименовывайте и не сокращайте: они и есть контракт со слоем
   `ui/courses.css`.
5. Значения берите ссылками на токены. Литерала цвета, тени или шрифта в
   новой разметке быть не должно; размеры, которых в токенах нет (радиусы,
   отступы, кегли), берите из правил и спецификаций записей.
6. Тексты пишите по `content.json`: дробь через точку, цена с пробелом в
   разрядах, счётчик слитно, кнопка перехода в карточке — «Далее» или
   «Подробнее», остальные кнопки — инфинитив.
7. Проверьте результат правилами из `rules.json`, у которых `predicate.type`
   не `manual`. Правило с `manual` проверяет человек — так и скажите.

## Чего не делать

- Не выдумывать того, чего в пакете нет. `index.json → coverage.boundary`
  называет границу: личный кабинет, формы ввода, пустые состояния, ошибки и
  открытые оверлеи продакшеном не сняты. Нужен такой экран — скажите, что
  это за границей, и предложите ближайший измеренный аналог из
  `decision-guide`.
- Не брать записи со `sourceScope: "figma-only"` и `"storybook-only"` как
  факт о продукте: их в продакшене нет. Они помечены, потому что макет и
  снимок Storybook — тоже источники, но слабее.
- Не считать раскладку карусели известной: `148` из `315` карточек продукта
  лежат в лентах Swiper, и ленту раскладывает скрипт, которого в замерах не
  было (GAP решения `DG-3`).
- Не править `machine/*.json` руками: файлы собираются
  `node tools/build-machine.mjs` из источников, и следующая сборка правку
  сотрёт. Менять нужно источник — спецификацию, манифест, CSS слоя или
  документ правил.

## Изображения

Отдельного `machine/assets.json` в пакете нет. Иллюстрации и логотипы в
собранных страницах стоят локальной заглушкой `ui/assets/images/content-placeholder.svg`;
значки — спрайты из `ui/assets/sprites`. Недостающие ассеты раздела
экспертов перечислены в `ROADMAP.md`, строка X-102. Подставлять вместо
заглушки чужую картинку из интернета нельзя.

## Чем проверяется результат

```
node tools/validate-machine.mjs        # проекция сходится с источниками
node tools/validate-components.mjs --strict
node tools/validate-classes.mjs        # в разметке нет классов вне ui/
node tools/validate-showcase-claims.mjs
```

`validate-machine.mjs` падает, если id есть в JSON и нет в markdown, если
токен разошёлся с `ui/tokens.css`, если разметка записи не отрисовывается на
пустой странице с одним `ui/courses.css` или если предикат правила не
выполняется на собранной странице витрины.
