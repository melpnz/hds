# Хабр Курсы — machine-first гайд v1.1

Пакет знаний о публичном интерфейсе **Хабр Курсов**. Канонический слой разбит
на небольшие адресные JSON-файлы; универсальный viewer строит человеческое
представление из тех же данных и изолированных HTML-примеров.

> **Статус: v1.1, пригоден к использованию.** Покрыта публичная гостевая часть;
> в viewer доступны 6 разделов основ, 72 элемента и блока, 12 живых production-страниц,
> 42 правила и 82 изолированных примера. Пакет продолжает дорабатываться; границы и
> известные пробелы перечислены в `machine/index.json` и адресных спецификациях.

Версия v0.1 целиком сохранена локально в `archive/courses/v0.1`. Архив не
публикуется и не входит в обычный маршрут чтения.

## Как читать ИИ

Короткая точка входа без истории проекта — [`AI.md`](AI.md).

1. Открой `machine/index.json`, затем для Nuxt-проекта — указанный там
   `machine/consumer-workflow.json` и локальный `layers/courses/courses-kit.manifest.json`.
   Если layer отсутствует, workflow прямо требует скачать, проверить и
   скопировать зафиксированный release; это не нужно заменять ручной вёрсткой.
2. Сверь версию manifest с `machine/compatibility.json`. Матрица автоматически
   проверяется против версий обоих `package.json`, manifest и записи changelog.
3. В `machine/index.json` проверь границу покрытия и `activeImplementationProvider`.
4. Через `machine/providers/courses-nuxt-kit.json` найди export текущей версии;
   не перевёрстывай существующий компонент по скриншоту.
5. В `machine/catalog.json` найди сущность по `id`, типу, группе или `tags` и
   открой только файл из поля `file`.
6. Правила, implementation, examples и evidence загружай только по ссылкам.
7. Для подробного обоснования открой `source.spec` из `guide/`.
8. Не используй записи со scope `design-source-only` как факт о продакшене.

## Как подключить UI Kit в проект

Опубликована версия **1.4.1** от 06.10.2026, совместимая с гайдом v1.1:
[релиз и архивы](https://github.com/melpnz/hds/releases/tag/courses-nuxt-kit-v1.4.1).
Полный CI точного тега прошёл; архивы Kit и каталога проверены по SHA-256.

Канонический маршрут установки описан машинно в
[`machine/consumer-workflow.json`](machine/consumer-workflow.json).

1. Возьми по точным `archiveUrl` и `checksumUrl` из workflow архив
   `courses-nuxt-kit-v1.4.1.zip` и соседний `.sha256`, проверь контрольную сумму
   и распакуй `layers/courses` целиком. Для отсутствующего layer в Nuxt-проекте
   ИИ выполняет этот шаг самостоятельно; если GitHub недоступен — сообщает об
   этом и не имитирует компоненты кита.
2. Положи эту папку в `layers/courses` своего Nuxt-проекта; не смешивай файлы
   разных версий и не редактируй скопированный layer.
3. Установи `@nuxt/ui`, `@fontsource-variable/inter`, `swiper` и dev-зависимость
   `@iconify-json/tabler`, затем подключи локальный layer через `extends`.
4. Сверь `courses-kit.manifest.json` с `machine/compatibility.json`. Агент один
   раз в начале задачи запускает read-only проверку обновлений; она ничего не
   скачивает. Новая версия только предлагается, а изменённый layer не заменяется.
5. Готовые компоненты бери через provider mapping. Собственные компоненты и
   wrappers размещай снаружи `layers/courses`; недостающий публичный API
   запрашивай у владельца kit.

## Адаптивные страницы production

В основном viewer они находятся в разделе «Собранные страницы»:
выберите страницу в левом меню, затем вкладку «Сборка из UI Kit» или
«Эталон production». Живые страницы и компонентные превью используют локальный
kit-сервер `http://127.0.0.1:3002`; он должен работать вместе с сервером гайда.

Двенадцать страниц доступны в основном viewer как живые Vue/Nuxt-композиции из
публичных компонентов Courses UI Kit. Для каждой страницы первая вкладка — рабочая
сборка, вторая — локализованный инертный production-reference. Превью поддерживает
320 / 480 / 768 / 1024 / Auto; статический каталог prerender-ит все маршруты `/ui/pages/*`.

Исследовательские материалы сохранены отдельно: [атлас двенадцати страниц](viewer/pages.html),
[правила точной сборки](docs/guide/production-pages.md) и
[адресные машинные замеры](machine/page-analysis/atlas.json) на
320 / 393 / 480 / 744 / 768 / 1024 / 1440 с граничными проверками 767 / 1023.
[Новые варианты и расхождения](docs/decisions/page-analysis-approval.md)
перечислены отдельно; без решения владельца они в кит не добавляются.
Текущие адресные измерения имеют приоритет над историческими обобщениями.
После приёмки 05.10.2026 правила сборки и машинные `ownerDecisions`
синхронизированы с текущими 12 страницами. Для новой страницы сначала читать
эти решения, затем измерения: принятые отличия имеют приоритет над evidence.
Принятые доработки кита включены в опубликованный релиз 1.3.1.

```powershell
npm run serve -- 4181
npm run validate:page-atlas -- http://127.0.0.1:4181
```

## Структура

```text
courses/
  machine/
    index.json                 граница знаний и порядок чтения
    compatibility.json         проверенные пары guide/provider
    consumer-workflow.json      установка, использование и обновление provider
    catalog.json               маршрутизатор по 84 материалам
    foundations/*.json         шесть разделов визуальных основ
    components/*.json          один компонент или модуль на файл
    page-analysis/pages/*.json двенадцать адресных контрактов страниц
    rules/*.json               42 адресных правила и decision guides
    states.json                словарь UI и feature states
    tokens.json                полный набор токенов v0.1
    content.json               форматы чисел и подписи действий
    migration-map.json         карта полноты перехода v0.1 → v0.2
    providers/*.json           связь стабильных guide-id с активной реализацией
  guide/components/            подробные спецификации 72 сущностей
  docs/guide/production-pages.md правила сборки production-страниц
  docs/guide/                  длинные тексты о композиции и основаниях
  examples/foundations/        шесть наглядных обзоров основ
  examples/components/         изолированные живые примеры компонентов
  courses-nuxt-kit/app/        живые Vue/Nuxt-композиции страниц
  ui/                          продуктовый CSS, шрифты, иконки и изображения
  evidence/                    исходные снимки production, Figma и Storybook
  viewer/                      производная человеческая оболочка
```

## Покрытие

- 6 разделов основ: цвета, типографика, отступы и сетка, скругления и границы,
  иконография, адаптивность и брейкпоинты;
- 72 записи: 32 компонента и 40 модулей;
- все 78 catalog-записей имеют статус `complete`;
- 82 изолированных примера покрывают основы, компоненты и модули;
- 12 живых Vue/Nuxt-страниц доступны в разделе «Собранные страницы»;
- шесть исторических статических recipes удалены из активного каталога;
  исходное evidence и архив v0.1 сохранены для сравнения;
- 432 evidence-файла и 70 исходных UI-файлов перенесены без выборочного
  сокращения.

Viewer группирует материалы в четыре пользовательских уровня: **Основы →
Элементы → Блоки → Страницы**. Исходные адреса спецификаций компонентов и
страниц при этом не меняются.

Не покрыты личный кабинет, избранное, сравнение, тёмная тема, полная система
доступности, серверные ошибки и состояния, которые нельзя было воспроизвести
гостем. Для неизвестного используй ближайший измеренный аналог и явно называй
допущение; не восстанавливай отсутствующий DOM по внешнему виду.

## Посмотреть и проверить

Для нового сценария используйте [адресный набор QA-проверок](docs/guide/application-qa.md):
шаблон отчёта, ошибки хранения, восстановление на разных страницах, адаптивные
состояния и read-only аудит переиспользования Kit. Проверка структуры отчёта
не заменяет браузерный прогон и визуальную приёмку.

```powershell
npm run validate
npm run serve
```

Открой `http://127.0.0.1:4181/viewer/`. Отдельная браузерная приёмка:

```powershell
npm run validate:viewer -- http://127.0.0.1:4181
```

Чтобы в той же витрине переключаться с документирующего HTML-примера на
реальный Vue-компонент активного provider, запусти:

```powershell
npm run serve:integrated
```

Гайд с UI Kit как основным источником preview откроется на
`http://127.0.0.1:4181/viewer/?provider=local`, каталог UI Kit — на
`http://127.0.0.1:3002/ui`. Переключатель показывается только у 72 записей с
прямым provider mapping; на обычном адресе статический пример остаётся основным
fallback для GitHub и для поведенческих сценариев, которых нет в API kit.

Viewer не является вторым источником истины. Значимое правило должно жить в
`machine/`, а исследовательское пояснение к примеру — в `previewNotes`, вне
продуктового iframe.
