## Вес вердикта — мнение по итогу

Нашёл ещё одну содержательную дыру в самом гейте (находка 1): fix-2 сузил
хрупкость до трёх заявленных текстовых вариантов, но не убрал механизм
«не нашли закрывающую строку → 0 блоков, 0 диагностики, EXIT=0» — а это
и есть формулировка самого X-75. Формально по чеклисту `major` не принимает
шаг. Тем не менее рекомендую **принять с замечаниями**, не отправлять в
`blocked`, по четырём причинам:

1. Находка не задним числом ломает уже сделанную работу: `sprite-icon.md` —
   единственная спецификация волны — обе границы валидны, гейт для неё
   работает корректно; находка про гипотетический будущий ввод, не про
   поставленный артефакт.
2. Это не новый вид дефекта, а тот же самый (регэксп-граница fence-блока
   хрупка к форме текста), в третий раз найденный в третьей своей
   разновидности. После двух патчей на конкретные заявленные варианты
   очевидно, что залатывание по одному репортнутому случаю не сходится —
   у регэкспа с текстовой границей всегда найдётся четвёртый вариант.
   Правильное решение — не четвёртый патч регэкспа, а структурная замена
   (построчный скан c явным парным учётом открытий/закрытий, который **явно
   падает** на непарном ```` ``` ````, а не молча возвращает пустой список) —
   это по объёму отдельный шаг, не ещё один точечный fix в границах уже
   исчерпанных трёх итераций.
3. Гейт — не единственная линия обороны: ревью каждой из 54 будущих
   спецификаций по чеклисту (в частности, пункт про копируемость — вставить
   разметку и проверить руками) обязано визуально заметить незакрытый
   блок кода в самой спецификации задолго до того, как это станет
   вопросом к автоматике. Держать первую поставку пакета в `blocked` ради
   гипотезы, которую следующий же ручной шаг ловит по построению, — цена
   выше пользы для объёма в один компонент.
4. Правило конвейера — три итерации на шаг. Если требовать полного
   закрытия категории (а не заявленных вариантов) на третьей итерации,
   планка становится недостижимой для любого регэксп-гейта данного типа:
   всегда можно предъявить очередной адверсарный ввод. Разумнее зафиксировать
   находку 1 как обязательную строку `ROADMAP.md` со ссылкой на этот отчёт
   (структурная замена парсинга, не очередной патч регэкспа) и решить её
   до того, как гейт останется единственной защитой на большом количестве
   спецификаций сразу (несколько шагов вперёд, не сейчас, пока проверяется
   вручную по одному компоненту за раз) — а первый компонент пакета
   принять с этим долгом явно записанным, а не отправлять по кругу вопрос,
   на который итеративный патч одного и того же регэкспа не даёт
   сходящегося ответа.

Находка 2 (квадратичная деградация) — минор, тоже в roadmap, без спора
о вердикте: не блокирует ни этот, ни ближайшие шаги при типичном размере
