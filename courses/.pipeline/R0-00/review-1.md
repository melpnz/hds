### 1 · blocker · Вывод «переход 375 → 744 даёт ноль изменений, 10/10» неверен как вывод

Отчёт утверждает (§3.3, §4 п. 1–2, вынесено в `ROADMAP.md`):

> 320, 375 и 744 дают одну раскладку … Правило пакета для канонических 320 и 744 —
> это одно и то же правило, а не два.
> Единственная граница раскладки внутри канонической схемы ниже 1024 — 768.

Между 375 и 744 в DOM подменяется реализация выпадающего списка фильтра.
Счётчик `base-modal` и `v-popper--theme-dropdown` по `dom-<w>.html`:

| Страница | `base-modal` 320/375/744/768 | `v-popper--theme-dropdown` 320/375/744/768 |
|---|---|---|
| `courses-listing` | 1 / 1 / **0 / 0** | 0 / 0 / **1 / 1** |
| `education-centers-listing` | 6 / 6 / **0 / 0** | 0 / 0 / **6 / 6** |
| `promocodes` | 26 / 26 / **20 / 20** | 0 / 0 / **6 / 6** |
| `rating` | 6 / 6 / **0 / 0** | 0 / 0 / **6 / 6** |
| `reviews` | 4 / 4 / **0 / 0** | 0 / 0 / **4 / 4** |
| `schools-for-children` | 6 / 6 / **0 / 0** | 0 / 0 / **6 / 6** |

Покрытие 6/10 — по METHOD §8 это правило, а не наблюдение. На 320 и 375 фильтр
раскрывается модалкой, на 744 и 768 — дропдауном. Это тот же вид расхождения,
который сам отчёт нашёл на границе 744 → 768 и назвал «две реализации одного
модуля» (§3.4), только здесь второе поддерево в DOM вообще отсутствует.

Дополнительно на границе 375 → 744 исчезает аффорданс «показать целиком»
(`div.absolute bottom-[20px] … bg-gradient` плюс `button.absolute bottom-0 …`):
2 узла на `reviews`, 1 на `education-center`.

**Почему метод шага этого не увидел.** Сопоставление идёт по `path + classes`,
а сравниваются три признака: видимость, `flex-direction`, число колонок грида.
Узел, которого на одной из ширин в DOM нет, не получает пары и молча выпадает
из сравнения — «сменить видимость» он не может по построению. На границе
375 ↔ 744 без пары остались 429 узлов со стороны 375 и 1059 со стороны 744 —
**1488 из 10 877 ключей, 13,7 %**. Отчёт ни в §3.3, ни в §6.4 не называет ни
числа сопоставленных узлов, ни числа выброшенных: «ноль изменений, 10/10»
подано как утверждение обо всей странице, а измерено на 86 % узлов.

Сам замер верен — я его воспроизвёл: на сопоставленных узлах 375 ↔ 744 ровно
0 смен видимости, 0 смен `flex-direction`, 0 смен числа колонок, 10/10.
Неверен вывод, сделанный из него.

Воспроизвести — из `courses/evidence/source/production/pages`:

    for p in */; do for w in 320 375 744 768; do
      echo "$p $w modal=$(grep -o base-modal $p/dom-$w.html | wc -l)" \
           "popper=$(grep -o 'v-popper--theme-dropdown' $p/dom-$w.html | wc -l)"
    done; done

`.pipeline/R0-00/media-queries.mjs` устроен ровно так, как забраковано:

«колонок / header / footer» в §3.1, и именно на них держится вывод
«переключение между 767 и 768». Шаг потратил сорок отдельных запусков на то,
чтобы уйти от ресайза в основных данных, и вернулся к ресайзу в данных,
несущих главный вывод.

Сами числа я сверил — в `media-queries.json` они ровно те, что в §3.1
(header 108 · 108 · 108 · 108 · 108 · 64 · 64 · 64 · 64; footer 476 ×5 → 256 ·
256 → 192 · 192; `rubricGrid` от `272px` до `260px 260px 260px 260px`).
Претензия к методу, не к переносу чисел.

Отдельно: 200 мс на ресайз против 1200 мс `--wait` в `capture.mjs` — на сайте
с Vue-гидратацией это разные условия, и разница нигде не оговорена.

## Что проверено и претензий нет

**Полнота evidence — сходится полностью.**

- 10 папок × 28 файлов = 280. Раскладка: 100 канонических (320/744 × dom,
  computed, tokens, meta, png), 100 холодной перезагрузки (375/768 × dom,
  computed, tokens, meta, `*-reload.png`), 80 нетронутых от 7 сентября.
  Совпадает с заявленным. Нулевых файлов нет.
- Таблица размеров §2 сверена: `courses-listing` 320.png 4 100 309 Б = 4004 КиБ,
  `author` 320.png 420 819 Б = 411 КиБ — сходится на всех двадцати.

**PNG подлинные.**

- Все 80 PNG: сигнатура `89504e470d0a1a0a`, ширина IHDR совпадает с именем.
- Таблица размеров §2 (`320 × 29068`, `744 × 27654` … `744 × 3406`) сверена
  по IHDR — совпадает на 20/20.
- Копий чужой ширины нет: 320, 375, 744, 768, 1024, 1440 внутри каждой папки
  имеют разные хеши и разные размеры.
- Единственные побайтово равные PNG — `author/375.png == 375-reload.png` и
  `author/768.png == 768-reload.png`. Это статичная страница без каруселей
  и рекламы (300 узлов на всех четырёх ширинах); на остальных девяти страницах
  `*-reload.png` от снимка 7 сентября отличается. Подлогом не считаю — это,
  наоборот, косвенный ответ на GAP §6.1: на `author` ресайз и холодная загрузка
  дают идентичный пиксель.

**Файлы 7 сентября не перезаписаны.** `1024.png`, `1440.png`, `375.png`,
`768.png`, `computed.json`, `dom.html`, `meta.json`, `tokens.json` во всех
десяти папках имеют mtime 09-07 20:33–20:38; все новые файлы — 22:05–22:29.

VCS-подтверждения нет.

`"computedAtWidth": w`, совпадающие с суффиксом имени. Старые `meta.json`

верно, и computed 7 сентября действительно относится к 1440.

ширине, и `run-capture.mjs` копирует PNG только после `fs.existsSync`.
`run-log.json` — 40 записей, `ok: true` на всех, ни одной пометки `MISSING`
или `EXISTS-SKIPPED`.

**Пин инструмента.** `sha1sum .pipeline/R0-00/capture.mjs` =
`b81051ed74dfea2ff546c598e8bb4371d324f749` — совпадает с заявленным в §1
