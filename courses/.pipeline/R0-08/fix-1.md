## Подробнее по major 1

Было:

```js
const RE_LOOKS_LIKE_MARKUP = /<\/?[a-z][\w-]*(?:\s[^<>]*)?>/i;
function checkUnit(unit) {
  if (RE_LOOKS_LIKE_MARKUP.test(unit.text)) return;
```

Стало — гашение фрагмента, а не пропуск единицы:

```js
const RE_MARKUP_TAG = /<\/?[a-z][\w-]*(?:\s[^<>]*)?\/?>/gi;
function maskMarkup(text) { /* replace(..., ' '.repeat(m.length)) до неподвижной точки */ }
function checkUnit(unit) {
  const masked = maskQuotes(maskMarkup(unit.text));
```

Длина сохраняется намеренно: строка находки берётся из карты «смещение →
строка», и любое изменение длины увело бы её. Повтор прохода нужен из-за
вложенного `<`: в `<section class="doc-section" id="c-<id>">` внешний тег
не совпадает, пока внутренний `<id>` не погашен, — на это заведена
отдельная проба.

Проверено на текущем дереве: клауз с сущностями **176 → 193**, из них
о `ui/` — **12**; находка по-прежнему ровно одна и ровно та же
(`showcase/components.css:705`). Ложных срабатываний ноль: три ранее
глухих комментария CSS (`:315`, `:469`, `:736`) прочитаны и зелены.

## Подробнее по major 2 — все границы слова файла

Ревью назвало одно место; правка прошла по всем.

| Где | Было | Стало | Почему это тот же класс |
|---|---|---|---|
| `exceptionsOf` | `\bв\s+том\s+числе\b` | `BOUND0(?:и\s+)?в\s+том\s+числе BOUND1` | мёртвое выражение, находка ревью |
| `htmlTokens`, закрывающий тег | `</\s*${name}\b` | `</\s*${name}(?![A-Za-z0-9_-])` | `\b` считает границей и дефис, и кириллицу: `</style-x>` закрывал бы `<style>` |
| `attr()` | `\b${name}\s*=` | `(?<![A-Za-zА-Яа-яЁё0-9_-])${name}\s*=` | имя атрибута с дефисом: `\bdata-claim` совпадает внутри `x-data-claim` |
| `RE_UI_LAYER` | `(?:^\|[^\w/])ui\/` | `(?<![A-Za-zА-Яа-яЁё0-9_/-])ui\/` | `[^\w/]` пропускает кириллицу как «не букву» |
| `RE_VAR`, `RE_PREFIXED`, `RE_DOTCLASS` | `(?<![\w-])`, `(?<![\w/\\.-])` | те же классы плюс `А-Яа-яЁё` | комментарий обещал «слева не буква или цифра», а русская буква буквой не считалась |

Формы, оставленные как есть, — ASCII по существу предмета и проверены:
`/^(?:-[\w]+-)?keyframes$/` (имя at-rule), `[a-zA-Z][\w-]*` (имя тега),
`docs\/[\w.-]*` и `ui\/[\w./-]+\.css` (пути).

## Отклонённое

**Note 10 — незакрытый тег съедает слой (`claim-unscoped` вместо
`claim-negative`).** Отклонено. Что говорит источник: `htmlTokens`
читает тег до `>` вне кавычек значения атрибута, и в
`<span class="x" В ui/ нет <code>tablet:px-6</code>` подстрока `ui/`
физически лежит внутри незакрытого тега. Чтобы отдать её текстом, сканеру
пришлось бы **угадывать**, где автор хотел закрыть тег, — то есть
делать ровно то, от чего шаг отказался, отвергая регэксп по форме
документа (X-81). Поведение при этом не тихое: находка остаётся, гейт
красный, файл и строка названы верно; беднее только вид находки, и
только на невалидном HTML. Цена правки — догадка в сканере; выгода —
более точное имя находки в случае, который сам по себе является ошибкой
разметки. Отдельной строки долга не завожу: предел следует из
устройства сканера и описан в его комментарии.

**Note 8 и note 9 — приняты и исправлены** (строки 8 и 9 таблицы).
