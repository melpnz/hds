### Подробнее по находке 1

Проверка `review-2.swallow.mjs`, носитель 2, комментарий `showcase/components.css:703–706`
(тот самый, где живёт четвёртое проявление). Меняются только две строки прозы
внутри того же комментария:

```
   Атрибут ставится на <section class="doc-section"          ← незакрытый тег выше клаузы
   чтобы границы было видно перетаскиванием окна: в ui/ из шести поднят
   только phone:, и только для двух ступеней шкалы.
   Прямой потомок .doc-list > .doc-item здесь не нужен.      ← любой `>` ниже клаузы
```

```
0. как есть (контроль)                       EXIT=1  находка ЕСТЬ
1. незакрытый тег выше + `>` ниже            EXIT=0  находка НЕТ
   Клауз с сущностями 193, из них о ui/ 11; … Расхождений нет.
2. тот же незакрытый тег, но без `>` ниже    EXIT=1  находка ЕСТЬ
```

Носитель 1 ведёт себя так же: то же предложение прозой с `&lt;section class="…"`
и `&gt;` после клаузы снимает находку (случаи 3 и 4, 2 находки → 1).

Механика: `[^<>]*` не исключает перевод строки, поэтому совпадение тянется от
`<section` до первого `>` **где угодно дальше по единице**, и всё между ними
гасится пробелами. `maskMarkup` устроен как «съесть до ближайшего `>`», а не
как «съесть тег», и на невалидной или оборванной разметке это ровно тот тихий
ноль, ради которого заведён шаг. Шапка файла при этом утверждает обратное про
сканер: «не теряет незакрытый тег молча (текст после него остаётся текстом)» —
для `htmlTokens` это верно, для нового слоя гашения нет.

Замечу связь с отклонённой note 10: её обоснование опирается на «поведение при
этом не тихое: находка остаётся, гейт красный». Для незакрытого тега это больше
не общее свойство гейта — оно перестало им быть на самом fix-1.

## Что проверено и претензий нет

**Major 1 закрыт в названных формах и в двенадцати новых.** Пропуска единицы
целиком в коде нет; читаются все двенадцать ранее глухих единиц, включая три
комментария CSS об `ui/` (`:315`, `:469`, `:736` — в переписи, зелёные).
Обе пробы ревью-1 (`R1`) теперь красные, как и должны. Мои формы обхода —
тег внутри атрибута `<span data-x="<b>">`, тег внутри тега, одинокий `<` без
пары, тег, разорванный переводом строки (в том числе четырьмя), экранированный
тег внутри уже экранированного (`&amp;lt;span&amp;gt;`), пять уровней
вложенности при четырёх проходах, верхний регистр и самозакрывающийся,
`>` внутри значения атрибута, образец **после** клаузы — все тринадцать дают
находку (`review-2.probes.log`, A1–A7, A9–A14). Ложных срабатываний на самом
образце разметки нет (A14). Единственная форма, которая проходит, — находка 1.

**Major 2 закрыт, и полнее, чем просил ревью.** Живых `\b` в файле не осталось
(`grep`); `\w` остался в семи местах, шесть из них ASCII по существу предмета —
имя at-rule `keyframes`, имя тега (`[a-zA-Z][\w-]*`, HTML-имена ASCII по
спецификации), пути `docs/`, `career/`, `showcase/`, `ui/…css`, имя переменной
`--[a-z][\w-]*`, имя класса в `RE_DOTCLASS`; седьмое — находка 6, и она
безопасна по направлению. Форма «кроме `px-6` в том числе `small-phone:text-center`»
без запятой снова даёт находку (`B1`), с запятой и с «и в том числе» — тоже
(`B2`, `B3`), а перечисление без разделителя остаётся зелёным (`B4`).
Проверены и остальные пять правок: `x-data-claim` не читается как `data-claim`,
а настоящий `data-claim` с ложным числом краснеет (`B5`, `B6`); «в нашем слое»
без пути опознаётся (`B7`); `не раскрывается` в кириллическом окружении
работает (`B8`); «лишь» наравне с «только» (`B9`); `</style-x>` не закрывает
инлайновый `<style>` (`B10`).

**Major 3: 39 чисел действительно выводятся из разбора `ui/`.** Проверено не
чтением таблицы, а мутацией **источника**: правка `ui/` роняет ровно то число,
которое из неё выводится (`review-2.probes.log`, C1–C7) —
`letter-spacing:-.5px → -.25px` роняет `scale.tracking`;
`.text-h1{font-size:44px → 46px}` роняет ряд `scale.sizes`;
`.font-semibold{600 → 650}` роняет ряд `weights.list`; четвёртое начертание
роняет `weights.count`; `@media (max-width:767px → 800px)` роняет `scale.edge`;
снятие `.text-h4` из правила трекинга роняет `scale.tracked`;
`.max-w-\[1124px\]{max-width:1200px}` роняет `container.maxWidth`. Величин
в `DERIVED` действительно 24 плюс 3 ряда, все выводятся из `postcss`-разбора,
`@font-face` в начертания не попадает (проверено чтением `fontWeights()` и
`ui/fonts.css`: ось `100 900` в 14 блоках `@font-face` в счёт не идёт).
Числа `39 / 527 / 566` сходятся арифметически и совпадают с моей переписью;
список непокрытых — не свалка: 220 записей по клаузам, каждая с текстом и
адресом, не-числа (`blue-50`, `#94bdfc`, `R0-06`) отфильтрованы. Формулировка
о X-90 сужена в трёх носителях; остаток по существу вынесен в X-96 и X-101,
и X-101 описана верно (ряды в парах `<dt>/<dd>` покрыты, прозаические формы —
