## Почему `blocked`, а не четвёртая правка — `review-3.md`, находка 1

Гейт §6.2 в `tools/validate-classes.mjs` требует, чтобы каждый CSS-класс
оболочки витрины нёс префикс `doc-`, а в продуктовом слое (`ui/`) не было
ни одного класса `doc-*`. Реализация — ручной регексп-разбор CSS
(`classNames`/`UNESCAPE`, `tools/validate-classes.mjs:110-121`), а не
настоящий CSS-парсер. Три предыдущих обхода этого гейта — все закрыты
по существу (см. ниже, «Что закрыто за три итерации»). Четвёртый, найденный
на финальной итерации, — не закрыт:

- **Механизм.** У CSS есть два разных синтаксиса экранирования символов
  в идентификаторах: «один слэш — один символ» (`\:`, `\.`) и hex/unicode-escape
  (`\` + 1–6 шестнадцатеричных цифр, опционально с завершающим пробелом,
  например `\64` = `d`, `\6c` = `l`). `UNESCAPE` в `tools/validate-classes.mjs`
  реализует только первый вид. На hex-escape он «откусывает» одну
  шестнадцатеричную цифру как «экранированный символ», а остаток цифр
  уходит в обычный текст; в паре с фильтром «класс не начинается с цифры»
  (добавлен ранее для отсечения `@media (min-width: 37.5em)`) остаток
  выпадает из разбора целиком, без класса.
- **Обход в обе стороны инварианта, воспроизведён в реальном браузере
  (Chromium, `playwright`)**, не только по трассировке регэкспа:
  - **(a) утечка в `showcase/*.css` не ловится.** `.doc-badge.\6c eaked-hidden { background: lime; }` — гейт видит только класс `doc-badge`, второй класс (`\6c eaked-hidden`) выпадает из разбора; браузер же применяет стиль к элементу с классами `doc-badge leaked-hidden` — реальный класс `leaked-hidden`, без `doc-`, но `EXIT=0`, «All defined».
  - **(b) продуктовый слой получает класс-«приманку» витрины, и гейт молчит.** `.\64 oc-injected-hack { color: red; }` в `ui/tokens.css` — браузер применяет `color: red` к `class="doc-injected-hack"` без единого слэша в разметке; гейт же не находит в `ui/tokens.css` ни одного класса `doc-*` и печатает «15 ui stylesheet(s) free of doc-». Это прямое нарушение инварианта METHOD §6.2 в его продуктовой половине.
- **Повторено независимо** третьей стороной (ревьюером, не автором правки) на изолированной копии пакета, с браузерной проверкой, а не только по чтению кода.

Ревьюер сам отмечает: «похоже на структурный предел выбранного подхода
(ручной разбор регулярными выражениями), а не на серию случайных
недосмотров» — три предыдущих обхода лежали в разных частях того же
регексп-разбора (список at-rules, критерий `.some()`/`.every()`, разбор
селекторов), и четвёртый, найденный именно на предельной итерации, —
не последний правдоподобный класс такого рода.

## Что закрыто по существу за три итерации (не отменяется этой приёмкой)

- **review-1, major B.8** — гейт разбирал набор имён классов файла целиком,
  а не по правилам; переписан на `forEachRule`/`selectorLeaks` с рекурсией
  по `@media`/`@supports`/`@layer`, требование «каждый селектор несёт `doc-*`».
  Три обхода ревью (инлайновый `<style>` витрины, bare-селектор
  `button, input, a`, атрибутный селектор `[class~="leaked-shell"]`) —
  закрыты, подтверждены `EXIT=1` в `fix-1.md`, регрессия держится во всех
  последующих ревью.
- **review-1, major B.10 + обе «дыры» вне формата** — зеркальное правило
  `non-planned component must have showcaseAnchor` в
  `tools/validate-components.mjs`; поиск якоря витрины переведён с поиска
  подстроки по файлу на поиск настоящего тега (заполнитель `c-<id>` внутри
  `<pre>` больше не засчитывается как якорь). Обе дыры закрыты одной правкой,
  проверены `EXIT=1` на подложенных значениях.
- **review-2, major B.8** — два новых обхода того же гейта: составной
  селектор «доc- + непрефиксованный» проходил, потому что критерий требовал
  «хотя бы один» класс `doc-*` (`.some()`), а не «каждый» (докстринг обещал
  «каждый»); `@container` не входил в белый список at-rules для рекурсии
  и пропускал bare-селекторы внутри себя. Оба закрыты: критерий на
  `.every()` + явное условие «классы найдены» (`names.length > 0`, иначе
  пустое множество молча проходит), список at-rules инвертирован — по
  умолчанию рекурсия во всё, кроме короткого перечня at-rules, структурно
  не содержащих селекторов элементов (`@font-face`, `@property`, `@page`,
  `@keyframes`).
- **Третий изъян, найденный самой правкой fix-2, не отдельной находкой
  ревью** — at-rule без блока (`@import ...;`, `@charset ...;`) склеивался
  с преамбулой следующего блока и «съедал» его из разбора; исправлено
  разбором до `;`, когда `;` встречается раньше следующего `{`.
- **Регрессия всех прежних обходов подтверждена на каждой итерации**,
  включая финальную (`review-3.md`): R-d, R-f, R-j, R-a, bare-selector
  control, R-x1/R-x2/R-x5 (review-2), T1/T3 (fix-2) — все по-прежнему
  `EXIT=1`, ничего не откатилось при закрытии новых находок.
- **Обязательные гейты пакета держатся на протяжении всего цикла** —
  `validate-components.mjs --strict`, `validate-counts.mjs`,
  `node --check tools/*.mjs`, `measure-selectors.mjs` — все код 0 на каждой
  из трёх итераций, `components/manifest.json` и `components/selector-census.json`
