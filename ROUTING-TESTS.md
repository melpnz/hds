# Контрольные сценарии маршрутизации

Эти примеры проверяют логику корневых `README.md` и `AGENTS.md`. Они не задают
новые дизайн-правила.

| Запрос | Ожидаемое действие |
|---|---|
| «Сверстай ленту статей внутри Хабра» | контекст и продукт известны → `habr/AGENTS.md`, без повторного вопроса |
| «Сделай страницу Хабра» | неоднозначно → уточнить: интерфейс сервиса или лендинг |
| «Сделай форму авторизации» | функция не определяет контекст → сначала уточнить интерфейс или лендинг |
| «Форма заявки на корпоративном лендинге» | контекст известен → `landings/AGENTS.md`, theme `company` |
| «Промостраница Курсов» | слово «Курсы» не означает интерфейс → продуктовый Landings-маршрут, затем уточнить цель/пример |
| «Брендовый спецпроект» | `landings/AGENTS.md` + исследование `07`, предупредить о статусе в разработке |
| «Экран вопросов Q&A» | предупредить: гайд в планах; использовать `02-habr-qna.md` как приблизительное исследование |
| «Обнови компонент в гайде Courses» | это поддержка репозитория → не задавать меню продукта, читать root и `courses/AGENTS.md` |
| «Собери страницу каталога внутри Хабр Курсов в новом Nuxt-проекте» | контекст известен → `courses/AGENTS.md` → `courses/machine/index.json` → `consumer-workflow.json`; при отсутствии manifest скачать зафиксированный release, проверить checksum и скопировать `layers/courses`, затем использовать provider mapping и адресные правила |
| Тот же запрос, но совместимый `layers/courses` уже есть | использовать локальный layer без сетевого запроса и без проверки обновлений |
| Тот же запрос, но существующий layer изменён или несовместим | не перезаписывать; сообщить конфликт и запросить решение о миграции |

Проверка путей и версий: `node tools/validate-guides.mjs`.
