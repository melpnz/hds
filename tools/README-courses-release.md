# Выпуск Courses Nuxt Kit

Workflow: [Courses UI Kit — prepare draft release](https://github.com/melpnz/hds/actions/workflows/courses-release.yml).

GitHub проверяет выбранную версию, собирает архив слоя и статический каталог, затем создаёт **только черновик** релиза. Публикация и обновление копий в продуктах остаются ручными.

## Подготовка версии

1. Завершить изменения UI kit, обновить версию package/manifest, датированный CHANGELOG и integrity штатными инструментами пакета.
   До публикации consumer-workflow помечает будущий архив как `prepared-not-published`.
   После ручной публикации снять эту пометку и предупреждение в README,
   вернуть обычный preflight установки опубликованного архива.
2. Связать manifest с исходным коммитом. Между ним и релизным коммитом допускаются изменения только manifest/integrity внутри слоя.
3. Отправить коммиты в `main`, создать и отправить аннотированный тег `courses-nuxt-kit-vX.Y.Z`, совпадающий с manifest. Workflow сам теги не создаёт.

## Запуск

1. Открыть workflow → **Run workflow**, выбрать ветку `main` и ввести тег.
2. Для пробного прогона включить `dry_run`: проверки и архивы будут собраны, релиз не создаётся. Так можно проверить уже выпущенную версию.
3. Для подготовки нового черновика оставить `dry_run` выключенным.
4. После успешного прогона открыть [Releases](https://github.com/melpnz/hds/releases), проверить описание и четыре вложения, затем вручную опубликовать черновик.

Вложения: ZIP слоя `layers/courses/`, его SHA-256, ZIP проверенного статического каталога и его SHA-256. Каталог нужно раздавать HTTP-сервером от корня; полный обозреватель иконок требует API локального сервера пакета.

## Ограничения и защита

- Проверяются контракты, привязка источника, сборка, автономный потребитель, превью, поведение и визуальные эталоны **точного коммита тега**.
- Тег должен быть аннотированным и указывать на коммит из истории `main`. Изменение тега после проверок блокирует выпуск.
- Существующие релизы не перезаписываются. Ошибка проверки не создаёт релиз.
- Только последний этап имеет `contents: write`; он исполняет скрипт из ревизии workflow, а не код релизного тега. Постоянные дополнительные секреты не нужны.
- Используются стандартные GitHub runners. Временные CI-артефакты хранятся 3 дня; опубликованные вложения релиза не зависят от этого срока.
- Если создание черновика завершилось частично, сначала проверить его вложения вручную: повторный запуск не удаляет и не заменяет существующий релиз.

Локальная проверка политики: `node tools/test-courses-release.mjs`. Проверка существующего тега без записи: задать `COURSES_RELEASE_TAG`, затем `node tools/courses-release.mjs check`.
