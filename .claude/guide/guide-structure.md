# Целевая структура гайда

Эталон организации — [Контур.Гайды](https://guides.kontur.ru/): три раздела верхнего
уровня, статьи одинакового устройства, правило всегда рядом с примером.

Мы добавляем к этому то, чего у Контура нет: **вторая проекция того же самого
в машиночитаемом виде**, чтобы по гайду можно было не только сверстать вручную,
но и сгенерировать интерфейс.

## Разделы гайда

```
Принципы    как устроен продукт и как принимать решения
  Базовые       лейаут, сетка, отступы, цвет, тёмная тема, адаптивность, форма
  Текст         типографика, тон, названия, работа с данными
  Доступность   клавиатура, фокус, контраст, скринридер
  Интерактивность  отклик, загрузка, залипание, бесконечный скролл
  Данные        валидация, сохранение, редактирование, пустые состояния
  Взаимодействие   уведомления, подтверждения, ошибки
  Решения       Decision Guides: как проектировать то, чего в продукте ещё нет

Компоненты  каталог: поля, действия, выбор, навигация, попапы, прогресс, экраны
Паттерны    семейства страниц (интерфейс) или рецепты блоков (лендинг)
Ресурсы     токены, иконки, шрифты, шаблоны, витрина
Машинный слой  те же знания в JSON — для генерации интерфейсов
```

В файловой системе это `docs/guide/*`, `components/*`, `pages/*` или `blocks/*`,
`ui/*`, `machine/*` — см. METHOD.md §2.

## Статья о компоненте

Порядок разделов — по Контуру; наши разделы извлечения идут после, чтобы статья
сначала отвечала «когда и как применять», и только потом «как это устроено».

```
1  Когда использовать      контекст выбора и чем отличается от соседнего компонента
2  Когда не использовать   что взять вместо — со ссылкой
3  Примеры                 живые случаи применения из продукта
4  Как работает            поведение: реакция на курсор, срабатывание, режимы
5  Название и текст        как называть: форма глагола, регистр, длина, многоточие
6  Размер и расположение   размеры с контекстами применения, правила ширины
7  Управление клавиатурой  фокус, Enter, Escape, стрелки, ловушка фокуса
8  Валидация               недопустимые состояния и что показывать
9  Анимация                переходы, спиннер, длительности
10 Внешний вид             варианты, цвета, отступы, радиусы — числами
—— слой извлечения ——
11 Анатомия                дерево DOM из снимка
12 Токены                  var(--…) со значениями
13 Иконки · Responsive · Доступность
14 Разметка                готовый к переносу HTML
15 CSS                     текст правил
16 Ограничения             чего не подтверждено и чего для этого не хватает
17 Источники               URL + селектор, node key, файлы evidence
```

Разделы 1–9 пишутся **словами и правилами**, 11–17 — извлечёнными фактами.
Раздел, которому нечем подтвердиться, не пишется; исключение — 1, 14, 16, 17.

## Статья о принципе

```
1  О чём принцип        одно предложение
2  Правила              таблица: id · формулировка · покрытие
3  Как применять        призывом: «Используйте …», «Избегайте …»
4  Примеры              пары «неправильно → правильно» скриншотами
5  Исключения           когда правило не работает и почему
6  Где проверено        страницы и вьюпорты
7  GAP                  за какой чертой принцип не отвечает
```

## Статья о паттерне страницы

```
1  Что за семейство     листинг, страница сущности, профиль, дашборд, форма
2  Каркас               сетка числами: колонки, промежутки, контейнер
3  Состав по областям   какие модули в какой области и в каком порядке
4  Как перестраивается  брейкпоинты и что происходит на каждом
5  Правила семейства    ссылки на id правил
6  Живой пример         якорь в showcase/pages.html + снимок продакшена
7  Ограничения          что в семействе не снято
```

Для лендинга то же самое читается как **блок** (hero, секция, stats, CTA, форма,
футер) и **рецепт** — последовательность блоков, из которых собирается страница.

## Две проекции одной истины

Каждое утверждение живёт в двух видах: человекочитаемом (markdown) и
машиночитаемом (`machine/*.json`). Расхождение между ними — ошибка пакета,
а не деталь.

| Человеку | Машине | Связь |
|---|---|---|
| `components/<cat>/<id>.md` | `machine/components.json` | по `id` |
| `docs/guide/composition.md` | `machine/rules.json` | по `id` правила (`L-4`) |
| `pages/<id>.md` / `blocks/<id>.md` | `machine/patterns.json` | по `id` паттерна |
| `ui/tokens.css` | `machine/tokens.json` | по имени переменной |
| раздел «Название и текст» | `machine/content.json` | по `id` компонента |

Правило: **машинный слой собирается из источников скриптом**, а не пишется
параллельно руками. Руками пишется то, что скрипт снять не может (usage, тон,
когда не использовать), и живёт в `machine/*.overrides.json`, откуда сборка
его подхватывает. Проверяет соответствие `tools/validate-machine.mjs`.

Подробности схем — [`machine-layer.md`](machine-layer.md).
