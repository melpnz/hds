# Чеклист ревью свёрстанного элемента

Каждый пункт либо проходит, либо даёт находку. Находка без способа воспроизвести —
не находка: в отчёте у неё должна быть команда, файл со строкой или пара скриншотов.

## Severity

| Уровень | Что это | Что с ним делает приёмка |
|---|---|---|
| **blocker** | элемент нельзя использовать: не воспроизводит продукт, ломает инвариант пакета, вымышленный факт | не принимает шаг |
| **major** | заметное расхождение с источником или дыра в контракте состояний | не принимает шаг |
| **minor** | шероховатость, не влияющая на применимость | принимает, находка уходит в roadmap |
| **note** | наблюдение на будущее | не влияет |

## A. Соответствие источнику

1. Геометрия против прода: размеры, отступы, радиусы, кегли из `computed.json`
   совпадают со свёрстанным. Допуск 1px, всё сверх — находка с числами.
2. Цвета и типографика против Figma variables (`get_variable_defs`) и `tokens.json`.
3. Скриншоты рядом: уже лежащие именованные кропы
   `evidence/source/production/<id>/<Name>.1400.png` и `<Name>.320.png`,
   экспорт узла Figma из `evidence/source/figma/`, снимок нашего примера
   из витрины. Живой прод и Figma MCP за новыми скриншотами не открывай.
   Расхождение описывается словами — что именно не так, а не «выглядит иначе».
4. Композиция и состав слотов совпадают с узлом Figma; лишние элементы, которых нет
   ни в проде, ни в Figma, — находка.
5. Ни одно утверждение спецификации не расходится с иерархией источников
   (`evidence.md`). Выбор Figma поверх runtime без записи GAP — blocker.

## B. Инварианты пакета

6. Копируемость: разметка из спецификации, вставленная на пустую страницу
   с одним `ui/<product>.css`, отрисовывается правильно, иконки видны.
7. В `ui/components/*.css` нет литеральных цветов и размеров там, где в проде токен.
8. Оболочка витрины не протекла в `ui/`; в разметке спецификации нет классов витрины.
9. Ассеты локальные: в разметке спецификации нет продовых URL.
10. `manifest.json` сходится: спецификация, CSS root и якорь витрины существуют.

## C. Состояния и поведение

11. Все состояния из `requiredStates` показаны живым примером или объяснены как
    `unsupported` с обоснованием. Слова только из закрытого словаря.
12. Интерактивные состояния работают в браузере, а не только описаны:
    hover, focus-visible (клавиатурой), pressed, disabled, open/closed.
13. Фокус виден и не теряется; порядок табуляции осмысленный.
14. ARIA соответствует снятой разметке — ни выдуманных атрибутов, ни потерянных.

## D. Responsive и устойчивость

15. На 320, 768, 1024 и 1400 нет горизонтального overflow и обрезанного контента.
16. Длинный текст, пустое значение и отсутствие иконки не ломают раскладку.
17. Заявленные брейкпоинты действительно переключают композицию.

## E. Документация

18. Разделы спецификации — по шаблону, пустых заглушек нет.
19. Каждый факт имеет источник; каждое непокрытое место — в «Ограничениях».
20. Раздел «Назначение» отличает компонент от ближайшего соседа.

## F. Страницы и паттерны

_Проверяется на шагах, где собирается страница или блок лендинга._

21. Страница собрана только из принятых компонентов; разового CSS ради скриншота нет.
22. Каркас числами совпадает со снятым с продакшена: колонки, промежутки, контейнер.
23. Порядок схлопывания на 1024 / 768 / 320 совпадает с продовым.
24. Статья паттерна отвечает, чем это семейство отличается от соседнего.
25. Для лендинга: рецепт называет обязательные и необязательные блоки и их порядок.

## G. Правила и принципы

_Проверяется на шагах вывода принципов._

26. У каждого правила есть покрытие; победитель — частое значение; правил из одной страницы нет.
27. Формулировка содержит число или бинарный признак и фальсифицируема.
28. Оценочных прилагательных нет ни в одном правиле.
29. OBSERVED и рекомендация разделены; `Confidence` относится к рекомендации.
30. Правило стоит на витрине рядом с живым элементом или страницей (`data-rule`).
    Правило только в markdown — major. Есть раздел о том, чего правила не задают.

## H. Машинный слой

31. Каждый `id` из `machine/*.json` есть в markdown и наоборот.
32. `markup.html` отрисовывается на пустой странице с одним `css` из `index.json`
    и совпадает с разделом «Разметка» спецификации.
33. Токены из `tokens.json` есть в CSS, значения сходятся.
34. Правила с исполнимым предикатом выполняются на витрине; остальные помечены `manual`.
35. `coverage` в `index.json` не заявляет больше, чем покрыто.
36. По машинному слою без markdown собирается простой экран продукта.

## I. Текст

37. Тон информационный, активный залог, без канцеляризмов и оценочных усилителей.
38. Запреты разделены по силе («не рекомендуется» / «нельзя» / «запрещается»),
    у каждого названа причина.
39. Рекомендации написаны призывом и подкреплены фактом или картинкой.
40. Примеры даны парами, подпись говорит, что именно не так.

## Формат отчёта

```markdown
# Ревью <batch-id> · <component ids> — итерация N

Вердикт: **вернуть на доработку** | **принять** | **принять с замечаниями**
Режим: **полный** | **инкрементальный**
Проверено: <что открывалось, какие команды запускались>

| # | ID | Severity | Пункт | Находка | Где | Как проверить |
|---|---|---|---|---|---|---|
| 1 | card | blocker | A.1 | padding 12px вместо 16px | `ui/components/card.css:14` | evidence slice `div.card` |

## Что проверено и претензий нет
Короткий список — чтобы следующая итерация не перепроверяла всё заново.
```
