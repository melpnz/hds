# Общий контракт результата

## Предмет

Пакет знаний собирается обратной разработкой живого продукта, Figma и
опубликованных гайдов. Это карта того, что можно достоверно утверждать о
продукте сейчас, а не предполагаемая дизайн-система.

Есть два режима:

- новый пакет — источники есть, пакета нет; работа начинается с inventory;
- доработка — пакет уже есть; сначала обязателен audit свежего состояния.

Вид продукта определяет единицу работы:

| | Интерфейс | Лендинг |
|---|---|---|
| Признаки | сущности, листинги, состояния, повторяющиеся экраны | hero, CTA, маркетинговые секции, формы заявки |
| Единица | компонент → модуль → страница | примитив → блок → рецепт страницы |
| Ключевые примеры | страница на семейство | блок каждого типа и рецепты страниц |

## Факт, норматив и пробел

Каждое содержательное утверждение относится к одному классу:

- **факт** — DOM, computed styles, CSS, runtime/API, argTypes или узел Figma;
  указывается URL + selector, файл + строка либо node key;
- **норматив** — добавленная нами реализация отсутствующего, но необходимого
  поведения; помечается как новая и хранится отдельно от снятого;
- **GAP** — не подтверждено и не реализовано; в «Ограничениях» конкретно написано,
  чего не хватает.

Пустой раздел лучше правдоподобной догадки.

## Две равноправные проекции

Каждый принятый компонент, паттерн и принцип должен быть доступен:

1. человеку — в markdown-статье и живом примере;
2. модели — в `machine/*.json` под тем же стабильным идентификатором.

Если machine layer ещё строится отдельной волной, человекочитаемый источник
появляется сразу, а идентификатор резервируется для сборщика. К релизу обе
проекции обязаны сходиться валидатором.

## Границы

Пакет описывает только доступную для съёмки часть продукта. Закрытые экраны не
восстанавливаются по воображению; ограничение фиксируется в `README.md` и
`evidence/coverage.md`.

Не редактируй Figma, `career/` и `_sources/`. Не расширяй шаг соседними
улучшениями: добавь их в `ROADMAP.md`. Не отмечай работу выполненной без гейтов.
