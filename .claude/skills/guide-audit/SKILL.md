# Аудит существующего пакета

Читаешь [`.claude/guide/METHOD.md`](../../guide/METHOD.md) и
[`.claude/guide/guide-structure.md`](../../guide/guide-structure.md).

Задача: понять, **насколько пакет ещё правдив**, и превратить расхождения в план.
Ничего не чинишь по ходу — аудит только смотрит и пишет.

## 0. Определи объект и права

Пакет может быть read-only (замороженный пример вроде `career/`). Тогда отчёт кладётся в
`.audits/<пакет>-<дата>.md` в корне репозитория, внутрь пакета не пишется ничего.

Собери, что пакет **о себе утверждает**: `README.md` (статус, версия, границы),
`CHANGELOG.md` (дата последнего среза), `ROADMAP.md`, `components/manifest.json`
(число записей, статусы), `machine/index.json` (если есть — `coverage`, `generatedAt`).

## 1. Свежий срез источников

Не сверяй по памяти пакета. Свежий срез аудита кладётся в
`.pipeline/audit/<дата>/`, не поверх старого evidence. Если в этой папке
снимки ключевых страниц уже есть — не переснимай.

```bash
node <product>/tools/capture.mjs --url <url> --selector body --full-page \
  --name "<PageId>" --out .pipeline/audit/<дата>/<page-id> \
  --widths 320,768,1024,1400
```

Бери **выборку ключевых страниц**, а не всё подряд: по одной на семейство плюс те,
что менялись. Дополнительно — версия релиза продукта, если она видна в путях
к ассетам: расхождение версии само по себе повод пересчитать числа.

Figma: `get_metadata` по корню и `get_variable_defs` — состав и переменные
сейчас. `get_screenshot` — только если в этой папке аудита ещё нет снимков
нужных узлов.

## 2. Четыре сверки

**Актуальность.** Каждое проверяемое утверждение пакета — против свежего среза:
токены, геометрия, состав шапки, сетка, числа в текстах («18 компонентов»,
«121 переменная»). Числа, набранные руками, — первое, что устаревает.

**Полнота.** Что есть в источниках и нет в пакете: компоненты, состояния, страницы,
блоки, варианты. Отдельно — чего нет **у обеих сторон**, но что нужно для
генерации: usage, тексты, клавиатура, машинный слой.

**Целостность.** Внутренние ссылки, реестр против файлов, дубликаты записей,
статусы `complete` без покрытых состояний, утверждения без источника, расхождение
человекочитаемого и `machine/*.json`.

**Соответствие эталону.** Чего не хватает против
[`guide-structure.md`](../../guide/guide-structure.md): разделы гайда, разделы
статьи компонента, статьи принципов, паттерны страниц, машинный слой,
контракт `AGENTS.md`.

Если у пакета есть свои проверки (`tools/validate-*.mjs`, `check/run.py`) — прогони
их и вставь вывод в отчёт дословно.

## 3. Классификация находок

| Класс | Что значит | Куда ведёт |
|---|---|---|
| `устарело` | пакет утверждает то, чего в источнике уже нет | шаг на перемер |
| `не покрыто` | в источнике есть, в пакете нет | шаг на сборку |
| `противоречие` | пакет спорит сам с собой или с machine-слоем | шаг на согласование |
| `недоказано` | утверждение без источника | шаг на подтверждение или снятие |
| `лишнее` | в пакете есть, в продукте больше нет | шаг на удаление с пометкой legacy |
| `структура` | не хватает раздела против эталона | шаг на достройку |

У каждой находки — где (файл и строка или URL), чем подтверждается, и оценка
стоимости: `дёшево` (правка текста), `средне` (перемер одного элемента),
`дорого` (пересборка раздела).

## 4. План

Отчёт `.pipeline/audit-<дата>.md` (или `.audits/<пакет>-<дата>.md`):

```markdown
# Аудит <пакет> — <дата>

Срез источников: <какие страницы, какая версия продукта, состояние Figma>
Проверки пакета: <вывод команд>

## Итог одним абзацем
Чему в пакете можно верить сегодня, а чему нельзя.

## Находки
| # | Класс | Находка | Где | Подтверждение | Стоимость |

## План
| Приоритет | Шаг | Что делает | Закрывает находки |
| P0 | … | … | 3, 7, 12 |

## Что осталось верным
Список, чтобы следующий аудит не перепроверял всё заново.
```

Приоритеты: **P0** — пакет вводит в заблуждение (устаревшие числа, ложные
утверждения); **P1** — дыры, мешающие работать; **P2** — по требованию.

Строки плана дописываются в `ROADMAP.md` пакета как обычные шаги со статусом
`planned` — дальше их берёт обычный цикл. Для read-only пакета план остаётся
в отчёте и передаётся пользователю.

## Чего не делать

- Не править пакет по ходу аудита.
- Не верить внутренним числам пакета — пересчитывать.
- Не выдавать «мне кажется, устарело» за находку: у находки есть свежий срез.
- Не переписывать структуру эталона под то, что уже есть в пакете.
- Не переснимать один и тот же URL внутри одного аудита.
