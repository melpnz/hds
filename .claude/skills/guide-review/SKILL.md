# Шаг 3 — ревью

Читаешь [`.claude/guide/METHOD.md`](../../guide/METHOD.md) и
[`.claude/guide/review-checklist.md`](../../guide/review-checklist.md) и идёшь
по чеклисту. Ты **не правишь код**: ни одной правки, даже очевидной. Твой выход —
отчёт; правит шаг 4.

## Установка

Ты проверяешь работу, сделанную другим агентом, и относишься к ней недоверчиво.
Утверждение спецификации без источника — находка. Совпадение «на глаз» без числа —
не проверка. Если проверить нечем, так и пиши: «проверить не смог, потому что …» —
это честнее зелёной галочки.

## Что открыть до выводов

1. `.pipeline/<id>/capture.md` — что автор утверждает, что снял.
2. `evidence/source/production/<id>/` — уже лежащие `computed.json`, `dom.html`,
   именованные кропы (`CourseCard.320.png`, `CourseCard.1400.png`).
   **Не ходи на прод за новыми.** Числа — срезом по селектору, не файлом целиком.
   Full-page в чат не клади.
3. `evidence/source/figma/` — уже лежащие снимки и выписки узла. Figma MCP
   (`get_screenshot`, `get_metadata`, `get_variable_defs`) — **только если
   файлов нет**. Не снимай узел заново «для свежести».
4. Живой пример в витрине — открыть, а не прочитать:

```bash
node <product>/tools/serve.mjs &
# скриншоты витрины — только 320 и 1400, и только если их ещё нет
# в .pipeline/<id>/
```

5. Спецификацию, `ui/components/<id>.css`, запись в `manifest.json`.

Сравнение картинок делай **тройкой**: сохранённый прод ↔ сохранённая Figma ↔
наш пример. Числа бери из лежащего `computed.json` и computed styles нашего
примера, а не из глазомера и не с живого прода.

## Проверки

Полный список — в чеклисте: A соответствие источнику, B инварианты пакета,
C состояния и поведение, D responsive и устойчивость, E документация.

Обязательно выполняются руками, а не по описанию:

- копируемость — разметка из спецификации на пустой странице с одним
  `ui/<product>.css`;
- интерактив — hover, фокус клавиатурой, открытие/закрытие, disabled;
- ширины 320 / 768 / 1024 / 1400 — горизонтальный overflow и обрезка;
- прогон `node <product>/tools/validate-components.mjs --strict` — вывод в отчёт
  дословно.

## Отчёт

`.pipeline/<id>/review-N.md` (N — номер итерации), формат — в чеклисте. Требования
к находке: severity, пункт чеклиста, что не так с числами или скриншотами, где
(файл:строка или селектор), как воспроизвести.

Вердикт один из трёх:

- **вернуть на доработку** — есть blocker или major;
- **принять с замечаниями** — только minor; они уходят в roadmap строками;
- **принять** — находок нет.

Раздел «Что проверено и претензий нет» обязателен — по нему следующая итерация
не перепроверяет всё заново.

## Чего не делать

- Не править код, разметку, спецификации и manifest.
- Не выдавать пожелания за находки: «лучше бы» — это `note`, не `major`.
- Не проверять то, что в объём шага не входит.
- Не сглаживать: если элемент не воспроизводит продукт — это blocker, даже если
  вёрстка аккуратная.
- Не переснимать прод и Figma. Источник ревью — evidence на диске.
