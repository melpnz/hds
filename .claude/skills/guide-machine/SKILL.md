# Машиночитаемый слой

Читаешь [`.claude/guide/machine-layer.md`](../../guide/machine-layer.md) — там схемы
всех файлов, и [`.claude/guide/METHOD.md`](../../guide/METHOD.md).

Гайд читают двое: человек и модель. Этот шаг делает вторую проекцию — ту, по
которой интерфейс можно сгенерировать, а не только прочитать о нём.

## Принцип

Машинный слой **собирается из источников скриптом**, а не пишется руками рядом
с текстом. Руками пишется только то, чего скрипт снять не может — usage, тон,
названия, «когда не использовать», — и живёт в `machine/*.overrides.json`.

Ручная правка сгенерированного файла бессмысленна: следующая сборка её сотрёт.

## Порядок

### 1. Сборщик

`tools/build-machine.mjs` собирает из того, что уже есть в пакете:

| Файл | Из чего |
|---|---|
| `tokens.json` | `ui/tokens.css` — переменные со значениями, формат DTCG |
| `components.json` | `components/manifest.json` + спецификации + CSS + overrides |
| `rules.json` | таблицы правил из `docs/guide/composition.md` и `decisions.md` |
| `patterns.json` | статьи из `pages/` или `blocks/` |
| `content.json` | разделы «Название и текст» спецификаций + overrides |
| `index.json` | версия пакета, пути, команды проверок, границы покрытия |

Разметку в `components.json.markup.html` бери **из раздела «Разметка»
спецификации**, не переписывая: два разных HTML для одного компонента —
худший вид расхождения, потому что оба выглядят правдоподобно.

### 2. Overrides

`machine/components.overrides.json`, `machine/content.overrides.json` — то, что
живёт только словами: `usage.when`, `usage.whenNot`, `insteadUse`, правила
наименования, примеры хороших и плохих текстов. Ключ — `id` компонента.

### 3. Контракт AGENTS.md

В корне пакета — короткая инструкция для модели-потребителя: что читать в каком
порядке, как собирать экран (паттерн → области → модули → компоненты → тексты),
что брать буквально (`markup`, токены), чем проверять результат (`rules`), и где
граница знаний (`coverage.boundary`). Не длиннее страницы: это контракт,
а не пересказ гайда.

### 4. Валидатор

`tools/validate-machine.mjs` падает, если:

- `id` есть в JSON и нет в markdown или наоборот;
- `markup.html` не отрисовывается на пустой странице с одним `css` из `index.json`;
- токен из `tokens.json` не найден в CSS или значение разошлось;
- правило ссылается на несуществующий паттерн или компонент;
- исполнимый предикат правила не выполняется на витрине;
- числа в `coverage` разошлись с реальным содержимым пакета.

Проверку добавь в `npm test` и в гейты приёмки.

### 5. Проверка на пригодность к генерации

Финальная проверка — не формальная, а по существу: возьми `machine/` **без
markdown** и собери по нему простой экран продукта. Если для этого пришлось
подсмотреть в текст гайда — машинный слой неполон, и это записывается находкой:
чего именно не хватило.

## Отчёт

`.pipeline/machine-<дата>.md`: что собрано, сколько записей в каждом файле, что
пришлось положить в overrides, вывод валидатора, результат проверки на генерацию
и чего в слое всё ещё не хватает.

## Чего не делать

- Не писать JSON руками параллельно тексту.
- Не расширять схемы без нужды: лишнее поле, которое никто не заполняет, хуже
  отсутствующего.
- Не оставлять `markup`, который не проверялся отрисовкой.
- Не заявлять в `coverage` больше, чем покрыто.
