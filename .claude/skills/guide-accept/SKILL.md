# Шаг 5 — приёмка шага

Читаешь [`.claude/guide/METHOD.md`](../../guide/METHOD.md). Ты отвечаешь на один
вопрос: **шаг роадмапа действительно выполнен или нет**. Не улучшаешь, не чинишь,
не дописываешь — принимаешь или возвращаешь.

Приёмка — единственное место, где статус шага становится `done`, и единственное,
где появляется коммит.

## Гейты

Проверяются все, каждый — запуском или открытием файла, а не по чужому отчёту.

| # | Гейт | Как проверяется |
|---|---|---|
| 1 | Валидатор | `node <product>/tools/validate-components.mjs --strict` — код 0 |
| 2 | Браузерные проверки | `npm test` в пакете, если тесты заведены |
| 3 | Ревью закрыто | в последнем `review-N.md` нет открытых blocker и major; на каждую находку есть строка в `fix-N.md` |
| 4 | Реестр сходится | запись в `manifest.json` есть; `specPath`, `cssRoots`, `showcaseAnchor` существуют; строка в `INDEX.md` есть |
| 5 | Evidence на месте | `evidence/source/production/<id>/` со скриншотами и `computed.json`; для Figma — node key в `figmaEvidence` |
| 6 | Копируемость | разметка из спецификации на пустой странице с одним `ui/<product>.css` отрисовывается правильно |
| 7 | Соответствие exit criteria | условия волны из `ROADMAP.md` выполнены дословно |
| 8 | Честность статуса | `complete` только при покрытых обязательных состояниях; иначе `partial` с перечислением |

Гейт 3 не заменяется собственным ревью: если ревью не проводилось, шаг
не принимается по формальной причине «нет отчёта ревью».

## Вердикт

**НЕ ПРИНЯТО** — если упал хотя бы один гейт. В `.pipeline/<id>/accept.md` пишешь,
какие именно, с выводом команд, и что нужно сделать. Статус шага в `ROADMAP.md` —
обратно в `in-progress`. Ничего не коммитишь.

**ПРИНЯТО** — все гейты зелёные. Тогда, и только тогда:

1. Статус шага в `ROADMAP.md` → `done`, в колонку «Результат» — одна строка
   о том, что получилось; обнови таблицу «Текущий прогресс».
2. В `CHANGELOG.md` пакета, в раздел `## Unreleased`, — запись о шаге: что
   изменилось и почему, а не перечисление файлов.
3. `.pipeline/<id>/accept.md` — вердикт, вывод гейтов, дата.
4. Коммит по конвенции [`VERSIONING.md`](../../../VERSIONING.md):

```bash
git add -A
git commit -m "<product>: <шаг> <Элемент> — принят" -m "<чем подтверждён>"
```

Один шаг — один коммит. Если конвейер прошёл несколько шагов без коммитов, коммить
их по одному в порядке роадмапа, а не одной кучей.

## Граница волны

Когда принят последний шаг волны, проверь exit criteria волны целиком и напиши
в `.pipeline/wave-<id>.md` короткий итог: что закрыто, что перенесено, чего не
хватает для следующей волны. Волна с невыполненными exit criteria не закрывается,
даже если все её шаги приняты по отдельности — это сигнал, что критерии были
шире шагов, и он важнее удобства.

## Релиз пакета

Если закрытие волны меняет пригодность пакета к работе, предложи релиз по
`VERSIONING.md`: `## Unreleased` → `## vX.Y — дата`, статус в `README.md`, коммит,
аннотированный тег `<product>-vX.Y`. Решение о релизе — за пользователем, тег сам
не ставь без подтверждения.

## Чего не делать

- Не принимать «в целом нормально»: гейт либо зелёный, либо нет.
- Не чинить найденное — это шаг 4.
- Не коммитить при не пройденных гейтах.
- Не ставить теги без подтверждения пользователя.
