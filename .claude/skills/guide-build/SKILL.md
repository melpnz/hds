# Шаг 2 — снять и сверстать

Сначала прочитай [`.claude/guide/METHOD.md`](../../guide/METHOD.md) и
[`.claude/guide/spec-template.md`](../../guide/spec-template.md). Образец готового
результата — `career/components/` и `career/ui/`; править внутри `career/` нельзя.

Работаешь **над одним элементом** — тем, что назван в шаге роадмапа. Соседние
проблемы не чинишь: записываешь в конец `ROADMAP.md` как новую строку `planned`.

## 1. Собери контекст элемента

Из `.pipeline/inventory.json` возьми запись: источники, селекторы, node keys,
зависимости. Убедись, что все `dependsOn` уже `done` — если нет, останавливайся
и говори, чего не хватает: собирать компонент на несобранных зависимостях нельзя.

## 2. Сними факты с продакшена

```bash
node <product>/tools/capture.mjs --url <url> --selector "<selector>" \
  --out <product>/evidence/source/production/<id> --widths 375,768,1024,1440
node <product>/tools/capture.mjs --url <url> --selector "<selector>" --state hover \
  --out <product>/evidence/source/production/<id>-hover
```

Сними каждое состояние, которое достижимо: hover, focus-visible (клавиатурой),
disabled, open, loading — отдельным запуском или интерактивно через браузер.
Что снять не удалось — это будущий GAP, а не повод дорисовать.

Из `computed.json` возьми геометрию и типографику, из `tokens.json` — переменные
`:root`. Найди в сборке продукта CSS-правила компонента (сетевые ответы `.css`,
поиск по корневому классу) — правила нужны текстом, а не пересказом.

## 3. Сверься с Figma

`mcp__figma__get_metadata` — состав и структура узла; `get_variable_defs` — имена
переменных; `get_screenshot` — эталон внешнего вида; `get_code_connect_map` — если
у продукта есть привязка к коду. Ничего не редактируй.

Figma даёт внешний вид, состав, варианты и responsive-намерение. Семантику, API и
имя берёшь из прода и HTML (METHOD.md §3). Расхождение прода и Figma не сглаживай —
это запись в «Ограничения» со ссылкой на обе стороны.

## 4. Свёрстывай

- Токены — в `ui/tokens.css`: только те, что реально используются, со значениями
  из `:root` прода. Новых переменных не изобретай.
- CSS компонента — секцией в `ui/components/<id>.css`, подключённой из
  `ui/<product>.css`. Значения через `var(--…)`; литерал допустим, только если
  в проде литерал, и тогда это отмечается в спецификации.
- Иконки и шрифты — локальные копии в `ui/assets/`; в разметке спецификации пути
  локальные. Продовые URL остаются только в «Анатомии» как протокол снятого DOM.
- Разметка обязана работать на пустой странице с одним `ui/<product>.css`.
  Проверь это буквально: временный html в `.pipeline/<id>/copy-check.html`, открыть
  через `node tools/serve.mjs`, посмотреть, удалить.
- Состояния, которых в проде нет, но без которых компонент не собрать, пиши
  в `ui/state-contract.css` и помечай как новую реализацию.

## 5. Спецификация

По шаблону, разделы в фиксированном порядке. Каждый факт — с источником; раздел,
которому нечем подтвердиться, не пишется. Пиши на языке пакета (у `career/` — русский).

Файл: `<product>/components/<category>/<id>.md`.

## 6. Живой пример в витрине

Добавь секцию в `showcase/components.html` с якорем `c-<id>`: сам компонент
настоящей вёрсткой, все состояния и варианты, каждое подписано. Оболочка витрины —
только классы витрины с её префиксом, в `ui/` она не протекает.

## 7. Реестр

Добавь запись в `components/manifest.json` со всеми обязательными полями
(`id`, `canonicalName`, `storybookNames`, `legacyAliases`, `category`, `kind`,
`specPath`, `cssRoots`, `showcaseAnchor`, `figmaEvidence`, `status`, `requiredStates`)
и строку в `components/INDEX.md`. Статус ставь честно: `complete` — только если
покрыты все обязательные состояния; иначе `partial` с перечислением непокрытого.

## 8. Проверь себя перед сдачей

```bash
node <product>/tools/validate-components.mjs --strict
```

Плюс глазами: открой витрину на 375 и 1440, сравни со скриншотами прода и Figma.
Очевидные расхождения чини сам — ревью не место для того, что видно сразу.

## 9. Отчёт

`.pipeline/<id>/capture.md`: что снято (URL, селекторы, состояния, node keys),
какие файлы evidence появились, какие решения приняты при конфликте источников,
что осталось неподтверждённым.

В финальном сообщении: что сделано, какие файлы изменены, что не удалось снять и
почему, статус в manifest и результат валидатора — дословно, включая падения.

## Чего не делать

- Не выдумывать ARIA, состояния и props, которых нет в источниках.
- Не переносить в пакет фреймворк-атрибуты (`data-v-*`, скоупы, хеши).
- Не расширять шаг на соседние компоненты.
- Не ставить `complete`, когда состояния не покрыты.
- Не трогать `career/` и `_sources/`.
