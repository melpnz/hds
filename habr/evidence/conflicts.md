## CFL-1 · Радиус текстового поля: 4px (production) vs крупнее на вид (Figma)

| | |
|---|---|
| **Thing** | Радиус скругления текстового поля |
| **Production** | `.tm-input-text-decorated__input{border-radius:4px}` — реальный класс, используется на странице поиска (`search-7QaR2PSY.css`) и в навигации (`navigation-search-BPZh-5Ba.css`) |
| **Storybook/source** | нет: `Input` не входит в 12 покрытых компонентов |
| **Figma library** | `habr-lib` → `textfileds` → `Input` (status/filled matrix, 10 состояний), радиус визуально крупнее 4px по превью, точное значение не снято (не запрашивал `get_design_context` ради экономии токенов) |
| **Figma screens** | не проверялось |
| **Interpretation** | Figma design intent, вероятно, задаёт более округлый инпут, чем показывает production; либо разница — оптический эффект превью и реальное значение совпадает |
| **Canonical choice** | **CURRENT = 4px**, по правилу иерархии для implementation/geometry (source/production выше Figma library) |
| **Why** | `.tm-input-text-decorated` — реально используемый, реально отрендеренный класс на двух живых страницах; Figma-радиус не измерен инструментально, только на глаз |
| **Confidence** | HIGH по значению 4px; LOW по тому, действительно ли Figma расходится — это не подтверждённый конфликт, а недосмотренный |

**ЗАКРЫТО на этапе Figma Library Extraction pass.** `get_variable_defs`
на Figma-узле Input дал `elements/txtfield/radius=4` — дословное совпадение
с production. Это был не конфликт, а недосмотр (радиус не измерялся
инструментально раньше). Статус: **MATCH**, confidence HIGH по обеим
сторонам. `.tm-input-text-decorated` также наконец перенесён в `ui/` —
см. `components/forms/field.md`.

## CFL-2 · Наименования вариантов кнопки: Storybook vs Figma library

| | |
|---|---|
| **Thing** | Имена цветовых/семантических вариантов кнопки |
| **Production** | классы-модификаторы: `.btn_solid` / `.btn_transparent` / `.btn_text` (форма), `.tm-button_color-christi` (зелёный/успех), `.tm-button_color-fuzzy-wuzzy-brown` (опасность) — имена от названий цветов, не от роли |
| **Storybook/source** | те же классы; story называются `Default` / `Transparent` / `Text` / `Disabled` / `Loading` / `As Link` — нейтрально, без ролей |
| **Figma library** | `habr-lib` → `button` → **Primary-fill / Primary-line / Success-fill / Success-line / Danger / Minor / icon-button** — ролевые имена, плюс отдельная `focus`-стадия для каждого варианта, которой нет в живых story |
| **Figma screens** | не проверялось |
| **Interpretation** | одна и та же геометрия и одни и те же токены, но **два параллельных словаря имён**: production кодирует *цвет* (`christi`, `fuzzy-wuzzy-brown`), Figma кодирует *роль* (`Success`, `Danger`). Figma также содержит `focus` state, не пойманный ни в одном snapshot |
| **Canonical choice** | спецификация компонента использует **оба имени явно**: заголовок варианта — ролевое (Success/Danger), в скобках — реальный CSS-класс с цветовым именем. `focus` фиксируется как **FIGMA TARGET**, не CURRENT: живого CSS-правила `:focus-visible` с явным контуром в извлечённом срезе не найдено (только `outline:none` на `:hover,:focus,:active`) |
| **Why** | оба словаря реальны и оба нужны: разработчик ищет по классу, дизайнер — по роли; state `focus`, которого нет в CSS, нельзя тихо приписать production |
| **Confidence** | HIGH по именам; MEDIUM по тому, что `focus` вообще не реализован — не проверено на живой клавиатурной навигации |

**Дополнено после разбора палитры.** «Цветовой словарь» перестал быть
загадкой: это не произвольные имена, а **прежние названия токенов** до
перехода на семантические (поле «Старое» в палитре Figma):

| Класс в production | Старое имя цвета | Сегодняшний токен |
|---|---|---|
| `.tm-button_color-christi` | `christi` | `--accent-positive` |
| `.tm-button_color-fuzzy-wuzzy-brown` | `fuzzy-wuzzy-brown` | `--accent-danger` |
| `.tm-button_color-desert-storm` | `desert-storm` | `--background-secondary` |

Отсюда следует, что ролевые имена Figma (Success / Danger / Minor) и
цветовые имена классов — не два независимых словаря, а **два поколения
одного**: `Success` = `christi` = `--accent-positive`. Три пары выше —
единственные, что нужны для кода: только они живут в именах классов
production. Остальной исторический словарь из пакета удалён как ненужный.

| | |

| **Thing** | Что вообще значит «вариант чипа» у Habr |

## CFL-5 · Цвет ошибки формы: бледно-розовый (production) vs насыщенный красный (Figma)

| | |
|---|---|
| **Thing** | Цвет текста/рамки ошибки текстового поля |
| **Production** | `.error{color:var(--header-megapost-mona-lisa)}` — реальный, отрисованный класс `search-7QaR2PSY.css` (`/search/`), `--header-megapost-mona-lisa = hsl(5,100%,80%)` — бледно-розовый |
| **Figma library** | `habr-lib` → `textfileds` → Input: `elements/txtfield/hint_error=#d04e4e` — насыщенный красный, почти дословно совпадает с `--accent-danger = hsl(0,58%,56%) ≈ #cb5252` |
| **Interpretation** | Два реальных, но разных значения — не опечатка сканирования: одно взято из живого рендера, другое — из активной Figma-переменной. Похоже, что `--accent-danger` — предполагаемый общий токен ошибки для форм, а `--header-megapost-mona-lisa` — использован в конкретном компоненте `/search/` как локальное решение (возможно, до унификации токенов ошибки, возможно — намеренно другой, более мягкий акцент для non-blocking подсказки) |
| **Canonical choice** | **CURRENT = production (`--header-megapost-mona-lisa`)**, по правилу иерархии источников — это то, что реально показывается пользователю. Figma-значение зафиксировано отдельно, не как исправление |
| **Why** | Один-единственный найденный production-пример важнее непроверенного design-intent; переименовывать/подменять реальный цвет на Figma-red было бы усреднением |
| **Confidence** | MEDIUM — единственный production-пример, не проверено на других формах (их не найдено) |

**Усилено после разбора палитры (Figma `habr-lib`, node 3766-12196).**
Палитра прямо описывает назначение обоих цветов, и они не пересекаются:

* `--accent-danger` — «ошибки и предупреждения: текст, обводки,
  информаторы ошибок…» — то есть ошибка формы это **его** роль;
* `--header-megapost-mona-lisa` — «текст в хедере мегапостов, ховер
  заблокированных чипсов-хабов, кнопки и иконки» — про ошибки ни слова.

То есть production на `/search/` использует **не тот токен, который
палитра закрепляет за ошибками**. Это перестаёт выглядеть как
«дизайнеры хотели мягче» и становится похоже на легаси/недосмотр в одном
компоненте. Canonical choice не меняем (production остаётся тем, что
видит пользователь), но confidence по интерпретации повышается:
**расхождение реально, а не кажущееся**. Полные назначения обоих
токенов — `ui/themes/README.md`.

## CFL-6 · Иконки: production-спрайт vs дизайн-библиотека — два разных набора

| | |
|---|---|
| **Thing** | Состав, имена и рисунок иконок |
| **Production** | `ui/assets/icons/megazord.svg` — 138 символов, побайтово идентичен `/img/megazord-v28.svg?2.346.1`. Разобран в `icons/single/`, где символов **126**. Удалено двенадцать: шесть неиспользуемых (`counter-views-filled`, `complexity-low-2`, `edit`, `trash`, `rt-dc-desktop-mask`, `rt-dc-mobile-mask`) и шесть дублей, разрешённых попарно (`input-search`, `icon-report`, `bookmark`, `sorting-down`, `header-burger-v2`, `collapse_pin` — см. `evidence/icon-dupes.json`). После этого **дублей внутри набора не осталось ни одного**. Расхождение с `megazord.svg` намеренное: сам файл не правится, он свидетельство |
| **Дизайн-библиотека** | `ui/assets/icons/library/` — 143 файла, переданы пользователем напрямую (не CDP, не Figma MCP) |
| **Пересечение** | 72 общих имени: 70 совпадают по path дословно, 2 — одно имя, разный файл. Было 77/7: пять пар (`copy`, `dots`, `mail`, `placeholder-company`, `search`) оказались одной и той же иконкой в другой кодировке `path` и удалены из `library/` как дубли — расхождением дизайна они не были |
| **Interpretation** | Это НЕ один набор в двух форматах. (1) **Нейминг**: production `snake_case`, библиотека `kebab-case`, часть имён отличается целиком — **19 пар**, найдены растеризацией (хеш `path` давал только 13, шесть пар пропускал). По смыслу они не угадываются: `all`→`set`, `persona`→`human_resources`, `embed`→`pin`. (2) **Состав**: в библиотеке **49 рисунков**, которых в спрайте нет вообще — это **набор редактора статей (WYSIWYG), подтверждено владельцем пакета**. Он же объясняет нулевое использование при обходе: редактор доступен только авторизованному автору. (3) **Состояния, а не расхождение**: `counter-favorite` и `counter-vote` выглядели расхождением, но это два состояния одного элемента. В спрайте пара лежит явно: базовое имя — контур, `-filled` — заливка (так у четырёх элементов: `counter-favorite`, `counter-views`, `counter-vote`, `notifications`). Библиотека знает этот суффикс — `notifications-filled` в ней есть, — но у `counter-favorite` и `counter-vote` кладёт под базовым именем **залитое** состояние, отрисованное своими путями. Непоследовательна сама библиотека, конфликта дизайна нет |
| **Canonical choice** | **Для разметки — имя из спрайта**: только оно резолвится в `<use xlink:href="…#name">`. Библиотека — источник картинки и полноты набора, не имён. Наборы хранятся раздельно, не сливаются |
| **Why** | Слить их в одну папку — потерять гарантию «всё здесь реально отдаёт production», которая сейчас есть у `icons/single/` |
| **Confidence** | HIGH. Прежняя пометка «UNCERTAIN — что новее у `counter-*`» **снята**: это были не конкурирующие версии одного рисунка, а два состояния элемента, и выбирать между ними не нужно. Практическое правило: имена берутся из спрайта, базовое — контур, `-filled` — заливка |

## CFL-8 · Пагинация: production на 1–2px меньше Figma по шести свойствам

| | |
|---|---|
| **Thing** | Метрики `Pagination` — радиус, начертание, интерлиньяж, высота контейнера, его поля, размер иконки |
| **Production** | радиус 3, начертание 500, интерлиньяж 18px, высота 49, поля `0 2px`, иконка 16 (+8 отступа = 32). Снято с живой `habr.com/ru/articles/page7/` через `getComputedStyle` и `CSS.getMatchedStylesForNode` |
| **Figma library** | `habr-lib` → `pagination` (690:6046): `radius` 4, `weight/regular` 400, `line_height/body_l` 20, высота фрейма 48, `padding_between` 6, `iconsize/x1` 24 |
| **Interpretation** | Не одно расхождение, а систематический сдвиг на один шаг: Figma описывает компонент, собранный на общих токенах (радиус 4, интерлиньяж 20, иконка 24), production — реализацию, которая до этих токенов не доведена. Совпало при этом всё содержательное: **32×32 у страницы, цвета всех четырёх состояний, подписи «Сюда»/«Туда», состав списка страниц** — то есть расходится только шлифовка |
| **Canonical choice** | **Production.** В `ui/components/pagination.css` оставлены боевые значения; шесть Figma-значений записаны таблицей в `components/navigation/pagination.md` и в витрине |
| **Why** | Пакет описывает то, что действительно отрисовано на habr.com. Применить Figma-числа — получить файл, который ни один production-скриншот не воспроизводит, при том что визуальная разница ≤2px |
| **Confidence** | HIGH по обеим сторонам: production измерен на живой странице, Figma прочитана через `get_variable_defs` (значения выведены переменными, не сняты пипеткой) |

### Сюда же — два факта, которые конфликтом НЕ являются, но выглядят как он

**1. Стрелка серая вместо акцентной — артефакт нашей сборки, не продукта.**
`.tm-pagination__arrow{fill:var(--icon-primary)}` на habr.com не срабатывает
никогда: одинаковая специфичность с `.tm-svg-img{fill:currentColor}`, а
`svg-img` грузится позже. У нас `icon.css` импортируется раньше
`pagination.css` — каскад перевёрнут, и дословно перенесённое объявление
начинало работать. В `pagination.css` теперь `fill: currentColor` явно.
Тот же класс ошибки, что коллизия `.body` в `dropdown.css` (см. CFL-2):
**мы ломаем не тем, что читаем CSS неверно, а тем, что складываем файлы
в другом порядке.**

**2. Глобальный `border-box` в витрине искажал продукт.**
В `showcase/*.css` стоял `* { box-sizing: border-box }`. На habr.com
глобального сброса нет — замерено на живой странице: **2702 элемента из
2847 (95%) — `content-box`**, `border-box` расставлен точечно самими
компонентами (145 элементов). Под навязанным сбросом
`.tm-pagination__page` схлопывалась с 32×32 до 24×32 (переставала быть
квадратной), а `.tm-pagination__arrow` — с 32×32 до 16×16, где на контент
не оставалось ничего и иконка выглядела пропавшей. Сброс ограничен
классами `doc-*`. Проверено диффом геометрии 349 продуктовых элементов
витрины до и после: изменились 14, все — пагинация и `.tm-bordered-card`,
и все в сторону production-значений.

## Не конфликты (проверено и совпало)

Для протокола — что именно совпало и поэтому конфликтом не является:

* **Темы**: `light-v2.css` / `dark-v2.css` в `_sources/habr/source/css/` побайтово идентичны live `assets.habr.com` — сверено `diff`.
* **Sticky-шапка**: `.tm-header{position:sticky}` подтверждена и в статическом CSS, и в `getComputedStyle` на живой странице (`position: sticky`, высота 56/48).
* **Брейкпоинты оболочки**: 767/768 и 1023/1024 — дважды подтверждены (перепись 19 уникальных width-условий по всем 101 файлам **и** прямой просмотр `.tm-header{height:48px}` внутри `@media (max-width:767px)`).
* **Storybook = production по хэшам** — заявлено пользователем как доказанное для этого релиза, повторно не проверялось.
