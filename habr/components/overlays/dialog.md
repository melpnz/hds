## Назначение

Модальное окно продукта. Единственный компонент выборки с прямо
подтверждённой **responsive-трансформацией макета**, а не просто сжатием:
на широких экранах — центрированное окно, на узких — нижняя шторка
(bottom sheet).

## Анатомия (десктоп, из `rendered/dialog--minimal.html`)

```html
<div class="tm-overlay" style="--modal-window-width: 320px;">
  <div class="tm-overlay__background"></div>
  <div class="tm-overlay__inner">
    <div class="modal-window-wrapper">
      <div class="modal-window">
        <header class="header">
          <div class="dialog-header">
            <div class="dialog-title">Заголовок</div>
          </div>
        </header>
        <main class="body">
          <div class="dialog-body">Контент диалогового окна</div>
        </main>
        <footer class="footer">
          <div class="dialog-footer">
            <button class="btn btn_transparent btn_small tm-button_color-horizon" type="button">
              Закрыть
            </button>
          </div>
        </footer>
      </div>
    </div>
  </div>
</div>
```

Обратите внимание: `<header>`/`<main>`/`<footer>` — настоящие семантические
теги, не `<div>`. Кнопка действия по умолчанию — вариант Button `.btn_text.
tm-button_color-horizon` (текстовая кнопка-ссылка).

## Мобильная раскладка (bottom-drawer)

```html
<div class="bottom-drawer-inner" aria-hidden="false">
  <div class="overlay"></div>
  <div class="sheet">
    <div class="drag-area"><div class="drag-handle"></div></div>
    <header class="header with-divider">…</header>
    <div class="main"><div class="main-inner">…</div></div>
    <footer class="footer with-divider">…</footer>
  </div>
</div>
```

`.sheet` перетаскивается за `.drag-area` (`cursor: grab`), получает тень
только в диапазоне 768–1023 (`.sheet{box-shadow:…}` внутри
`@media (min-width:768px) and (max-width:1023px)`).

## Варианты

| Класс | Эффект |
|---|---|
| `.dialog-title.no-body` | заголовок без нижнего паддинга — когда тела нет |
| `.header.scrolled` / `.footer.scrolled` | появляется разделительная линия при прокрутке содержимого |
| `.cover-image` | картинка-обложка 140px сверху, со скруглением как у окна |
| `.base-dialog-drawer` | обнуляет паддинги шторки — `dialog-title/-body/-footer` берут их на себя |

## Полоски — индикатор, а не рамка

**Разделители под шапкой и над подвалом появляются только когда тело
прокручивается.** Это не оформление, а признак обрезанного контента: нет
скролла — нет полосок. В коде за это отвечают отдельные классы-состояния
(`.scrolled` в окне, `.with-divider` в шторке), то есть переключает их
рантайм, а не медиазапрос.

Figma подтверждает ровно это же: у компонента `modal` полоски вынесены в
отдельные булевы свойства, независимые от остальной композиции. Цвет
совпадает дословно: Figma `elements/modal/border` = `#929ca566`, в CSS —
`--icon-primary` с альфой 40%.

**Картинка (`.cover-image`) необязательна**, а тело принимает произвольный
контент — в Figma это слот «надшапкой» и слот тела соответственно.

## Расхождения Figma ↔ production (не усреднены)

| Свойство | Figma (`modal`) | Production (`dialog.css`) |
|---|---|---|
| Радиус окна | 8 | 8 — совпадает |
| Радиус шторки | 8 8 0 0 | **16 16 0 0** |
| Ручка шторки | 64×4, радиус 2 | 64×4, **радиус 8** |
| Паддинг шапки | 16 / 20 | **18 20 16** (`.dialog-title`) |
| Паддинг подвала | 20 десктоп / 16 мобайл | 0 20 20 + `margin-top:20` |
| Цвет полосок | `#929ca566` | `--icon-primary` / 40% — то же самое |
| Планшет | = десктоп, центрированное окно | тень у **шторки** на 768–1023 |

В `showcase/components.html` заверстаны **production-значения**.

**Планшет — содержательный конфликт**, см. `evidence/conflicts.md` CFL-7:
Figma говорит, что на планшете то же центрированное окно, а production даёт
тень именно шторке в диапазоне 768–1023, что осмысленно только если на
планшете показывают шторку. Брейкпоинт переключения по-прежнему GAP, но
показаний теперь два и они расходятся.

## Ширина

`--modal-window-width` — inline CSS-переменная. Story `Minimal` задаёт
**320px** (`style="--v52269707: 320px"` в rendered snapshot) — это значение
аргумента конкретной story, **не подтверждённый продуктовый дефолт**: живого
Dialog в production не найдено. Использовать 320 как отправную точку,
не как факт.

## Поведение

* подложка `.tm-overlay__background` — `transform: scaleY(2) translateY(-25%)`
  и переход `.3s` — растягивается за пределы экрана заранее, вероятно, чтобы
  избежать видимого края при быстрой прокрутке;
* `.sheet:not(.is-dragging)` анимируется `all .5s ease-in-out`, во время
  перетаскивания (`.is-dragging`) анимация отключается — типичный паттерн
  «плавно едет само, резко следует за пальцем»;
* GAP: конкретный брейкпоинт переключения между `.modal-window` и
  `.bottom-drawer-inner` не найден в CSS — переключение, судя по всему,
  решает JS. Единственный связанный факт в CSS — тень шторки в 768–1023.

## Responsive

| Ширина | Что известно |
|---|---|
| ≤767, вероятно и 768–1023 | bottom-drawer, тень появляется на 768–1023 |
| ≥1024, вероятно | modal-window по центру |

Формулировка «вероятно» — намеренная: сам переключатель не подтверждён
CSS, только следствия (тень).

## Доступность (наблюдаемое)

`.bottom-drawer-inner[aria-hidden]` управляет видимостью и
`pointer-events`. Других ARIA-атрибутов не наблюдалось.

## Ограничения

* брейкпоинт переключения desktop/mobile раскладки — GAP;
* ширина по умолчанию — GAP (только значение story);
* `.variant-hub` popover, `icon-button near-textfield` и подобные соседние
  детали не входят — см. отдельные спеки.

## Исправлено в Figma Parity Audit

**Возвращено оформление скроллбара шторки** — четыре правила
`.bottom-drawer-inner .main::-webkit-scrollbar*`, потерянные при
извлечении (псевдоэлементы `::-webkit-scrollbar` не попали в перенос).
Без них в шторке рисовался системный скроллбар. Приём в проде
нетривиальный и стоит его знать: thumb по умолчанию с альфой **0%** —
невидим, но место занимает, а проявляется при наведении на `.main`,
поэтому появление прокрутки не дёргает раскладку.

**Убран фолбэк ширины окна.** Было `width: var(--modal-window-width, 320px)`,
стало `var(--modal-window-width)` без второго аргумента — как в проде
(`width: var(--v52269707)`). 320px — ширина аргумента конкретной
Storybook-story, а не продуктовый дефолт; фолбэк давал поведение,
которого в проде нет. **Ширину задаёт потребитель**, инлайновой
переменной в разметке.

Имя переменной у нас читаемое намеренно: production-имя
(`--v52269707`) генерирует Vue, оно меняется от сборки к сборке. Плата
за это — разметка не переносима между нашим CSS и продовым дословно:
скопированный из прода `style="--v52269707: 320px"` наш CSS не увидит.
Это осознанный размен, а не недосмотр.
