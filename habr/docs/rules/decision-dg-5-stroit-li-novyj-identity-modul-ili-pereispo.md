### DG-5 · Строить ли новый identity-модуль или переиспользовать существующий

**OBSERVED.** Три существующих identity-модуля (hub/user/company) — разные
компоненты с разными полями, не один параметризуемый (EN-5).

**Context/When.** Нужна identity-карточка для сущности, отличной от
хаба/пользователя/компании.

**Prefer.** Проектировать новый модуль по **композиционному принципу**
DG-4 (расположение, наличие действия рядом), не пытаться подогнать под
код одного из трёх существующих. Три существующих — не интерфейс для
наследования, а три независимых свидетельства одного паттерна.

**Avoid.** Объединять `hub-card`/`user-card`/`company-profile-card` в общий
«EntityCard» без отдельной проверки — pattern-taxonomy прямо предупреждает
против этого.

**Evidence.** EN-5. **Confidence: MEDIUM**
