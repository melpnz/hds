### DG-2 · Публичный листинг: article-like feed или directory

**OBSERVED.** Habr использует два разных каркаса для списков: `ArticleCard`-
фид, когда сущность — контент (FD), и уникальную карточку на каждый тип,
когда сущность — directory-объект: хаб/компания/автор (DR-2).

**Context/When.** Новый листинг из N однотипных сущностей.

**Prefer.** Спросить: элемент списка — это контент (публикация) или
directory-запись (сущность, у которой есть профиль)? Если контент —
переиспользовать `ArticleCard` целиком, не проектировать новую карточку.
Если сущность — новая карточка ожидаема, Habr не требует единого шаблона
для directory-карточек.

**Avoid.** Пытаться впихнуть directory-сущность в `ArticleCard` ради
переиспользования — наблюдение прямо показывает, что Habr так не делает.

**Evidence.** FD-1, DR-1, DR-2. **Confidence: MEDIUM-HIGH**

**GAP.** Нет примера, где один и тот же listing показывает оба типа
элементов вперемешку — неизвестно, предусмотрен ли для этого паттерн.
