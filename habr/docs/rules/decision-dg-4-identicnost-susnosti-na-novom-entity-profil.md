### DG-4 · Идентичность сущности на новом entity/profile экране

**OBSERVED.** Identity-карточка — вверху главной колонки, не в сайдбаре
(EN-1), с действием прямо на карточке (EN-4). Повторено в admin (EN-2).
Сайдбар несёт вторичные факты, не идентичность (EN-3).

**Context/When.** Новый экран, показывающий профиль/карточку сущности
(человека, организации, продукта).

**Prefer.** Для нового entity-экрана начинать с identity вверху главной
колонки, **если** структура сущности сопоставима с наблюдаемыми (есть
аватар/лого, есть счётные метрики вроде рейтинга/подписчиков, есть
основное действие типа подписки). Класть вторичные факты (характеристики,
специализацию) в сайдбар.

**Avoid.** Переносить сюда Career-паттерн P-1 (идентичность **в левом
сайдбаре**) — Habr делает ровно наоборот, и путаница между двумя методами
здесь особенно вероятна.

**Evidence.** EN-1, EN-2, EN-3, EN-4. 3 production + 1 Figma-кросс-
подтверждение. **Confidence: HIGH**

**GAP.** Сущность без метрик/подписки (например, чисто контентная
коллекция без счётчиков) не наблюдалась — неизвестно, применим ли паттерн.
