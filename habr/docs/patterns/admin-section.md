### 9.1 · Admin section screen (dashboard-lite)

| | |
|---|---|
| **Наблюдений** | 1 полный экран (Биллинг), структура навигации — Figma-компонент с 6 секциями |
| **Confidence** | MEDIUM-HIGH (один полный скриншот, но композиция самосогласованна и перекрёстно подтверждена именами) |
| **Статус** | **CONFIRMED** (Figma) |

**Layout regions.** Стандартная шапка Habr (та же, что в public — логотип,
поиск, колокольчик, аватар) → identity-карточка компании (см. §6, тот же
приём) → **горизонтальные Tabs шести секций** (Статистика/Публикации/
Компания/Биллинг/Настройки/FAQ — тот же компонент `Tabs`, что в public) →
главная колонка: контентные карточки раздела (заголовок + описание +
условное состояние/форма) → правый сайдбар: **вторичный список** (карточка
с построчной навигацией внутри раздела, активный пункт — левая полоса
акцентным цветом + счётчик) + виджет «Новости Хабра» (та же карточка,
что и в public — заголовок + список ссылок с описанием).

**Reusable modules.** `Tabs` (переиспользован без изменений), `Block`
(вероятно, контентные карточки — не проверено на уровне кода), `Notice`
(информационное сообщение о заявке — похоже на `tm-notice_info`, не
подтверждено кодом, Figma-only), Button (зелёный «Запросить бронь» —
подтверждает Success-роль как основную CTA в admin).

**Primary actions.** Зелёная кнопка-действие рядом с описанием услуги —
тот же принцип «действие рядом с тем, к чему относится», что в §6.

**Responsive.** Не подтверждено — GAP (Figma не давала mobile-версию
именно этого экрана).

**States.** Явно показано состояние «запрос отправлен, ждём менеджера»
(информер вместо формы) вместо «услуга доступна» (форма + кнопка) —
两 разных состояния одного и того же блока услуги, качественное
свидетельство state-driven content.
