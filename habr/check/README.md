# check — проверки пакета

Пакет держится на одном утверждении: **всё, что здесь написано, замерено,
а не придумано**. Проверить это глазами нельзя — числа устаревают молча,
и это уже случалось: «18 компонентов» пережило три прохода работы, а
`Counter 13/16` пролежал ошибкой, пока его не перемерили.

Отсюда правило: **любое число в текстах пакета приходит из
`check/counts.py`**, а не набирается руками.

```
python check/run.py              все проверки
python check/run.py --offline    без браузера и сети
```

Возвращает ненулевой код при первой найденной ошибке — годится для
pre-commit и CI.

## Что проверяется

| Скрипт | Что ловит |
|---|---|
| `counts.py` | считает всё, что пакет о себе утверждает: компоненты, правила, иконки, токены, секции витрины. Плюс внутренняя согласованность — секций столько же, сколько пунктов навигации; токенов в light столько же, сколько в dark |
| `links.py` | битые markdown-ссылки и пути в backticks. Имена production-артефактов (`button-Ccclp6vQ.css`) отсеиваются по `allowlist.json` — их в пакете нет намеренно |
| `coverage.py` | класс есть в разметке витрины, но объявления нет нигде (копирующий получит не то, что видел); класс объявлен, но не показан ни одним примером — такие должны быть перечислены в секции «Новое» |
| `claims.py` | значения, процитированные в спецификациях, против настоящего CSS. Ловит спеку, отставшую от кода |
| `showcase.js` | отрисовка в настоящем браузере: висячие `<use>`, нулевые SVG, битые картинки, горизонтальное переполнение на 320/480/768/1024/1100/1440 |
| `parity.js` | **главная проверка**: собственные правила классов на живом `habr.com` против наших объявлений. Различия в форме записи (`.5rem` против `0.5rem`, `transparent` против `0 0`) нормализуются — они не меняют вычисленное значение |

## Что нужно для запуска

Статические проверки — только Python 3. Две последних ходят в браузер:

```
chrome --headless --remote-debugging-port=9333
```

Порт переопределяется через `CHROME_PORT`. Если Chrome не отвечает,
проверка сообщает «ПРОПУЩЕНО» и не роняет запуск: отсутствие инструмента
— не ошибка пакета. `parity.js` дополнительно требует сети — он
сравнивает с живым сайтом, а не со снимком.

## allowlist.json

Единственное место для исключений. Всё, чего в нём нет, проверка считает
ошибкой. Четыре списка:

* `markup_only_classes` — классы, у которых **и в production нет
  объявлений**: проверено замером. Остаются в разметке ради совпадения с
  продом, стилей не несут;
* `undemonstrated_ok` — служебные и анимационные классы, которым
  демонстрация не нужна;
* `external_artifacts` — как отличить имя production-файла от нашего;
* `parity_selectors` — что и на какой странице сверять с живым сайтом.

Добавлять сюда что-то можно **только с причиной в поле рядом**. Пустое
исключение — это спрятанная ошибка.

## Генератор

`gen_new_section.py` пересобирает секцию «Новое» в витрине — перечень
классов, которые есть в коде, но не показаны примером. Список берётся из
того же кода, которым `coverage.py` его проверяет, поэтому разойтись они
не могут. Запускать после правок `ui/*.css`.
