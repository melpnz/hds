### 02-1 · major · седьмая протечка слоя, в ядре

Р-5 вычистила шесть протечек из слоя продукта. Слой продукта сейчас чист:
в строках 269–380 пятнадцать маркеров `@snapshot`, все пятнадцать — `04_Brand`,
источников `02_Landings` там ноль. Проверено срезом:

```
sed -n '269,380p' ui/tokens.css | grep -n "@snapshot"
→ 15 строк, все «@snapshot 04_Brand …»
```

Седьмая протечка того же рода лежит **не в слое продукта, а в ядре**:

```css
/* ui/tokens.css:236-237 */
/* @snapshot 02_Landings 20216:120 — подсветка фона hero пятью размытыми овалами */
--core-glow-hero: inset 0 0 57.7px 43px #d04509, inset 0 0 100.7px 52px #a05024;
/* ui/tokens.css:266, светлая пара */
--core-glow-hero: inset 0 0 57.7px 43px rgba(208, 69, 9, 0.35), inset 0 0 100.7px 52px rgba(160, 80, 36, 0.25);
```

Узел-источник — тот же самый, из-за которого протечка и была замечена:
`20216:120` «Санаторий маркетолога», проект Хабр × eLama. `GUIDE.md:379-386`
про него написано прямым текстом: «`--product-cta` стоял `#fa722b` под
`@snapshot 02_Landings 20216:120` … цвет проекта, а не продукта». Оранжевый
`#fa722b` из слоя продукта убрали; оранжевые `#d04509` и `#a05024` из того же
узла остались в `:root` — то есть выше слоя продукта, а не ниже, и потому
действуют на все три продукта сразу.

Применяется классом без продуктовой привязки:

```css
/* ui/blocks/core.css:250-252 */
/* @snapshot 02_Landings 20216:120 — подсветка фона hero пятью размытыми овалами */
.hero-glow { box-shadow: var(--core-glow-hero); }
```

Значение снято верно — я его переснял: `get_design_context 02_Landings
20097:8612` (хедер-фрейм внутри `20216:120`) отдаёт
`shadow-[inset_0px_0px_57.7px_43px_#d04509,inset_0px_0px_100.7px_52px_#a05024]`
ровно на пяти узлах `20256:3566`, `20256:3564`, `20256:3565`, `20256:3561`,
`20256:3562` — «пять размытых овалов» комментария сходится до узла. Неверно
не число, а слой: покрытие 1 узел из 18, METHOD §8 — «одно вхождение —
наблюдение, не правило», а `tokens.css:384-385` формулирует принцип пакета
«цветом различаются продукты, а концепции — приёмом». Оранжевый hero
у Карьеры (семейство фиолетовое `#5A00B4`) и у Курсов (сине-бирюзовое
`#003580 → #00E0CE`) этому принципу противоречит.

**Что сделать.** Поступить с `--core-glow-hero` так же, как с `#fa722b`:
вынести из ядра в модификатор проекта (`ui/blocks/primitives.css` рядом
с остальными проектными акцентами) либо в слой концепции с явным node id,
а в ядре оставить имя без цвета или с нейтральным значением. Заодно
`blocks/hero.md:103` и `:156` называют его снятым, не оговаривая, что снят
он с одного проекта.

### 02-3 · major · светлая тема продукта неполна на три токена

`ui/tokens.css:349-350` обещает: «Ни один продуктовый макет не существует
в светлой версии, поэтому **все значения ниже спроектированы**». Ниже
перечислены шесть токенов на продукт: `base`, `base-deep`, `accent`, `acid`,
`cta`, `on-acid`. Ещё три продуктовых токена — `--product-gradient`,
`--product-gradient-veil`, `--product-ribbon` — объявлены в блоках
`[data-product="…"]` без темы (строки 331-347) и светлой пары не имеют.

Измерено в браузере, `getComputedStyle(document.documentElement)` при
переключении `data-theme`:

| Продукт | Токен | Тёмная | Светлая |
|---|---|---|---|
| habr | `--product-gradient` | `radial-gradient(circle, #030e71 0%, #06d0ef 100%)` | **то же** |
| career | `--product-gradient` | `linear-gradient(180deg, #7963e9 10%, #b654b6 90%)` | **то же** |
| career | `--product-ribbon` | `linear-gradient(90deg, #8b24e3 23.96%, …)` | **то же** |
| courses | `--product-gradient` | `linear-gradient(180deg, #003580 0%, #005999 20%, #0099cc 56%)` | **то же** |
| courses | `--product-gradient-veil` | `linear-gradient(180deg, rgba(0,153,204,0) 40%, #00e0ce 84.045%)` | **то же** |

Практический эффект: в светлой теме Хабра страница стоит на
`--product-base: #f2f6f8`, а фоновый градиент остаётся почти чёрным
`#030E71 → #06D0EF`. Формально контракт имён не нарушен — имя есть в обеих
темах, — но решение Р-2 говорит не про наличие имени, а про то, что светлая
тема спроектирована целиком.

**Что сделать.** Либо добавить светлые пары трём градиентам в блоки
`[data-theme="light"][data-product="…"]` под тем же `@normative`, либо явно
записать в комментарии, что градиент темой не меняется, и назвать причину.
Молчаливое наследование — третий вариант, и он худший: читатель статьи
о блоке этого не увидит.

### 02-5 · minor · дыра в стороже: ось игривости в форме `[data-play]` не ловится

Сторож объявляет три нормативные области, и «ось игривости» — одна из них
(`tools/validate-normative.mjs:110-116`). Триггер:

```js
triggerCss: /(?:--(?:[a-z0-9]+-)*play(?:ful)?(?:-[a-z0-9]+)*\b|\.play(?:ful)?[\w-]*)/i
```

— переменная с сегментом `play` или класс `.play*`. В пакете ось записана
атрибутными селекторами:

```css
/* ui/tokens.css:447-451 */
/* @normative ось игривости: решение владельца — Inter на 1–2, Unbounded на 3–4 */
[data-play="1"] { --core-font-heading: "Inter", sans-serif; --core-weight-display: 500; }
…
```

Ни имя свойства (`--core-font-heading`, `--core-weight-display`), ни селектор
под триггер не подпадают. Проверено красным прогоном на копии в скретчпаде:

```
подмена маркера на строке 447 на «@snapshot 04_Brand 5149:6443» → exit=0, тишина
подмена маркера на строке 397 (над --concept-play-step)          → exit=1,
  «--concept-play-step — ось игривости под маркером @snapshot … Инвариант И-2»
```

Остальные семь подделок сторож ловит, и ловит точно: светлая тема под
`@snapshot` (называет имя каждой переменной), объявление без маркера, битый
node id, `@normative` без причины, ссылка на несуществующий файл Figma,
маркер не по форме, безымянная светлая база `:root` с тёмным оверрайдом
(«область `:root` темой не названа, но ту же переменную перекрывает тёмная
тема — значит база светлая»), раздел статьи со светлой темой без слова
«норматив». Прикрыта одна дыра из восьми проверенных путей.

**Что сделать.** Добавить в `triggerCss` области `playfulness` атрибутную
форму (`\[data-play`), и подтвердить правку красным прогоном на подделке.
