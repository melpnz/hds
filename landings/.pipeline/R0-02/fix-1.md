## 02-1 · major · седьмая протечка слоя, в ядре

**Исправлено. `--core-glow-hero` из ядра удалён и разложен по трём слоям.**

Решение принято такое: **ни один из трёх вариантов ревью целиком, а их
разделение по существу значения.** В узле `20216:120` снято две разные вещи,
и у них разные слои:

| Что снято | Покрытие | Куда положено |
|---|---|---|
| **геометрия** пяти овалов: `inset 0 0 57.7px 43px` и `inset 0 0 100.7px 52px` | 1 узел из 18, пять узлов внутри него | роль `--product-glow-hero`, слой продукта, `@normative` |
| **цвет** `#d04509` и `#a05024` | тот же 1 узел | модификатор проекта `.hero-glow-sanatorium` в `ui/blocks/core.css`, `@snapshot 02_Landings 20216:120` |

Почему не «нормативом ядра с честной причиной»: значение красило hero всех
трёх продуктов, а `tokens.css` формулирует принцип пакета — «цветом
различаются продукты, а концепции — приёмом». Оранжевый в ядре этому
противоречит независимо от того, каким маркером он помечен.

Почему не «токеном слоя концепции»: концепций четыре, и подсветка hero
не принадлежит ни одной из них — она принадлежала одному проекту.

Почему не просто «в модификатор, а в ядре имя без цвета»: тогда `.hero-glow`
без модификатора не делал бы ничего, и снятая геометрия — единственное,
что в этом узле измерено достоверно, — пропала бы вместе с цветом.

Что теперь в `ui/tokens.css`, общий блок трёх продуктов:

```css
/* @normative подсветка hero: геометрия снята с 02_Landings 20216:120
   (пять размытых овалов, inset 0 0 57.7 43 и inset 0 0 100.7 52), цвет — нет.
   Оранжевый того узла принадлежит проекту «Санаторий маркетолога» и в ядре
   красил все три продукта разом; здесь цвет берётся из семейства продукта… */
--product-glow-hero: inset 0 0 57.7px 43px var(--product-accent),
                     inset 0 0 100.7px 52px var(--product-base-deep);
```

`ui/blocks/core.css`:

```css
.hero-glow { box-shadow: var(--product-glow-hero, none); }
.hero-glow-sanatorium { box-shadow: inset 0 0 57.7px 43px #d04509,
                                    inset 0 0 100.7px 52px #a05024; }
```

**Измерено в браузере** (chromium через msedge, `getComputedStyle` на пробном
узле, переключение `data-product` / `data-theme`):

```

habr/light     rgb(11,127,150) …,                    rgb(3,14,113) …
career/dark    rgb(121,99,233) …,                    rgb(53,0,106) …
career/light   rgb(122,61,245) …,                    rgb(53,0,106) …
courses/dark   rgb(0,153,204) …,                     rgb(0,53,128) …

без data-product   none

Подсветка теперь различает продукты и следует теме — потому что собрана
из токенов, которые сами объявлены в обеих темах. Без `data-product`
подсветки нет вовсе, и это честнее оранжевого по умолчанию.

### Весь слой ядра тем же вопросом: ещё значения 1/18

Проверил каждый `@snapshot` в слое ядра. **Значений с покрытием «1 узел»
в ядре много — почти вся цветовая часть**, и это не находка, а свойство
материала: CSS снят у девяти макетов из восемнадцати, и большинство цветов
встречается ровно в одном протоколе. `--core-bg-surface` (`1324:7793`),
`--core-bg-field` (`6509:20474`), `--core-text-secondary` (`17473:869`),
`--core-glass-*` (`18085:3948`), `--core-shadow-hard` (`14871:1319`),
`--core-glow-inset` (`18085:3890`) — все по одному узлу.

Вопрос, который отличает 02-1 от них, не «сколько узлов», а **чей это цвет**.
Оранжевый `#d04509` — фирменный цвет стороннего проекта Хабр × eLama,
и в ядре он присваивал этот цвет Карьере и Курсам. Ни один из перечисленных
выше такого свойства не имеет: это нейтральные подложки, серые и белые.

Разобрал отдельно два кандидата, которые формально похожи:

| Кандидат | Вердикт |
|---|---|
| `--core-text-primary: #f2f0eb` — снят с **того же** узла `20216:120` | **Оставлен в ядре.** Это подтонированный белый, а не фирменный цвет: у проекта он не опознаётся, продуктам ничего чужого не навязывает, и внутри узла стоит на пяти текстовых слоях. Покрытие 1 макет из 18 — записанная граница пакета, а не протечка слоя |
| `--core-font-wordmark: "ALS Hauss"` — маркер `20216:92`, словесный знак «Хабр» | **Оставлен в ядре.** Проверено по evidence: ALS Hauss не однократное вхождение — `evidence/source/figma/10929-505.md:35-44` показывает десять текстовых ролей одного лендинга целиком на ALS Hauss, и `9588:1223` набран им целиком. Это второй шрифт экосистемы, а не шрифт одного проекта |

## 02-3 · major · светлая тема неполна на три токена

**Исправлено. Заведены светлые значения нормативом с причиной, и проверен
весь набор.**

`--product-gradient`, `--product-gradient-veil` и `--product-ribbon` стояли
в блоках без темы и в светлой теме молча наследовали тёмное значение.

Что сделано:

| Токен | Светлое значение | Причина в маркере |
|---|---|---|
| `--product-gradient` Хабра | `radial-gradient(circle, color-mix(#030e71 25%, #fff) 0%, color-mix(#06d0ef 30%, #fff) 100%)` | форма и стопы снятые, тона осветлены, чтобы фон остался светлее `--product-base` `#F2F6F8` по краю |
| `--product-gradient` Карьеры | `linear-gradient(180deg, color-mix(#7963e9 22%, #fff) 10%, color-mix(#b654b6 22%, #fff) 90%)` | стопы 10 % и 90 % снятые (`5141:5094`), доля осветления одна на оба, чтобы переход сохранил направление |
| `--product-gradient` Курсов | три стопа `18 % / 20 % / 24 %` на белом при стопах 0 / 20 / 56 % | осветление растёт вниз, потому что и в снятом слое тон вниз светлеет |
| `--product-gradient-veil` Курсов | цветной стоп `color-mix(#00e0ce 30%, #fff)`, прозрачный оставлен как снят | осветлять прозрачный стоп нечего |
| `--product-ribbon` Карьеры | те же четыре снятых стопа | **решение, а не наследование**: лента — графика поверх фона, а не подложка текста; осветление разрушило бы узнаваемый переход из фиолетового в оранжевый, а на светлой базе `#F6F1FB` её тона читаются. Значение выписано в светлом блоке целиком, чтобы решение было видно в файле, а не выводилось из отсутствия строки |

Геометрия во всех пяти случаях осталась снятой: направление, форма
и проценты стопов те же, что у соответствующего `@snapshot`. Меняются только
тона, и доля смешения с белым названа в каждом маркере.

**Измерено в браузере после правки** (`getComputedStyle` на корне,
переключение `data-theme`):

```

Практический эффект, ради которого находка и заведена: на светлой базе Хабра

сине-лавандовый радиал. Снимок витрины в светлой теме сделан и просмотрен.

### Проверен весь набор на сирот, а не только три названных

Статический разбор `ui/tokens.css`: собраны все цветоносные имена
(литерал `#…`, `rgb/hsl(`, `color-mix(`, `gradient(`) и проверено, объявлено
ли каждое хоть раз внутри `[data-theme="light"]`.

**Результат: цветоносных имён без объявления в светлой теме — 0.**

Перекрёстно то же проверено в браузере: для каждого продукта прочитаны
вычисленные значения всех имён `tokens.css` в тёмной и светлой теме. Имена,
у которых значение совпадает в обеих темах, остались только эти, и каждое
совпадает **по явному объявлению**, а не по наследованию:

```
habr     --product-base-deep #030e71 · --product-cta #4da3cb · --product-on-acid #ffffff
career   --product-base-deep #35006a · --product-on-acid #ffffff · --product-ribbon (см. выше)
courses  --product-cta #3670f4 · --product-on-acid #ffffff
```

`--product-glow-hero` и `--concept-outline-color` литералов не содержат
вовсе — они собраны из `var(--product-*)` и потому меняются вместе с темой
автоматически; это записано в их маркерах.

Заодно закрыт разрыв контракта имён **между продуктами**: `--product-ribbon`
был объявлен только у Карьеры, `--product-gradient-veil` — только у Курсов,
и `var()` на них у остальных двух продуктов резолвился в пустую строку.
Теперь оба имени объявлены `none` в общем блоке трёх продуктов, с причиной:
отсутствие приёма — это значение `none`, а не отсутствие имени.
