# Брейкпоинты

Контракт сохраняет пороги русского Webflow-экспорта без округления.

| Диапазон | Ширина | Исходный запрос | Назначение |
|---|---:|---|---|
| Mobile portrait | 0–479 px | `max-width: 479px` | Самые узкие экраны и точечное упрощение сеток |
| Mobile landscape | 480–767 px | `max-width: 767px` | Мобильная типографика, один столбец, поля страницы 20 px |
| Tablet | 768–991 px | `max-width: 991px` | Планшетная типографика, поля 30 px, сворачивание навигации |
| Desktop | 992–1279 px | Базовые стили | Основная desktop-композиция |
| Wide | 1280–1439 px | `min-width: 1280px` | Дополнительное пространство и отдельные крупные варианты |
| Large | от 1440 px | `min-width: 1440px` | Самый большой диапазон, расширенная композиция |

Пороги 479, 767 и 991 — основные: на них допустимо менять структуру. Пороги 1280 и 1440 используйте для улучшения масштаба, отступов и композиции; важный контент не должен появляться только на большом экране.

До 1439 px контейнер резиновый. Начиная с 1440 px его внешняя ширина фиксируется на 1440 px и центрируется; дальше наращивается только фон полноширинных секций. При боковых полях 50 px полезная ширина контента внутри контейнера составляет 1340 px.

В исходном Webflow CSS есть дополнительный запрос `min-width: 1920px`. В HDS он не образует отдельный диапазон: такие правила следует включать в `Large` либо оставлять локальным улучшением конкретного компонента.

Так как пакет работает без сборщика, значения пишутся в media queries явно. CSS custom properties внутри условий media queries не используются. Машинная версия: [breakpoints.json](../machine/breakpoints.json).
