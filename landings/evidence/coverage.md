## Как читать

**чем подтверждается** (файл, node id, команда) и **адрес закрытия** — шаг
роадмапа, вопрос владельцу или строка «Найдено по ходу».

Числа не округляются: «2 из 9» значит два из девяти. Дробь без знаменателя
в этот файл не пишется. Знаменатель считается на момент чтения, а не берётся
из прежней редакции: у границы 14 он растёт вместе с каталогами `.pipeline/`.

шагами, прошедшими после составления каркаса. Граница 8 разбита на 8а, 8б и 8в:

## 1. CSS снят выборочно: сплошь — у 2 узлов из 18

**Что неизвестно.** Полные значения цвета, кегля, радиуса и отступа по всей

`get_design_context` на весь узел, сняты **2 из 18**: `18085:3890` и
`1324:7793`. Сохранённые дампы этих двух вызовов весят **116 604 байта**

MCP, а не файл, и единица измерения там не названа.

У семи узлов, доснятых на R0-00, CSS взят по **2–4 секциям верхнего уровня
из 11–22**; девять узлов, измеренных аудитом, сняты точечно по отдельным

`14871:1319`, `1284:3362`.

**Отдельная и большая часть границы: сохранённого дампа нет у семи узлов
из девяти.** Дамп `get_design_context` со значениями CSS сохранён по двум узлам:

и `raw-1324.txt` (298 и 25). По трём узлам — `12395:7441`, `6509:20474`,
`14871:1319` — сохранена только структурная выдача `get_metadata`, где нет ни
одного значения `border-radius`, ни гарнитуры, ни цвета. По четырём —
`10929:505`, `9519:2095`, `7869:20760`, `1284:3362` — не сохранено ничего.

Значит, у **7 узлов из 9** записанные в evidence радиусы, гарнитуры и цвета
восходят к записи диалогового чтения, а не к файлу, и перепроверяются только
новым вызовом MCP. В прогоне критерия «радиус интерфейсный или иллюстративный»
на файл опираются **6 строк из 14**, остальные **8** — на диалоговое чтение.

**Чем подтверждается.** `.pipeline/R0-00/capture.md` §1, §2, §5, §7;
`coverage-notes.md` §1, §3. Одной командой из корня пакета:

**Адрес закрытия.** Досъёмка семи узлов с сохранением дампа — шага под неё пока
нет; строка в роадмапе — `X-31`, владелец не назначен. Хендофф чисел закрыт

## 14. Протокола съёмки нет у пяти шагов волны R0

**Что неизвестно.** Как именно шли пять шагов: что открывали, чем измеряли,

## 15. Канон ширин съёмки расходится с ширинами артбордов

**Что неизвестно.** Как ведёт себя вёрстка пятнадцати макетов на той ширине,
на которой они нарисованы.

**Числа.** Ширины артбордов: 1600 — 8 узлов, 1440 — 5, 1400 — 3, 1280 — 1,
1240 — 1. Канон съёмки METHOD §3 — 320 · 768 · 1024 · 1400. Совпадает одна
ширина, 1400, и то у трёх узлов. Значит, **15 узлов из 18** не получат
прод-снимка на ширине собственного артборда.

**Почему это не порок инструмента.** `tools/capture.mjs` снимает поведение
вёрстки, а иерархия источников METHOD §3 ставит runtime и CSS выше визуального
наблюдения из Figma. Механизм исключения в инструменте есть — предупреждение
при `--widths` вне канона плюс `widthsSource` в `meta.json`, — но вызов
по умолчанию им не пользуется.

**Что этим задето.** Чеклист ревью A.1/A.3 сверяет тройку «прод ↔ Figma ↔
наш пример». Для этих пятнадцати узлов числовая сверка на одной ширине
невозможна, пока по узлу не взято исключение METHOD §3 «отдельный артборд».

**Смежное решение.** Опорная ширина продукта — **1440** (ответ на Q-4).
Рабочий каркас `ui/blocks/core.css` на неё не переведён: он читает
1600-базовые токены, узкие 1440-базовые не использует ни один блок пакета —
строка `X-17`.

**Чем подтверждается.** Строка `X-12` роадмапа, где владельцем прямо назван
шаг **R0-07**; `BRIEF.md` §1, таблица ширин.

**Адрес закрытия.** Обе записи, которых требует `X-12`, сделаны этим шагом:
граница здесь и **пункт 15 «Известные ограничения» `README.md`** — вторая
половина строки владельца больше не ждёт. Открытым остаётся решение по каждому
узлу на съёмке: шаги волн **R2** и **R3** решают, берётся исключение METHOD §3
или нет, и пишут решение в `capture.md`.

## 16. Сторож чисел не видит покрытия правил и варианты блоков

**Что неизвестно.** Сходятся ли между документами дроби покрытия, у которых
нет ключа в `tools/validate-counts.mjs`.

**Числа.** Сторож держит ключ на каждый из **19 типов блоков** — семейство
`cover:*`, по ключу на запись реестра. Ключей на покрытия правил `L-*` — **0**;

знака» → 12/18 даёт EXIT=0; покрытие правила `L-2` «лендинги 18/18» → 12/18 —

(«18/18 (hero)» → 12/18) даёт 1, то есть дыра точечная, а не общая.

**Что этим задето.** Покрытие лок-апа (R1-01), покрытие правила уровня
страницы `L-2` — у такого правила число и есть весь смысл (METHOD §8) —
и три варианта шапки, из которых растёт R2-02.

**Итог прогона здесь не пишется — и это решение, а не пропуск.** Строка
«Проверено утверждений: N в M файлах» меняется от любой правки сторожа,
включая правки этого же шага: первая редакция границы несла «188 утверждений

сделали её «196 в 26» — число устарело раньше, чем шаг закончился. Ключом оно
не берётся: сторож считал бы собственные строки, привязка к этому числу сама
стала бы строкой прогона и изменила бы измеряемую величину, а знаменатель
растёт от файла, в котором утверждение написано. Поэтому итог печатает сам
прогон, а в границе стоят только сторожимые числа — **19 типов блоков** равны
`blockTypes`, ключ заведён этим шагом (`tools/validate-counts.mjs`) — и нули,

`.pipeline/status-2026-09-09.md` — там он остаётся снимком даты, строка
`X-36`.

**Смежные строки того же рода.** `X-24`: счётчик принятых шагов
