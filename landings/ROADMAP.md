## Чеклист приёмки шага

Прогоняется приёмкой каждого шага. Выдача вставляется в `accept.md`
копированием из терминала вместе с кодом возврата — не пересказом.

```bash
node tools/validate-blocks.mjs --strict     # реестр блоков и примитивов: код 0; до R0-05 код 2 «реестра ещё нет»
node tools/validate-counts.mjs              # заявленные числа: код 0
node tools/validate-classes.mjs             # классы витрины: код 0; до R0-06 код 2 «витрины ещё нет»
node tools/validate-normative.mjs           # норматив не выдан за факт (И-1, И-2): код 0; до R0-02 код 2 «объявлений в ui/ ещё нет»
node tools/validate-radius.mjs              # лестница радиусов 0 · 6 · 16 · пилюля и правило Ф-3: код 0 (сторож заведён вне роадмапа, строка W-03)
node --check tools/*.mjs                    # инструменты разбираются
npm test                                    # smoke-спек витрины: до R0-06 скрипта нет, проверка не запускается
```

**Код 2 — «предмета проверки нет», а не «проверено и хорошо».** Он ставится
только там, где проверять действительно нечего, и не глушит ошибок: протечка
оболочки в `ui/` при отсутствующей витрине даёт 1, один `@snapshot` без
объявлений даёт 1, реестр с записями или пропавшая инвентаризация под
`--strict` дают 1. Каждый код 2 назван вместе с шагом-владельцем — в выдаче
самого инструмента и в [`tools/README.md`](tools/README.md). Приёмка шага
после R0-06 ждёт от всех семи строк код 0.

Дополнительно, для любого шага, трогавшего число или покрытие:

```bash
node tools/validate-counts.mjs --explain    # какое число где написано и чем измерено
```

`validate-counts` сторожит числа этой сводки во всех местах, где они написаны:
18 узлов, 9 измеренных CSS, 83 %, 19 типов блоков, 24 записи реестра, 46 шагов,
40 находок, 23 баннера, 0 веб-форматов, 0 пар тем. Инвариант И-7: 15/18 значит
измерено 15 из 18, а не «примерно все».

### Что значит статус `review`

Восемнадцать шагов стоят `review`, а не `done`. Результат шага лежит в пакете
и валидаторы по нему зелёные — но **отчёта ревью у шага нет**: работа шла вне
конвейера, и шага 3 (`guide-review`) на ней не было. По METHOD приёмка
не заменяет ревью собственным осмотром: без отчёта шаг не принимается по
формальной причине. `done` в пакете ровно один — `R0-01`, и он прошёл полный
цикл: вёрстка → ревью → правки → повторное ревью → приёмка.

Перевести `review` → `done` можно двумя дорогами, и обе законны: провести
ревью по каждому шагу задним числом, либо решением владельца принять
внеконвейерную работу пачкой, назвав это в `CHANGELOG.md` прямым текстом.
Приёмка такое решение за владельца не принимает.

Черновой слой правил каркаса и сетки допускается сразу после R0 — без него
не собрать блоки. Он помечается черновиком и пересматривается в R5-01.

**Блоки с покрытием 1–2 узла в правила не идут** (METHOD §8). В реестре
и в статьях они помечены `rule: false` и словом «наблюдение»: FAQ 2/18,
таймлайн 2/18, галерея 2/18, корпоративный B2B-футер 2/18, отзывы 1/18.
Статью такой блок получает — правило из него не выводится.

**Методика подсчёта объявлений `ui/tokens.css` (находка `R2-5`,
`.pipeline/R0-02/review-2.md`).** Число в строке R0-02 — не оценка на глаз:
файл прогоняется через разбор комментариев `/* … */` (они вырезаются
целиком, включая многострочные), затем считаются вхождения вида
`{ --имя:`, `; --имя:` или начало файла `--имя:` — то есть объявление
переменной как начало CSS-декларации, а не `var(--имя)` внутри значения.
Многозначные строки вида `--product-glow-hero: inset …, inset …;` считаются
**одним** объявлением: запятая внутри значения не начинает новую
декларацию, регэксп её не подхватывает. На этой методике и текущем файле —
**175** объявлений, **96** уникальных имён, **70** `@snapshot`,
**42** `@normative` (пересчитано после правок этого fix-раунда;
до них, на состоянии `review-2.md`, было 175/96/69/40 — счётчик деклараций
не сдвинулся, потому что находка `R2-1` убрала `--core-glow-inset` из

**Пробел покрытия `tools/validate-tokens.mjs` — витрина не на CSS (находка

сканирует `var(--x)` только в файлах `*.css` (`ui/`, `showcase/`) — обращение
к токену внутри JS-массива `showcase/blocks.html` (`{ v: '--core-glow-inset', … }`)
не строка `var(...)` и не `.css`, поэтому невидимо инструменту дважды: по
формату файла и по синтаксису обращения. Из-за этого пробела витрина полторы
итерации подряд (`fix-1.md`, `fix-2.md`) продолжала ссылаться на упразднённые

и ни один автоматический гейт этого не поймал — нашло только ручное

покрытии инструмента; заведено как задача R2 (в объём R0-02 не входит).

1. `ui/landings.css` подключается одной строкой и отдаёт токены, шкалу и шрифт.
2. В `ui/tokens.css` **каждое** значение помечено: снято (с node id) или
   спроектировано. Светлая тема целиком в норме «спроектировано»,

3. Имена токенов в светлой и тёмной темах совпадают один в один; расхождение
   имён — код 1.
4. Витрина открывается по `npm run serve`; CSS витрины не пересекается с `ui/`
   ни одним селектором.
5. `evidence/coverage.md` называет все 12 границ, включая ноль веб-форматов
   и ноль пар тем.
6. `validate-blocks --strict` проходит на пустом реестре; `validate-counts`
   зелёный на всех числах сводки.
7. Досъёмка R0-00 либо закрыла девять неизмеренных узлов, либо назвала
   поимённо, что именно не открылось и почему.

## Чего в пакете не будет

Перечислено с причиной в [`BRIEF.md`](BRIEF.md) §5. Кратко: мобильных
раскладок (в источнике 0 из 18 артбордов), пар «одна страница в двух темах»
(0 из 22 узлов), веб-форматов нового брендового стиля (0 из 23 баннеров),
библиотеки 3D и персонажей, tone of voice, состояний hover / focus-visible /
disabled, снятых с источника, правил уровня продукта «Курсы» (1 узел),
описания нижних ≈2460 px `14871:1319` до досъёмки, и утверждений о живом
production — он не переснимался.
